# nest

A personal platform built as two systems with one seam: a **sandbox system** that runs isolated VMs on commodity cloud compute, and an **agent system** that runs long-lived Claude Code agents on my own subscription. Brains run on brain hosts (or, later, inside the control plane) and act on sandboxes only over the network, through each sandbox host's gateway; neither system knows where the other runs. nest is a microkernel: captains, task boards and pipelines are structures that agents and external apps build from a few primitives, not platform features. Everything scales to zero.

**Status:** early implementation; each crate or package README says what is built and what is missing, and [`control-plane/README.md`](../control-plane/README.md) lists the control plane's gaps.
- **Built and on AWS** (the `use1` cell): the runtime (control plane, nestd, nest-proxy, guest agent, agent runner, gateway, `nest` CLI). Sandbox hosts scale from zero and back, suspend idle sandboxes to S3, wake them lazily, and survive spot interruptions and nestd restarts ([autoscaling](compute/autoscaling/)). Sandboxes run jailed in Firecracker on nested-virtualization hosts, with turn-end disk commits ([firecracker](sandbox/drivers/firecracker/)); a host without `/dev/kvm` refuses the sandbox role and never enrolls ([drivers](sandbox/drivers/)). Every brain runs on a [brain host](compute/brain-hosts/) and reaches its sandbox only through the seam: the [gateway](sandbox/gateway/), bindings and each sandbox host's tunnel behind Access.
- **Built:** templates and capabilities as data ([CatalogDO](control-plane/durable-objects/catalog/)); spawning, ownership and lifetimes; [transcript grants](agents/tools/#built-transcript-grants-2026-11-06) (`read_transcript` by id or label selector, conferred at spawn, attenuated and checked down the chain); taint (a conservative per-agent stand-in) and approvals, listed per agent; remote MCP capabilities; brokered actions; agent [timers](agents/capabilities/timers/) (named one-shot wakes); the shadow disk cut, which clones only the ranges that differ from its shadow ([M3′](sandbox/state/disk/)); and the [API clients](control-plane/api/clients/) interface for external apps (grants, labels, a catalog namespace, caller identity, owner webhooks, GitHub tokens, idempotent creates, live traces). A local harness (`e2e/`) runs the real components together. The one-brain rule is model-checked, and nestd's cores are checked as shipped ([verification](verification/)).
- **Designed, not built:** grants beyond transcript grants, budgets, scoped operator tokens, the `api` capability source and capability parameters, the memory capability's tools, repeating scheduled wakes (`wake_at`), the gateway's terminal and ingress routes (so previews, terminals and port-forwards), fork, archive and the pause tier, the egress hardening (see Docs ahead of code), runtime metrics, desired host versions, memory snapshots and the restore ABI, M3's commit-time extent diff and the ublk lazy disk (memory snapshots wait for cold boot to prove too slow: [memory](sandbox/state/memory/)).

**Start with [architecture/](architecture/)** for how the pieces fit and how a turn flows. Everything needed to bring nest up (accounts, credentials, where they go) is in [setup/](setup/).

## Goals

- Run many agents in parallel, each in an isolated VM, on cheap cloud compute (AWS spot first, with other providers kept possible).
- **Durable:** an agent can wait days for an event at near-zero cost and survive losing its host.
- **Scale to zero:** an idle system costs close to nothing.
- **Arbitrary agent structures:** a captain managing workers, a reviewer watching an implementer, a pipeline, a swarm sharing a board. Agents and external apps build these; the platform only provides primitives.
- **Use my Claude Code subscription** (Claude Code is the only harness for now). Apps in sandboxes bring their own API keys; that isn't a platform concern.

## Principles

1. **Mechanism, not policy.** Primitives make no assumptions about the work inside them: no git, no worktrees, no port conventions, no roles, no workstreams.
2. **Structure is the model's job** ([the bitter lesson](http://www.incompleteideas.net/IncIdeas/BitterLesson.html)). The platform provides general primitives and hard limits. How agents organize, delegate and coordinate lives in prompts and tool calls, so it improves as models do and changes without a release.
3. **Authority is grants, and grants only shrink.** Every action needs a grant, and an agent can pass on only grants it holds. A session that has read untrusted content needs approval for actions that send data out. I hold the root.
4. **The sandbox is the trust boundary.** Everything inside one sandbox shares a trust domain.
5. **Decisions on the agent's hot path are local; everything else is async.** Hooks never wait on the network.
6. **Each piece of data lives next to its main reader.** Metadata lives in Durable Objects, bookkeeping in R2 and sandbox bytes in S3.
7. **One writer per entity, fenced by epochs.** Each entity has a single Durable Object, and stale writers are rejected.
8. **Claude Code runs unmodified, on brain hosts that never share a machine with a sandbox.** The subscription token never enters a sandbox or a sandbox host. Agents act on sandboxes only through RPC hands, over the network, through the gateway.
9. **nest is a microkernel** (decided 2026-11-02). The kernel keeps what needs the root or the seam: sandboxes (with the gateway and hands); agents (the loop, the input queue, lifecycle, spawning, ownership); the credential broker and egress policy; MCP tool attachment; scoped API clients and labels; and agent events delivered to owners. Everything else, coordination included, is an external integration that agents reach over MCP and the public API. A small kernel keeps the trusted, fenced and model-checked surface small, and coordination tools can change without a platform release. If an app seems to need a special case inside, the interface is wrong: fix it generically.

## Primitives

| Primitive | What | Doc |
|---|---|---|
| **Sandbox** | A machine: volumes, processes, network | [sandbox/](sandbox/) |
| **Agent** | A brain with optional hands in one sandbox, plus capabilities and grants | [agents/](agents/) |

- **Operations:** create, **attach** (bind an agent's hands to a sandbox), **fork** (copy a sandbox; the only isolation primitive), **spawn** (an agent creates an agent), **grant / revoke**.
- **On every resource:** an **owner** (the agent that created it, or me) and **labels** (free-form key/values).
- **Capabilities:** pluggable bundles of tools, grants and prompt instructions (spawning, memory, MCP servers, brokered actions, …).
- **Templates:** named spawn specs, mostly a list of capabilities, stored as data. `captain` and `worker` are templates.

Captains, task boards and teams are patterns that agents and external apps build from these. See [orchestration/](orchestration/) and [API clients](control-plane/api/clients/).

## Glossary

| Term | Meaning |
|---|---|
| Sandbox | A VM: volumes, processes, network. Holds 0..N attached agents. |
| Agent | A brain (Claude Code on a brain host, on my subscription; later, a Messages API loop inside AgentDO) plus optional hands and grants. There are no agent roles. |
| Agent runner | Brain-host component that starts, drives and tails Claude Code processes, and carries their hands calls to a sandbox's gateway |
| Hands | `nest` MCP tools modeled on Claude Code's built-ins, executed in a sandbox by the guest agent, reached through the sandbox host's gateway |
| Gateway | The one network door into a sandbox: an unprivileged process per sandbox host, behind the host's Cloudflare Tunnel, that checks a binding and forwards hands connections to the guest over vsock (terminal and ingress connections are designed, not built) |
| Binding | A signed token from SandboxDO's `resolve`: sandbox, epoch, client, scope and expiry, one hour long. The gateway admits a connection only with one; a detach or an epoch bump voids it |
| Agent epoch | Fencing token for a brain, issued by AgentDO at each brain start; platform tool calls and brokered actions carry it |
| Attach | Bind an agent's hands to a sandbox |
| Fork | Copy-on-write copy of a sandbox (disk only, or live with memory; designed, not built) |
| Grant | Permission for a principal to do an action on a resource. Passed on only by someone who holds it. |
| Owner | Whoever created a resource. Holds every grant on it. |
| Taint | A per-session bit the platform sets when a session reads untrusted content (hands output, the web, MCP and API results, transcripts). Built: a per-agent stand-in that never clears, set for an agent with hands or a web built-in and once a possibly tainted agent's text, a transcript or an untrusted MCP or HTTP result reaches it |
| Sink | An action that can send data out or widen authority; from a tainted session it needs approval |
| Capability | A pluggable bundle of tools, the grants they need and prompt instructions, listed in spawn specs |
| Template | A named spawn spec, stored as data in CatalogDO: capabilities, launch settings (model, built-in tools, base prompt), whether it takes a sandbox and the credential (grants and the backend choice are designed, not built) |
| Generation | Immutable manifest of a sandbox's disk (and optionally memory; designed) chunks |
| Epoch | Fencing token. A new one is issued with each placement claim, and only a host holding the newest epoch's lease may act for the sandbox. |
| Cell | A unit of compute plus its object store (e.g. AWS us-east-1 with S3) |
| Sandbox host | A spot VM with nested virtualization running Firecracker sandboxes, nestd, nest-proxy, cloudflared and the gateway. Every sandbox lives here; no brain does. |
| Brain host | A cheap host with no KVM running nestd (supervisor duties only), the agent runner and Claude Code processes. Every brain lives here; no sandbox does. Capacity is counted in brains; scales to zero. |
| Captain | A template convention, not a platform concept: an agent without hands, spawned from the `captain` template, that manages the agents it spawns |
| API client | An external system's scoped principal: a token, a grant as its ceiling, and its own subtree of agents, sandboxes and catalog entries |
| Label | A free-form key/value on an agent or sandbox; API clients find their resources by label |
| nestd | Per-host daemon |
| nest-proxy | Per-host egress proxy |
| Guest agent | Hands server inside each sandbox VM. Holds no credentials. |
| `nest mcp` / `nest` | `nest mcp`: the stdio MCP bridge that Claude Code spawns on a brain host. `nest`: the CLI used for hooks and inside sandboxes (`expose`, `unexpose`, `whoami`); a person's terminal and port-forward through the gateway are designed, not built. |

## Open questions and watch items

- **Open (low):** a repo admitted under an [owner-wide grant entry](control-plane/api/clients/#owner-wide-entries) is a name from then on: a live sandbox's push tokens aren't re-checked against its owner's account id, as an exact entry's never were.
- **Open (medium):** open asks and pending approvals are uncapped per agent and their list is unpaginated; tainted content can drive sink calls with varying arguments, one ask and approval each, and any model can do the same with calls a tool rule holds (300 different calls made 300 asks, each a webhook, in the security review of 2026-11-11). So are a tool rule's approved approvals not yet spent (they never expire and the prune keeps them); nothing caps them or drops them when the agent ends. `GET /v1/asks` shows at most 20 per agent and names the rest in `more` ([open asks across agents](control-plane/api/#open-asks-across-agents)); the per-agent route still answers them all. See [AgentDO](control-plane/durable-objects/agent/).
- **Not built:** a brain host egress allowlist. The web built-ins (`WebFetch`, `WebSearch`) run on the brain host, whose security group limits egress by port (443) only, so they reach any host; nothing but taint and the tool rules limits where they go, and the seed's `nest` capability allows both (the owner's decision, 2026-11-11: built-ins and the web never ask). See [brain hosts](compute/brain-hosts/), [security](security/).
- **Open (low):** a rule approval whose `approval_check` answer is lost in flight (the session channel drops after AgentDO answered, or the answer comes after the hook's 5 s) is spent though its call never ran (a check whose hook already gave up is never sent): the call is denied, the model is asked to retry, and the operator is asked again. Safe (never two calls), but the operator's approval is wasted. A release message from the runner (it denied that check's call) would recover it. See [session](interfaces/control-host/session/#turns-inbox-and-caches).
- **Decide:** a tool rule's approval has no expiry (the owner's decision, 2026-11-11); a sink's still expires an hour after the decision (`APPROVAL_TTL_MS`). Should sink approvals match? See [agents/tools/](agents/tools/#taint-and-sinks).
- **Not built:** events to an owner agent. API clients hear their agents' turns, exits, asks, errors and fired timers, and `sandbox.destroyed`, by webhook; a spawning agent hears nothing of its children, and sandbox events (ports, egress denials and alerts), salvaged work and quota parking are only logged. The operator finds waiting approvals per agent (`GET /v1/agents/<id>/asks`) or across a registry ([`GET /v1/asks`](control-plane/api/#open-asks-across-agents): the cell's, or a client's), with no push. See [agents/tools/](agents/tools/#taint-and-sinks), [API clients](control-plane/api/clients/#events-to-the-owner).
- **Open (low):** a `sandbox_create` re-issued twice: its re-issue reached FleetDO, SandboxDO was reset before recording it, and the failure's re-run re-issues it. nestd treats a create at an epoch it already runs as done. An idempotency key on `issueCommands` would close it. See [FleetDO](control-plane/durable-objects/fleet/).
- **Open (nestd's incarnation lifecycle, found by the host state-machine audit of 2026-11):** an archive whose commit fails leaves the row `archiving` with its VM paused, and a later checkpoint runs that VM again; a `sandbox_create` at the epoch of a local row that is suspended fences the host's own live epoch; a `sandbox_create` executed after the lease lapsed starts a VM (only `agent_start` consults the lapse guard); a step that checked the fence before an await pauses a fenced VM or resumes one the fence paused (harmless: the fence's stop follows). The lifecycle machine that will own these rules runs beside nestd, which calls only its create admission; the fixes land when it decides. See [verification/nestd/](verification/nestd/#incarnations-nestd_coreincarnation).
- **Verify on EC2:** nestd's delegated cgroup and its start-up kill of leftover VMMs (AL2023's systemd 252, the jailer's `--parent-cgroup`), built for restart recovery and tested only off EC2. See [compute/nestd/](compute/nestd/).
- **Verify on EC2:** the gateway's pause mark against Firecracker (only the process driver was checked), and Claude Code's MCP tool timeout against the runner's 120 s wait for a paused VM, which one last bind can stretch to about 130 s (other `busy`s keep 30 s, keyed on the refusal's `reason: paused`). See [agents/runner/](agents/runner/).
- **Verify:** whether Claude Code's stream-json carries a subagent's own messages (`parent_tool_use_id` set). The runner doesn't read that field, so such messages would reach the live trace unmarked, while the trace history leaves sidechains out. See [trace history](control-plane/api/#trace-history).
- **Watch:** `--bare` may become the default for `claude -p`, which would break subscription auth. The mitigation is the `authMethod` startup check. See [agents/runner/](agents/runner/).
- **Verify:** that separate setup tokens can be revoked independently. See [setup/](setup/#decisions-to-make-first).

## First spike

On a c8id with nested virtualization and a hugepage pool:
1. Cold boot until the guest agent is ready, against a restore from a base memory generation.
2. Disk-only resume through `claude --resume`.
3. Hugepage UFFD resume from page cache, NVMe and S3 Express (no public benchmark of 2 MB UFFD restores exists). This also qualifies the pinned (Firecracker, guest kernel) pair for memory restore; until it passes, hosts create no memory generations ([restore ABI](sandbox/state/memory/#restore-abi)).
4. Time to write a full snapshot at 2 and 4 GB.
5. A dev server's first response after resume.
6. ublk lazy-disk throughput.
7. Commit latency under write load, including the guest flush and the reflink cut. **Measured in part** (2026-11-03 to 06): the reflink and shadow cuts' pauses with a writing VM ([disk](sandbox/state/disk/)); the guest `syncfs` flush isn't built.
8. Forced-partition test: self-fence, then STONITH, then restore.
9. **First real Claude Code run** through the runner, in the e2e harness (no KVM needed). **Done** (2026-10-16, Claude Code 2.1.301, `NEST_E2E_CLAUDE=real e2e/run.sh`): a real turn ran entirely through `mcp__nest__` hands, the token absent from the sandbox, and the brain self-fenced 20 s after the control plane was cut.
10. **Hands fidelity eval:** the same tasks with native tools (Claude Code inside a VM), with RPC hands from a brain on the same machine, and with hands from a remote brain through the gateway and the tunnel; compare success rate, turns and tokens, and record the per-call round trip of the remote arm. The same eval gates every upgrade of the pinned Claude Code version ([runner](agents/runner/)).
11. **Nested overhead:** CPU and I/O on a nested 8i instance against the same work on `.metal`.
12. **Resume or fresh:** turn cost and quality when resuming a long session after the cache expired, against a fresh session seeded from memory.
13. **The seam:** a brain drives its sandbox through `wss://<host>-gw-nest.<zone>`, so every hands call crosses Cloudflare's edge and Access and returns down the sandbox host's tunnel into the gateway. **Done** on `use1`: a brain on the sandbox's own host (2026-10-23), on another cell host (2026-10-24, with Access's Service Auth), and on a brain host, two workers driving their sandboxes (2026-10-29). A single failed `/ready` probe can flip a tunnel to `connecting` for 2 s, so a brain resolving then waits one retry ([gateway](sandbox/gateway/), [brain hosts](compute/brain-hosts/)).
