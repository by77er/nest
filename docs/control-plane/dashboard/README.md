# Dashboard

A read-only page of what is live in one cell: agents with a brain, sandboxes and their hosts (one suspended to S3 is counted, not listed), live hosts with their residents, the sandbox templates, and [what is left lying around](#abandoned). History and AMIs stay off it. It leads with what needs attention, errors first (an instance type whose launches are paused by its [enrolment breaker](../../compute/autoscaling/) among the warnings), and puts the detail below; it refreshes every 10 s (what is left lying around, every 60 s), only while the tab is visible. Code and page layout: [dashboard/README.md](../../../dashboard/README.md#the-page) (Vite + React, its own Worker, `dash-nest.bitcru.sh`).

- **Apart from the platform.** It shares nothing with the control plane but its admin API: its own directory, package, Worker (`nest-dashboard`) and deploy workflow. The Worker reads `GET /v1/admin/fleet`, `GET /v1/admin/images`, `GET /v1/admin/lifetimes` and `GET /v1/agents/:agent`, and nothing else. It proxies the first two as they are; answers `/api/agents` itself, for the agents the fleet view lists on its hosts (`HostView.agents`; at most 100, 4 at a time, each narrowed to the fields the page shows so prompts and rules stay in the Worker, one that can't be read a row with its error), so an agent without a brain isn't listed there; answers `/api/lifetimes` by following the lifetimes view's pages (at most 20, a cursor sent on only in the control plane's shape) and merging them; answers `/api/cells` from its own vars; and refuses every other method and route.
- **The token stays in the Worker.** The control plane's admin token is a secret on the dashboard Worker, added to the requests it makes; the page never sees it.
- **The Worker checks Access itself, and fails closed.** Cloudflare Access on `dash-nest.bitcru.sh` (an Allow policy for the owner's login, in the `edge` inframe stack: [setup](../../setup/)) logs the owner in, and the Worker verifies the token Access adds to every request (`Cf-Access-Jwt-Assertion`) before serving anything, page or API: RS256 against the team's keys at `<team>.cloudflareaccess.com/cdn-cgi/access/certs` (cached an hour, refetched for an unknown key id), `iss` the team, `aud` the dashboard application's tag (the edge stack's `dashboard_aud` output), not expired ([Cloudflare: validate the JWT](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)). Without a valid one the answer is 403. So the token stays private on any path that skips Access (`workers.dev` and preview URLs are off too), and a hostname rename that leaves Access behind closes the dashboard instead of opening it. The hostname follows the [naming rule](../../setup/#hostnames).
- **Typed by a shared contract.** `fleetView`, `images` and `lifetimes` return the types in `protocol/admin/view.ts`, a module that imports nothing; the page imports them as types only and never imports the control plane, so its build carries no outside code and a field the page reads but the view lacks fails `npm run typecheck`. A test holds both rules, the control plane asserts that the view's enums equal its protocol's, and a recorded response (`fixtures/admin.ts`) must satisfy the same types. `GET /v1/agents/:agent` is outside that contract, so the page reads each of its fields as optional and shows it as unknown when absent. A sandbox row keeps the lease's state (`lease_state`) apart from SandboxDO's own (`sandbox_state`, null with `info_error` when it couldn't be read).
- **Reads only.** Operator actions stay with the API and the `nest` CLI.

**Not built:** per-agent detail (turns, transcripts), cost, a second cell, an agent index (agents without a brain appear only in the lifetimes view), S3 bytes.

## Abandoned

**What is left lying around, so nothing accumulates unseen** (the owner's goal; the classes and both thresholds below are the owner's). The control plane decides what each thing is (`GET /v1/admin/lifetimes?cell=&cursor=&limit=&quiet_ms=`, admin token; FleetDO's `lifetimes`, rules in `control-plane/src/lib/abandoned.ts`); the page lists it oldest first and shows, as text, the API call an operator would make.

- **Sandboxes** (every live one in FleetDO's registry, each read from SandboxDO):
  - **Dormant:** SandboxDO's own rule (no agent attached, no placement in flight, no VM up; [lifetime](../durable-objects/sandbox/#lifetime)), with `dormant_since`, the TTL that applies (its own or the cell's) and when the lifetime check will destroy it (`destroyAtMs`, which mirrors `expiryStep` and is tested against it: the notice day for a TTL over a day, a missed-check gap restarting the clock; null before the clock starts). Already handled by the TTL; listed so it is seen.
  - **Held:** attached only to agents that will never use it (quiet, stuck ending, ended, or gone). Never dormant, so no TTL takes it: **the real leak**. Listed with its attached agents.
  - Unknown (an attached agent couldn't be read and none is active), destroyed (SandboxDO destroyed, the registry not marked) and unreadable are listed too. In use (no attached agent but a VM up or a placement in flight, or an attached agent active or recent) is counted.
- **Agents** (each read from AgentDO's `lifetimeFacts`):
  - **Quiet:** not ended, no brain, no start wanted, no turn current or queued, and no turn started for `quiet_ms` (default **a day**, the sandbox TTL's default; one that never had a turn is quiet). Listed with what it holds: its sandbox, its live children, and whether the operator's stop is why it is quiet. A quiet agent may be a durable one waiting for input; the view doesn't guess intent.
  - **Ending:** ended, its steps unfinished for over an hour (they retry every minute: stuck). Listed.
  - **Gone:** its records pruned yet a listed sandbox still has it attached. Listed; one named only as an owner is counted.
  - **Ended** (its end done, its records awaiting the 30-day prune) is **noise: counted, not listed**. It holds nothing (its end detached it from its sandbox and ended what it owned), and its prune is already scheduled. Active and recent are counted.
- **How agents are found:** from the cell's **agent registry** (FleetDO's `agent_registry`), so every agent is seen, whatever it holds. Each AgentDO registers itself when made (its `registry` deadline), records there when its end is done, and leaves at its reap; one whose registration failed, or that predates the registry, registers at its next alarm (at least hourly). The view pages the sandboxes first, reading their attached agents only to classify each sandbox, then the registry's agents whose end isn't done, each read and counted once; agents whose end is done are counted from the registry without a read. A sandbox page lists an attached agent only once its records are gone (it isn't registered). A registered agent found gone (its reap couldn't leave the registry) is counted and its row dropped.
- **S3 footprint: counts only.** Per sandbox, its generation records and how many carry a memory snapshot. The control plane has no sizes: manifests and chunks are in S3, read only by hosts, chunks are shared between generations, and the GC report sums the whole bucket. Bytes would need hosts to report a manifest's size at commit.
- **Bounds:** a page is 50 rows (at most 100, `limit`): sandboxes in registration order after `cursor`, then agents (`cursor` `a`, then `a.<ms>.<agent>`); a sandbox page reads at most 200 attached agents (`agents_omitted` counts the rest; a sandbox with an unread attached agent is unknown, never held); 8 reads at a time. The Worker follows up to 20 pages and lists an agent once.
