# Dashboard

A read-only page of what is live in one cell: agents with a brain (template, `state` with its `lifecycle` and `activity`, current turn, brain host, phase and since when, bound sandbox; an agent without a brain is not listed, since no route lists agents and the fleet view knows only the brains it indexes); sandboxes and the host each runs on (one suspended to S3 is counted, not listed); live hosts with their residents; the sandbox templates. History and AMIs stay off it. It refreshes every 10 s. Code: `dashboard/` (Vite + React, its own Worker, `dash-nest.bitcru.sh`).

- **Apart from the platform.** The dashboard shares nothing with the control plane but its admin API: its own directory, package, Worker (`nest-dashboard`) and deploy workflow (`deploy-dashboard.yml`, on pushes that touch it). It reads `GET /v1/admin/fleet` and `GET /v1/admin/images`, and `GET /v1/agents/:agent` for the agents the fleet view lists on its hosts (`HostView.agents`), and nothing else: the Worker proxies the first two as they are, answers `/api/agents` itself (at most 100 agents, 4 at a time, each narrowed to the fields the page shows so prompts and rules stay in the Worker, one that cannot be read a row with its error), and refuses every other method and route.
- **The token stays in the Worker.** The control plane's admin token is a secret on the dashboard Worker, added to the requests the Worker makes; the page never sees it.
- **The Worker checks Access itself, and fails closed.** Cloudflare Access on `dash-nest.bitcru.sh` (an Allow policy for the owner's login, managed by the `edge` inframe stack: [setup](../../setup/), [deploy](../../../dev/deploy.md)) logs the owner in, and the Worker verifies the token Access adds to every request (`Cf-Access-Jwt-Assertion`) before serving anything, page or API: RS256 against the team's keys at `<team>.cloudflareaccess.com/cdn-cgi/access/certs` (cached an hour, refetched for an unknown key id), `iss` the team, `aud` the dashboard application's tag (the edge stack's `dashboard_aud` output), not expired ([Cloudflare: validate the JWT](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)). Without a valid one the answer is 403. So the token stays private on any path to the Worker that skips Access (`workers.dev` and preview URLs are off as well), and a hostname rename that leaves Access behind closes the dashboard instead of opening it. The team domain and audience are vars in `wrangler.jsonc`; the hostname follows the [naming rule](../../setup/#hostnames).
- **Typed by a shared contract.** `fleetView` and `images` return the types in `protocol/admin/view.ts`, a module that imports nothing, in the contract directory both sides depend on; the page imports them as types only (`src/api.ts`) and never imports the control plane, so its build carries no outside code and a field the page reads but the view lacks fails `npm run typecheck`. A test holds both rules, and the control plane asserts that the view's enums equal its protocol's. `fixtures/admin.ts`, a recorded response, must satisfy the same types. `GET /v1/agents/:agent` is not in that contract, so the page's agent fields (`src/agents.ts`) are unchecked against the control plane: each is read as optional and shown as unknown when absent, and a recorded response in the fixture holds their names. A sandbox row keeps the lease's state (`lease_state`) apart from SandboxDO's own (`sandbox_state`, null with `info_error` when it could not be read).
- **Reads only.** Operator actions stay with the API and the `nest` CLI; the page shows state and changes none.

**Not built:** per-agent detail (turns, transcripts), channels, cost, a second cell.
