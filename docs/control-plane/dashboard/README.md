# Dashboard

A read-only page of what is live in one cell: agents with a brain (template, `state` with its `lifecycle` and `activity`, current turn, brain host, phase and since when, bound sandbox; an agent without a brain is not listed, since no route lists agents and the fleet view knows only the brains it indexes); sandboxes and the host each runs on (one suspended to S3 is counted, not listed); live hosts with their residents; the sandbox templates; and [what is left lying around](#abandoned). History and AMIs stay off it. It refreshes every 10 s (what is left lying around, every 60 s). Code: `dashboard/` (Vite + React, its own Worker, `dash-nest.bitcru.sh`).

- **Apart from the platform.** The dashboard shares nothing with the control plane but its admin API: its own directory, package, Worker (`nest-dashboard`) and deploy workflow (`deploy-dashboard.yml`, on pushes that touch it). It reads `GET /v1/admin/fleet` and `GET /v1/admin/images`, `GET /v1/agents/:agent` for the agents the fleet view lists on its hosts (`HostView.agents`), and `GET /v1/admin/lifetimes`, and nothing else: the Worker proxies the first two as they are, answers `/api/agents` itself (at most 100 agents, 4 at a time, each narrowed to the fields the page shows so prompts and rules stay in the Worker, one that cannot be read a row with its error), answers `/api/lifetimes` by following the lifetimes view's pages (at most 10, a cursor sent on only in the control plane's shape) and merging them, and refuses every other method and route.
- **The token stays in the Worker.** The control plane's admin token is a secret on the dashboard Worker, added to the requests the Worker makes; the page never sees it.
- **The Worker checks Access itself, and fails closed.** Cloudflare Access on `dash-nest.bitcru.sh` (an Allow policy for the owner's login, managed by the `edge` inframe stack: [setup](../../setup/), [deploy](../../../dev/deploy.md)) logs the owner in, and the Worker verifies the token Access adds to every request (`Cf-Access-Jwt-Assertion`) before serving anything, page or API: RS256 against the team's keys at `<team>.cloudflareaccess.com/cdn-cgi/access/certs` (cached an hour, refetched for an unknown key id), `iss` the team, `aud` the dashboard application's tag (the edge stack's `dashboard_aud` output), not expired ([Cloudflare: validate the JWT](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)). Without a valid one the answer is 403. So the token stays private on any path to the Worker that skips Access (`workers.dev` and preview URLs are off as well), and a hostname rename that leaves Access behind closes the dashboard instead of opening it. The team domain and audience are vars in `wrangler.jsonc`; the hostname follows the [naming rule](../../setup/#hostnames).
- **Typed by a shared contract.** `fleetView`, `images` and `lifetimes` return the types in `protocol/admin/view.ts`, a module that imports nothing, in the contract directory both sides depend on; the page imports them as types only (`src/api.ts`) and never imports the control plane, so its build carries no outside code and a field the page reads but the view lacks fails `npm run typecheck`. A test holds both rules, and the control plane asserts that the view's enums equal its protocol's. `fixtures/admin.ts`, a recorded response, must satisfy the same types. `GET /v1/agents/:agent` is not in that contract, so the page's agent fields (`src/agents.ts`) are unchecked against the control plane: each is read as optional and shown as unknown when absent, and a recorded response in the fixture holds their names. A sandbox row keeps the lease's state (`lease_state`) apart from SandboxDO's own (`sandbox_state`, null with `info_error` when it could not be read).
- **Reads only.** Operator actions stay with the API and the `nest` CLI; the page shows state and changes none.

**Not built:** per-agent detail (turns, transcripts), channels, cost, a second cell, an agent index (agents without a sandbox, owner or child in view), S3 bytes.

## Abandoned

**What is left lying around, so nothing accumulates unseen** (owner's goal, 2026-11-01). The control plane decides what each thing is (`GET /v1/admin/lifetimes?cell=&cursor=&limit=&quiet_ms=`, admin token; FleetDO's `lifetimes`, rules in `control-plane/src/lib/abandoned.ts`); the page lists, sorts oldest first, and shows the API call an operator would make as text. The classes and both thresholds below are the owner's (confirmed 2026-11-02).
- **Sandboxes** (every live one in FleetDO's registry, each read from SandboxDO):
  - **Dormant:** SandboxDO's own rule (no agent attached, no placement in flight, no VM up; [lifetime](../durable-objects/sandbox/#lifetime)), with `dormant_since`, the TTL that applies (its own or the cell's) and when the lifetime check will destroy it (`destroyAtMs`, which mirrors `expiryStep` and is tested against it: the notice day for a TTL over a day, a missed-check gap restarting the clock; null before the clock starts). Already handled by the TTL; listed so it is seen.
  - **Held:** attached only to agents that will never use it (quiet, stuck ending, ended, or gone). Never dormant, so no TTL takes it: **the real leak**. Listed with its attached agents.
  - Unknown (an attached agent could not be read and none is active), destroyed (SandboxDO destroyed, the registry not marked) and unreadable are listed too. In use (no attached agent but a VM up or a placement in flight, or an attached agent active or recent) is counted.
- **Agents** (found as below, each read from AgentDO's `lifetimeFacts`):
  - **Quiet:** not ended, no brain, no start wanted, no turn current or queued, and no turn started for `quiet_ms` (default **a day**, the sandbox TTL's default; one that never had a turn is quiet). Listed with what it holds: its sandbox, its live children, its open channel subscriptions (a post would wake it), and whether the operator's stop is why it is quiet. A quiet agent may be a durable one waiting for input; the view does not guess intent.
  - **Ending:** ended, its steps unfinished for over an hour (they retry every minute: stuck). Listed.
  - **Gone:** its records pruned yet a listed sandbox still has it attached. Listed; one named only as an owner is counted.
  - **Ended** (its end done, its records awaiting the 30-day prune) is **noise: counted, not listed**. It holds nothing (its end detached it from its sandbox and ended what it owned), and its prune is already scheduled. Active and recent are counted.
- **How agents are found:** from the cell's **agent registry** (FleetDO's `agent_registry`, built 2026-11-02), so every agent is seen, whatever it holds. Each AgentDO registers itself when made (its `registry` deadline), records there when its end is done, and leaves at its reap; one from before the registry, or whose registration failed, registers at its next alarm (at least hourly). The view pages the sandboxes first, reading their attached agents only to classify each sandbox, then the registry's agents whose end isn't done, each read and counted once; agents whose end is done are counted from the registry without a read. A sandbox page lists an attached agent only once its records are gone (no longer registered). A registered agent found gone (its reap couldn't leave the registry) is counted and its row dropped.
- **S3 footprint: counts only.** Per sandbox, its generation records and how many carry a memory snapshot. The control plane has no sizes: manifests and chunks are in S3, read only by hosts, chunks are shared between generations, and the GC report sums the whole bucket. Bytes would need hosts to report a manifest's size at commit.
- **Bounds:** a page is 50 rows (at most 100, `limit`): sandboxes in registration order after `cursor`, then agents (`cursor` `a`, then `a.<ms>.<agent>`); a sandbox page reads at most 200 attached agents (`agents_omitted` counts the rest; a sandbox with an unread attached agent is unknown, never held); 8 reads at a time. The Worker follows up to 20 pages and lists an agent once.
