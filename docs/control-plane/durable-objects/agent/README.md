# AgentDO

The authority for one agent (conversation).

- **Brain lifecycle:** its rules are pure decisions in `control-plane/src/lib/brain.ts` (how a brain's end counts and wakes, a refused start, an unresponsive brain, an intent against a live brain, escalation's verdict, each phase's deadline), table-tested; AgentDO sequences the awaits and applies each decision in one synchronous step with the deadlines it arms.
  - `agent_start` goes to a [brain host](../../../compute/brain-hosts/) with room, preferring the host that ran the agent last (FleetDO's `placeBrain`); where the agent's sandbox runs plays no part, and a sandbox host never gets one. An agent with hands has its sandbox woken alongside (a suspended one resumes, an unplaced one is placed); the brain doesn't wait for it, and only a sandbox that can never run again stops the start. An operator may name the host (`POST /v1/agents/<id>/start {host}`, an active, connected brain host of this release in the agent's cell) to pin a brain for a test. For `api-loop` the loop runs in this DO. The setup token named in the spawn spec travels as a BrokerDO reference.
  - **Agent epoch:** each start issues one (`agent_start.epoch`, a counter in AgentDO that only grows, for every agent). The brain presents it in its session hello; a hello with any other epoch is stale. Platform tool calls and asks are keyed by it, events are filtered by it, and brokered actions are fenced by it (checked as each request leaves). Hands calls carry the sandbox's epoch instead, inside the binding: AgentDO keeps no copy of the sandbox's epoch, only the sandbox's id. The guest `nest` CLI and task exits are fenced by FleetDO's lease check (`holds()`) before they reach AgentDO, events about the sandbox carry SandboxDO's current epoch, and each turn records SandboxDO's epoch when it starts (`turns.hands_epoch`), so the recovery turn can tell whether the sandbox moved during it.
    - **One brain per agent: the brain record.** A control-plane rule, not a gateway fence. AgentDO holds one durable record, `brain` (null, or `{host, epoch, since_ms}` in phase `starting`, `live` or `condemned`, a condemned one with the kill FleetDO stored for it, `kill: {cmd, ms}`), and one stored start request, `intent: {host_hint?, avoid?, reason: operator | wake | drain | retry}`; nothing else says where the brain is (the API's `host` is derived from `brain`). Every transition arms the alarm that carries it on in the same synchronous step (the deadline row is written before any await), so a reset between steps strands nothing.
      - **Current:** a session is current iff `brain` is set, isn't `condemned`, and the session's epoch is `brain.epoch`. Hello, tool calls, `hands_resolve` (checked again after the resolve), every event of a batch, turns and every platform write after an await check it, so a condemned or superseded brain gets nothing, even when it reconnects at its own epoch.
      - **Start** (an operator's `POST /start`, a wake, a drain, a retry: each merges into `intent`, newest fields winning, and the intent is run single-flight; the answer is `started`, `waiting` or `none`). First FleetDO is asked about the brain's host: if its brains are proven gone (its lease expired, or its death confirmed; a host merely retired as dead doesn't count), the brain is released. No brain: pick a brain host (the hint, else FleetDO's `placeBrain`: the last brain's host if it has room, for a warm session, else the fullest with room; never `avoid`, never a sandbox host, and never a host of the previous release: one whose hello didn't say `brain_epochs`; with none the start waits, its intent kept and retried after 30 s doubling to 5 min (`capacity_waits`, reset by the next start; not the crash-loop guard's), and FleetDO launches a brain host if capacity is really short; a start FleetDO refuses because the host filled meanwhile is condemned like any unconfirmed send, uncounted), bump the agent epoch, record the brain `starting` with its deadline, send `agent_start{epoch}`. A brain that isn't condemned is never started again (no same-host re-issue: at most one start of an agent is outstanding on a host): it is condemned when the start moves it (another hint, its host avoided, or its host no longer active: draining, expired, lost or wedged; a brief socket drop isn't a reason) or is an explicit restart (`POST /start {restart: true}`; a later plain start never downgrades it), with the intent kept, so the start follows its release (maybe on the same host). Otherwise the start answers `none`, and an operator's intent stays only for a graceful stop's `stopped` exit (so a start during a stop runs after it); any other end of that brain drops it. Condemning closes and fences its sessions at once, before anything is made durable (late bytes go to the orphan branch), and answers `waiting_for: <its host>`. The kill is part of the condemn: the record owes it (no `kill`) and the `condemned` alarm is armed in the same step, so `agent_stop{mode: kill, epoch}` is issued until FleetDO has stored it (`issueKill` keeps one per agent and epoch). A start without a hint never moves a live brain, least of all to follow its sandbox. Decisions are committed only if the record and intent are still what they were when taken. A start whose send fails is condemned, never forgotten (its command may have been queued), and its intent kept.
      - **Stop** (an operator's `POST /stop`): ends every start wanted before it, in one synchronous step with its alarm: an operator's start kept beside the brain, a move or restart waiting for a condemned brain's release, and a start still waiting for a brain host (FleetDO is told to drop the agent's `brain_waiters` row, so the tick launches no brain host for it; a run that records a wait after that notice drops the row itself when it fails). Wakes armed before it (`wake`, `wake_after_exit`) go too. A run of the intent in flight finds it gone at its re-check and commits nothing, and its failure arms no retry. **One rule then covers the brain it ends:** the stop records `stop_epoch` (the agent epoch then), and a brain at or below it is stopped, however it ends: its release (a `fenced` exit after a condemn, its host's loss) counts as `stopped`, so it wakes nothing and isn't counted; a failed send or a host's refusal of its start condemns it with no retry and no `errored`; its host's drain condemns it with no move; an exit without an epoch, or the `starting` or no-session deadline, condemns it without counting, erroring or waking. A live brain gets a graceful `agent_stop`. **Only what comes after the stop starts the agent again,** and it always does: an operator's start (kept, and run after the stopped brain ends), or input from outside the agent (a turn, an inbox message whatever its `from`, a delivery merged into a queued turn; the platform's own notes about its work, a sandbox move or a background task's exit, sent as `system`, are not input). The stop sets `stop_quiet`, which that input clears; it quiets wakes only while no start has been issued since the stop (`stop_epoch` still the agent epoch), so a start after it ends it too. While it is quiet no wake runs, so work that predates the stop (a queued turn, the turn in progress) waits, whatever arms the wake: a release, a sandbox move (including one the cancelled start's placement began), a wake alarm. Input after the stop clears it even while the stopped brain winds down, and that brain's end, however it comes, then wakes the agent (uncounted). A placement begun by a start the stop cancelled may still place or resume the sandbox: that costs a VM until its idle suspend (11 minutes) and starts no brain.
      - **Release:** a brain on a host of the previous release is released only by that host's loss (its lease expiry, or its confirmed death); its exits, and escalation's processed kill without a row, prove nothing. Past the 15-minute cap its host is wedged like any other, so the wait ends in that host's loss. Otherwise `brain` is cleared only by `agent_exited` from its host at its epoch or later (an exit there means nothing of the agent at or below that epoch still runs there), or by its host's loss: FleetDO's notice carries the index row's epoch and releases only a record at or below it, and only while FleetDO still reports the host's brains proven gone. A failed `agent_start` never releases: it condemns the brain at that epoch (killing anything at or below it there) and records the retry (an intent, up to 3 times) or `errored`; the start's own exit, owed by nestd until older brains there have gone, releases it. **A condemned brain's exit reason describes its kill** (`fenced`, `stopped`), not the brain, so its release restarts nothing of its own and isn't counted: whatever condemned it kept an intent or woke if a start is wanted, and a refused start left `errored` stays so until new input. An exit without an epoch (FleetDO's row is the previous release's) isn't ignored: it condemns the brain, and escalation proves it gone. Anything else that doesn't match the record is ignored. The intent then runs from the alarm.
      - **Escalation** (60 s after the kill was stored, then every 60 s): its host's brains proven gone → released. No kill stored yet → sent again, never a reason to wedge. The kill processed, and FleetDO's index has no start at or below the brain's epoch there → released. The kill not processed and the host processing no commands at all (no result since the kill was stored, nothing older pending) → wedged ([FleetDO](../fleet/)). Otherwise (a host working through commands queued before the kill) → checked again, and wedged after 15 minutes. On a previous-release host escalation waits for the host's loss and wedges it only at the cap. The record is re-checked after every await before anything is decided. A wedged host's brains are released only when STONITH confirms it dead (an operator, without EC2); its blast radius is the whole host: every brain on it restarts, and every sandbox on it is placed again from its head.
      - **No session:** a live brain whose current session went away arms a 10-minute deadline (cleared by the next hello); past it, with no exit either, the brain is condemned.
      - **Orphans:** a host whose hello reports a brain the record doesn't place there gets a kill for it (at the highest epoch issued), whatever left it running. A condemn always names the epoch it is for, so a record replaced meanwhile is never condemned by it.
      - **Migration from the previous release:** `host` becomes the brain record, migrated once and persisted with its alarm: `condemned` if the agent was detached or errored (the previous release kept `host` after an exit), `starting` or `live` otherwise (a live one with the no-session deadline). Its `restart` alarm is dropped (it fired long ago).
    - **A draining host's brains** are condemned at once (in the background, in parallel) with an intent that avoids the host, whether or not another host exists; each starts elsewhere once its exit (or the host's loss) releases it.
    - **Migration:** state stored before the agent epoch has `hands.epoch` (the sandbox epoch its brain was started with); `load()` starts the counter there and drops the field. A hello with epoch `0` (what a runner that predates the agent epoch presents) is always stale.
  - **Hands:** for an agent with hands, `create` calls SandboxDO `attach`, and `agent_start` names the sandbox only. The runner fetches the target (gateway URL, binding, guest version) with `hands_resolve` on its session channel, which AgentDO answers from SandboxDO's `resolve`, and only on the current runner's socket: a stale runner (an older epoch or a superseded process) gets `stale_epoch` and no binding. The binding never passes through FleetDO, nestd or a stored command. **The brain survives its sandbox moving:** `onSandboxMoved` neither restarts nor reconnects it and leaves the agent epoch alone; its next call is refused and it re-resolves. It is told what the restore lost (the head generation's time, and whether processes stopped): every turn starts by comparing SandboxDO's epoch with the one the brain was last told about (`told_sandbox_epoch`, durable, so no notice can be lost) and begins with the note when they differ; mid-turn, the move notice also queues it at once as a `system` inbox message (reliably, without needing a live session); a brain that died mid-turn hears it from its recovery turn ([SandboxDO](../sandbox/)). SandboxDO sends move notices from its own alarm, never inside a call (a placement made by an agent's own start would otherwise call back into it), and the notice never starts a brain itself: it records when the move happened and sets the wake alarm for a stopped brain with work waiting; a `hands_resolve` places a sandbox left unplaced (evicted while idle), since no brain start will. A brain follows its own host instead: when that host's brains are proven gone (it expired after 30 s of silence holding no lease, or its death was confirmed by STONITH or an operator, or it never connected), AgentDO starts it again elsewhere.
  - **An agent's cell is its sandbox's:** `create` refuses a mismatch, and the API takes it from the sandbox when omitted. Its brain starts through that cell's FleetDO.
  - Retryable start failures are retried 3 times (through the intent).
  - **A start refused for good** (non-retryable: a credential its client's grant doesn't name or that isn't stored, [BrokerDO](../broker/)) drops the intent and leaves the agent `errored`, recording why as `start_error {code, message, ms}` in the same step, which also queues its client's `agent.error` (`start_refused`). It is recorded only by a step that makes the agent `errored` (a refusal while a brain still runs records nothing), and entering `errored` any other way drops an older one, so a stale reason never labels a later error. The next start issued clears it.
  - **`starting` has a deadline:** a brain that hasn't said hello 4 minutes after its `agent_start` (above the runner's own budget before its hello: session rebuild 120 s, auth check 20 s, version 10 s, session open 10 s) is condemned (`errored`, counted by the crash-loop guard); waiting work starts it again once it is released. The deadline doubles for each consecutive timeout, up to 16 minutes, so a slow start isn't condemned for ever.
  - Exits and host reports count only from the brain record's host.
  - **Waking:** a brain that isn't running (it went idle, exited or lost its host) starts again whenever work is waiting: a new turn, a due [scheduled wake](../../../agents/capabilities/#schedules) (an alarm here), or the turn it was in the middle of. It resumes; an agent with memory starts fresh from it instead when its last turn was over an hour ago and its session is over ~50k tokens. A turn cut off by a crash always resumes. See [continuity](../../../agents/#continuity). A start with no host available retries every 30 s, and brain starts per cell are capped so a broadcast can't start every brain at once.
  - **Crash-loop guard:** an exit other than `stopped` or `auth_failed` restarts the brain at once if work is waiting. Each is counted once, where it happens (the release of a brain that ended on its own, a start or session deadline, an exit without an epoch; a condemned brain's exit isn't counted again); after 3 such restarts without a completed turn, the agent is `errored` and only new input retries.
  - **A brain whose host goes silent** for 30 s is released when FleetDO expires the host, and starts again on another brain host; its sandbox, if it has one, is untouched. See [FleetDO](../fleet/).
- **Session socket:**
  - Only the brain record's host, in the agent's cell, while that host is live, may attach.
  - A new socket supersedes the old one only after a valid hello.
  - A stale epoch gets the orphan branch only.
- **Runner lineage:** the runner's hello carries `instance_id`. A new runner process resets the channel's seqs and event dedup, and the turn it was in the middle of comes back first as a `recovery` turn.
- **Timers** ([timers](../../../agents/capabilities/timers/), built 2026-11-02): `timers` (`name`, `id`, `at_ms`, `note`, `set_ms`), each row armed in the same step as one deadline of the existing alarm, `timer:<name>`. A fired one goes through `postInbox` (from `timer`, keyed `timer/<id>`), then its row is deleted. `timer_set`, `timer_cancel` and `timer_list` are brain-only platform tools; `timers()` and `cancelTimerFor()` serve the owner's routes. An end drops every timer and its deadline.
- **Turns and inbox:**
  - One turn at a time. `TurnQueue` (`control-plane/src/lib/turns.ts`) is the only code that touches the `turns` and `inbox` tables, and every status it writes goes through one pure step each (`turnStep`, `inboxStep`: status and event in, the next status or `refuse` out; 2026-11-09). So the guards are the ledger's, not its callers': only a queued turn is claimed, only an active one completed or recovered (a second `recover` adds no second recovery turn), and `done`, `interrupted` and `dropped` are final. The hourly prune also settles by age what can't end on its own: an active turn that isn't the agent's current one and started over 7 days ago is interrupted, and a message still mirrored to a turn that is no longer active comes back as a queued turn, as one unconfirmed at a turn's end does (the model never saw it, so it isn't dropped). The agent's own turn is never interrupted by age: AgentDO passes `current_turn`, so a turn that has run for over a week under a live brain stays. Queued turns are work and are never pruned. AgentDO decides when to call it. Its input is the operator's turns and inbox posts, a spawner's task, answered asks, and the platform's own notes. Channels and their deliveries left the platform ([principle 9](../../../README.md#principles)): the previous release's `channel_subs`, `chan_wakes` and `chan_out` rows are left unread (an undelivered `chan_out` post is lost; its `chan_out` deadline is dropped as unknown), and no agent event is posted. Agent events to owners are kernel work not built yet.
  - **State follows the current turn:** a `turn_started` or `state_changed` stamped with another turn (a finished turn's trailing `idle`, reported after its `turn_completed` when the next turn may already be running) leaves `state` alone. `pump` sends a claimed turn only if it is still current after its awaits (a new runner process may have recovered it meanwhile).
  - Mid-turn inbox messages go to the runner (`inbox`) and to its inbox mirror (the cache), from which it shows them to the model ([runner](../../../agents/runner/)). **AgentDO is the only source of turns:** a mirrored message the runner never confirmed (`inbox_delivered`) by the time the turn completes, whoever sent it, comes back as one queued turn (`TurnQueue.complete`), so a message is never lost with a turn that ended before the model saw it; ahead of the turns already queued if one of the messages interrupted the turn, else where the first of them arrived (`inbox.created_ms`): behind the queued turns created by then, ahead of those created later. The emptied mirror goes to the runner in that step, ahead of any later `run_turn`, so its old cache can't show a requeued message again inside the turn that carries it.
  - Interrupts are supported.
  - **Who a message is from:** the platform's notes go through `systemNote` (not input, dropped once the agent has ended); everything else through `postInbox`, which refuses an ended agent and counts as input. The sender a post names is checked by its route: an API client's is a label of its own, never one of nest's, marked with its id ([inbox senders](../../api/clients/#inbox-senders)).
  - **Admission is idempotent:** a turn or inbox post with a `request_id` (body, or `Idempotency-Key`) that AgentDO has seen returns the same turn or message, queued once.
  - **Recovery turn:** a turn cut off by a brain restart (a new runner process) comes back first as a `recovery` turn, queued at the front in the same step as the hello that cleared the turn, the only way an interrupted turn continues: the runner never sets `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`, so Claude Code can't also continue it. It says where the durable transcript ends (actions after that may have taken effect without appearing in it), and, if the sandbox moved during the turn (decided when the recovery turn starts: SandboxDO's epoch differs from the one recorded when the interrupted turn started), the time of the head generation it was restored from (changes after that are lost; processes stopped when it was disk-only). Interrupted again, it keeps the original turn's text. The outcomes of hands calls that were in flight come from `call_status` through the gateway ([hands](../../../agents/hands/)).
  - **No cascade:** an operator's stop or an interrupt affects only that agent; its open asks stay answerable, and an answer becomes its next turn. An [end](#ending) does cascade, through the ownership the spawner recorded (an index, not a structure: who structures what stays convention).
- **Session stream:**
  - One stream per file of the session directory (the main JSONL, subagents, sidecars), keyed by relative path.
  - Acked to the **agent runner** by offset once committed to SQLite, which is durable.
  - Flushed to R2 as segments at 1 MiB, at turn end, after 30 s idle, and **before any start**, so `--resume` gets everything AgentDO holds. One flush at a time: two reading the same rows would write one R2 key twice, and the shorter put landing last would lose acked bytes.
  - SQLite holds the segment index and the unflushed buffer.
  - **Rewritten file (`base: true`) or new session id:** a new receive stream starts. The committed base stays what `--resume` and transcripts read until the new stream is durable and caught up, and, when its base segment said how long the rewrite is (`total_bytes`), until at least that much is durable (`streamCommittable`; 2026-11-09): a rewrite arriving in several segments is never committed part-way by a flush between them, where a brain dying before the rest came would resume from a truncated session. A rewrite whose rest never comes stays uncommitted, and the old base resumable. **It is then dropped, never spliced:** when a brain is started (it resumes from the committed base) and at a new runner process's hello, an uncommitted receive stream is forgotten (`dropUncommittedStream`). The receive state is the base's again, `hello_ack.durable_bytes` is the base's, and the stream's buffered and stored segments are deleted (a dropped stream's number is never reused, `recv_high`). The rows go at once; the R2 keys are listed in `seg_trash` in that step and deleted behind it, tried again every minute (the `seg_trash` deadline, armed again at any alarm that finds keys listed without it) until R2 took the delete. A flush that was mid-put when its stream was dropped writes no `segments` row and lists its object there too. **A rewrite received whole isn't dropped:** at a hello, one whose stated length has all arrived and only waits to be made durable is flushed first, so it becomes the base (a runner process replaced without a brain start loses nothing). One of unstated length (a previous release's runner) can't be known whole and is dropped. Otherwise the new runner, resumed from the old file, would be told the partial rewrite's byte count, append the old file's tail to it, and that mix would become the base.
  - See [../../../agents/sessions/](../../../agents/sessions/).
- **Events:** applied in order, deduplicated by event seq within a runner lineage. An event counts as seen only once its side effects succeeded (an escalation's ask, the sandbox's activity); they are idempotent, so a failure leaves the batch unacked and the resend runs them again. See [../../../agents/state-tracking/](../../../agents/state-tracking/).
- **State:** two fields, stored apart. `lifecycle` is AgentDO's (`starting`, `ready`, `detached`, `errored`), written only by its own transitions; `activity` is what the runner last reported (`working`, `idle`, `waiting_permission`, `quota_parked`, …), cleared when a brain starts or is released. The API's `state` is derived: the lifecycle, or while it is `ready`, the activity (`ready` until the first report). A runner's report can't erase AgentDO's `errored`, nor a release leave a dead brain's report behind. `state` is also written into the stored record, for the previous release, which reads it; a stored `state` that disagrees with the two fields (written by the previous release after a rollback) is read as the authority.
- **Working:** AgentDO owns whether the agent is working (a brain running and busy or mid-turn) and tells SandboxDO's idle refcount with `agentActivity`, a "set to", whenever that differs from what SandboxDO last acknowledged. A failed call is retried from an alarm every 5 s, and every session hello re-asserts it, so a lost call can neither suspend a sandbox mid-turn nor keep it awake for ever.
- **Tool relay:** `CallLedger` (`control-plane/src/lib/calls.ts`) is the only code that touches the `tool_calls`, `asks` and `approvals` (sink calls waiting for, or spending, the operator's approval: [taint and sinks](../../../agents/tools/#taint-and-sinks)) tables; where an answer goes is a pure decision there (`askRoute`). Every status the three tables hold is written through one pure step each (`callStep`, `askStep`, `approvalStep`: status and event in, the next status or `refuse` out; 2026-11-09), so the guards are the ledger's, not its callers':
  - **A call gets its outcome once.** A finished call keeps it (a second finish, a cancel and a wait are refused), and `finishCall` sends `tool_result` only when the outcome was stored, so a call the runner cancelled is never answered later.
  - **An ask is answered once** (the first answer stands), and **an approval is decided once** and spent on one call (`approvalUsable`: approved, unexpired, unspent or spent on this same call key).
  - **The hourly prune settles by age what can't end on its own:** a call still `dispatching` or `waiting` after 7 days ends `outcome_unknown` (its brain is long gone), and an ask a previous release's call or guest CLI was still waiting inside (`sync`, `cli`) becomes an ordinary open ask. An open ask and the pending approval it decides are the operator's work: they stay until answered, however old.
  - **Brokered actions:** run here, through the pipeline in [brokered](../../../agents/capabilities/brokered/#the-pipeline); `BrokeredJournal` (`lib/brokered.ts`) is the only code that touches `brokered_journal`. The epoch is checked, and the row written `sending`, in the same synchronous step as the request leaves. `egress_policy` widens the bound sandbox's egress through SandboxDO (`widenEgress`, `narrowEgress`).
  - **Remote MCP tools:** an mcp capability's tools are called through AgentDO's own MCP proxy (`lib/mcp-proxy.ts`, the only code that touches `mcp_servers` and `mcp_forwards`): the epoch checked as each request leaves, older epochs' forwards settled first, a call key forwarded once unless idempotent. The list, and a slot for each call, come from the server's [connector](../mcp-connector/); a connector's notice that the list changed (`mcpToolsChanged`) becomes `tools_changed` to the runner. See [mcp capabilities](../../../agents/capabilities/mcp/).
  - **Checks:** grants and argument validation (types, enums, bounds, array items).
  - **Idempotency:** idempotent on the call's id: a call first seen at an earlier epoch keeps that epoch's row and key, so its writes never run twice, while a stale epoch's session gets nothing at all. A guest `nest` command is fenced by FleetDO's lease check and keyed by the sandbox lease it came under, never by the agent epoch, so a brain start mid-call doesn't fail it. A call's seq is marked processed only after it ran, so a call cut short by an eviction is run again when redelivered. A re-run repeats no side effect: every write a tool makes to another object carries the key `<agent>/<epoch>/<call>`, applied once by its target (the child and its inbox for `agent_spawn`, the brokered journal, an MCP forward, a grant id), and a held call re-run reuses its ask. A new mutating tool must do the same before it ships.
  - **Grants:** each call needs a grant held by this agent; `grant` and spawn specs are checked for attenuation (a subset of this agent's grants).
  - **Changes under a live session:** grants and rules apply at the next call (a revoked tool fails at once). The tool list the model sees comes from MCP `tools/list` at brain start, so a new tool appears at the next start, and a changed schema is validated against the current catalog. Upgrades that replace the brain mid-turn go through the recovery turn.
  - **Asks (approvals):** a call the sink gate holds, or one a tool rule in `ask` mode denies (the runner's `escalation` event), is recorded as an ask in one synchronous step (with its approval, if a sink), logged, and listed by `openAsks` (`GET /v1/agents/<id>/asks`) until answered; the answer (`POST …/asks/<ask>/answer`) comes as an `ask_answer` turn, an approval letting that one call through once within an hour. The same call, or the same sink with the same arguments while undecided, holds the same ask. Owners hear of asks once agent events reach them as webhooks (not built).
  - **Compat (one release):** an ask the previous release's `ask` tool left in its sync window (`sync`, with an `ask:<id>` deadline) still ends its waiting call `pending` when the window lapses, and an answer inside it is the call's result while the brain that asked is current; a guest's `cli` ask is answered as a turn.
  - **`read_transcript`** of another agent needs the caller to own it (transitively, as `agent_stop`), or a [transcript grant](../../../agents/tools/#built-transcript-grants-2026-11-06) that reaches it, whose limits then apply.
  - **Grants** it holds are rows of `grants` (one JSON `HeldGrant` each), written in `create`'s step with the record, never changed. `grantFor(id)` answers another AgentDO walking a chain: the grant, whether this agent has ended (from the moment its end is asked for), and its subtree. `info()` shows them as `grants`.
  - **`read_transcript`** pages by entry, where an entry is a 1-based line of the session JSONL. `since_seq` is the last entry seen, the default limit is 200 (max 500, about 256 KiB), and reads stream segment by segment. Each page names its `base`; a reader passes it back with `since_seq`, and if the file was rewritten since (a new base), the page starts again from entry 1 with `reset`. The HTTP transcript (`?since=&base=`) is the same cursor, so a client attaching mid-turn reads to `more: false`, then polls from `next_seq`.
- **Spec:** grants, priority, labels, owner, and rules for the runner's local hook answers.
  - **Built:** the expanded spawn spec from [CatalogDO](../catalog/), copied in at spawn: template name, tools (what `tools_list` offers and every call is checked against), launch, rules, and `credential` (the BrokerDO name its setup token is resolved from), plus `owner`. Nothing branches on a role. A spec stored with channel tools, `channel_grants`, `notify`/`ask`/`emit`, `escalate_to` or `subscribe` still loads and starts: the tools are no longer offered (a call answers `unknown_tool`), and the fields stay in the record untouched for a rollback but aren't shown.
  - **Compat (one release):** the record also holds `workstream`, the `ws_` value `agent_start` carries to runners of the previous release (a real id for an agent made before workstreams left, `ws_<id suffix>` since); not shown, and nothing reads it.
  - **Owner:** recorded once, at spawn, and checked then to name an agent.
  - **Migration:** a record stored with a `role` loads as that role's frozen spec (`ROLE_SPECS`, what the seed gives at this release, kept apart so a catalog edit never changes how an old record reads), with the launch and rules it stored and its `grants` list narrowing the tools (names the role didn't offer are ignored, as they were); its `captain` becomes `owner`. Persisted once.
- **Taint:** one bit for the current session, set from runner events (hands results, web tools), from `mcp` and `api` capability results, from tainted input and from reads of tainted content, and checked on every sink call. See [taint and sinks](../../../agents/tools/#taint-and-sinks). **Built:** a conservative stand-in: an agent with hands or a web built-in is tainted from the start, and taking in another agent's possibly tainted text (a relayed inbox post, a spawner's task, a transcript) sets a sticky bit (kept for the agent's life, since every start resumes its session). An untrusted [mcp capability](../../../agents/capabilities/mcp/#taint)'s tool list or result sets the same bit. The sink gate reads it (remote MCP tools, brokered actions, `egress_policy`).
- **Budget:** tracked against its owner's subtree. An agent over budget is parked, and the overrun waits for the operator.
- **Hands outcomes:** the runner's `tool_call` and `tool_result` canonical events, plus the `call_status` lookups it makes after a crash, build the recovery context. Nothing about hands arrives from nestd.
- **Backend:** for `api-loop` agents (deferred until the API credits are picked up), the DO runs the model loop itself and opens one outbound WebSocket to the sandbox's gateway per hands call, with the same binding a runner would hold. See [../../../agents/backends/](../../../agents/backends/).

**Not built:** scheduled wakes, the resume-or-fresh choice, the per-cell start cap, the rest of the spec (grants, labels, budget, priority), taint beyond the stand-in above, budgets, and `call_status` lookups after a crash (the [hands journal](../../../agents/hands/)). An operator-stopped agent (not ended) keeps its slot and its gateway client entry until its sandbox's epoch moves. Session bytes are acked after the R2 put and flushed every 5 s, and a turn for an agent that was never created is refused. See `control-plane/README.md`.

**Events to its client** ([events to the owner](../../api/clients/#events-to-the-owner)): an agent in a client's subtree writes each event to its `client_events` outbox in the step of the change it reports (a completed turn, an ask recorded, a runner `error` event, the move into `errored`, its end done), with the `client_events` deadline in that step. The alarm hands them to ClientDO (`enqueue`, 100 at a time, cut off at 10 s), deleting rows only once it answered; a failure is retried every 5 s. Nothing on the turn path waits on ClientDO or the webhook. The event's id is derived from what it reports (`<agent>/turn/<turn>`, `<agent>/ask/<ask>`, a runner event's epoch, seq and time), so a resent event batch repeats the same event. `kv.turn_text` keeps the current turn's last `assistant_text` for `turn_completed`'s `text`. Every alarm run (the hourly `prune`) arms the deadline again for waiting rows a rolled-back release left. An agent with no client writes none.

## Live trace

The [live trace](../../api/#live-trace) (2026-11-02): `control-plane/src/lib/trace.ts` holds the shape, the redaction and the ring; AgentDO writes and sends.
- **Two kinds of socket, kept apart by tag:** the runner's is `session`, a trace client's `trace`. Nothing on the session path lists or reads a trace socket (fencing, the current socket, superseding), and a frame or close from a trace socket returns before any session handling. The runner sends only JSON objects, so the `ping` auto-response never answers it.
- **Written in the step of the change:** a runner event's trace row is written right after its dedup check, before the state it changes and before any await, keyed by the runner's own stamp (`<epoch>.<seq>.<ts_ms>.<type>`), so a batch applied again after a throw records it once. `state` is written by `update()` whenever the agent's state changes; `ask` with the ask's record, `ask_answered` with the answer, `ended` with `done_ms`.
- **The ring:** `trace` (`seq`, `at_ms`, `src`, `body`) and `trace_head` (the last seq given, so a pruned seq is never reused). Each append prunes past the newest 1,000 rows or 24 h; a connect prunes by age too.
- **Never blocking the agent:** a send is a synchronous `ws.send` to each open trace socket right after its row is written: nothing awaits it, and Durable Objects hold outgoing messages until the writes before them are confirmed ([storage API](https://developers.cloudflare.com/durable-objects/api/storage-api/), "pause outgoing network messages … until all previous writes have been confirmed"), so no client sees an event the ring could lose. A send that throws closes that socket (1011). A slow client never holds anything up; nothing here measures its backlog, because a Workers WebSocket exposes none (unverified: no `bufferedAmount` is documented).
- **A connect** (`fetch`, path ending `/trace`, its caller already checked by the Worker) is one synchronous step: the socket is accepted and numbered, the oldest beyond 8 closed (4008), then the gap, the backlog, and `live` (or, for an agent whose end is done, `ended` and a close). No event can land between the backlog and the first live send. Every answer carries `x-nest-trace: 1`, so the Worker tells a previous release's answer (its session route's 400) from this one's and answers 503 for it.
- **History** (`traceHistory`, [trace history](../../api/#trace-history)): reads the committed base's segments from R2 backwards (a line may span segments), normalizes each entry (`lib/trace-history.ts`), and stops at the ring's seam (`TraceRing.seam()`), leaving out what the ring holds near it (`TraceRing.identity()`). A connect whose backlog starts at or before the seam sends the cursor (`history`, and `gap.before`) when the agent has transcript bytes. Nothing in it writes.
- **Ending:** once `done_ms` is set, `ended` is recorded and every trace socket closes (1000). The `reap` deletes the ring with the rest of the storage.

**Cost:** an AgentDO is billed for duration only while it's active. Hibernatable sockets and alarm-based timers let an idle one hibernate; pending `setTimeout`s, RPCs and fetches keep it active (and billed) for up to 15 minutes each ([changelog](https://developers.cloudflare.com/changelog/product/durable-objects/)). Even an AgentDO that never hibernates (about 10.8k GB-s/day at 128 MB) costs roughly $4/month beyond Workers Paid's included 400k GB-s/month ([pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/)). An `api-loop` brain's outbound WebSocket to a gateway does not hibernate and holds the object in memory for up to 15 minutes ([WebSockets](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)), so the DO is billed while a hands call is open: an agent spending two hours a day in hands calls uses about 27,000 GB-s a month, inside the included amount.

## Ending

An agent [ends](../../../agents/#lifetimes) by `agent_stop` from an agent that owns it (the target's owner chain must reach the caller, at most 4 hops), by `exit`, as an ephemeral agent that is done (checked right after a turn completes, with no turn current or queued, no open ask and no child that hasn't ended), by its owner's end, or by the operator (`POST /v1/agents/<id>/stop {end: true, destroy_sandbox?}`). Code: `endAgent`, `endBrain`, `finishEnd`, `reap`; rules in `lib/lifetimes.ts`.
- **One step:** `ended {ms, by, reason, kill, destroy_sandbox, note?}` is written with an operator stop's effects (no intent, `stop_epoch` at the agent epoch, `stop_quiet`, the `intent`/`wake`/`wake_after_exit` alarms cleared), every queued turn and mirrored message dropped (`dropped`), and the `end` deadline. Nothing lifts it: `setIntent`, `wake`, `start` and `inputArrived` check it, so the brain rules see a stop that no input follows. A second end answers `already_stopped`. `agent_stop`'s write passes the caller's epoch fence after its awaits, like every tool write.
- **The brain:** a kill (`agent_stop`, an owner's end, the operator's) condemns it through the usual path; a graceful end (`exit`, done) leaves the turn in progress to finish, then sends `agent_stop{mode: graceful}` at that epoch (from the turn's completion), condemning it instead past 15 minutes (`END_GRACE_MS`). Its release drops the turn it was in and arms `end`.
- **The rest, from `end`** (each step recorded once done, retried every 60 s): the agents it owns (its `children` index) are asked to end, killed (`asked`); once its brain is released **and each of them has finished ending** (its `childEnded`, which also runs this deadline now; one sharing its sandbox detaches only then), `SandboxDO.release(agent, destroy)` detaches it and, with `destroy_sandbox` (an ephemeral agent's always), destroys a sandbox it owns that no other agent is attached to, in SandboxDO's one step; then its owner is told (`childEnded`, so it no longer counts against the live-children cap), and `done_ms`.
- **Rollback:** the previous release drops the `end` and `reap` keys it has no handler for; every alarm run (the hourly `prune` keeps one coming) arms them again when an end is unfinished or done without `reap`.
- **To senders it is gone:** turns and inbox posts answer `unknown_agent` (404), whatever sender a post names; the platform's own note is dropped. A start or a spawn is refused (409). `info()` still reads it.
- **Records:** the `reap` deadline, 30 days after the end (`AGENT_RECORD_RETENTION_MS`) and only with no brain record left, deletes its R2 session segments (`sessions/<agent>/`), then its storage; afterwards it is `unknown_agent` everywhere.
- **For the operator's lifetimes view**, `lifetimeFacts` reads (never decides) what an agent holds and when it last worked: brain, intent, current and queued turns, the latest turn's start, the operator's stop, live children, its end ([abandoned](../../dashboard/#abandoned)).
- **Spawning:** `agent_spawn` checks the template against `spec.spawn`, the depth and live-children caps, expands the spawn spec (`SpawnerOverrides`, the cell's idle TTL as the bound), indexes the child in `children` right after the epoch fence and before anything is made, checking the live-children cap again in that step (an index row may name a child never created; an end reads `unknown_agent` as done, and a refusal for good before the child exists takes the row back), creates the sandbox (`owner`: the child) and the child (`owner_is_caller`: not asked back, it awaits the call), each write behind the epoch fence, and posts the task to the child's inbox under the call's key. A spawner that ended while the child was being made (its end may have looked for the child before it existed) arms its end again for that child, which then ends before it gets the task. Ids are derived from the call's key (`keyedId`), so a redelivered call makes the same child, sandbox and turn.
