# FleetDO

One per cell: hosts, enrollment, leases, placement, drains, STONITH, base generations and command delivery.

- **Enrollment:**
  - **One-time enrollment token** minted by the operator for a host kind.
  - **AWS signed identity document**, accepted only for an instance this control plane recorded as launched in this cell, as the recorded role, from the recorded account and region, and only once.
  - **Order:** the CSR for nest-proxy's intermediate CA is validated before the proof is consumed, so a bad CSR doesn't burn a token. Only the fixed CSR shape is accepted, and the intermediate is signed with the KMS-held root ([TLS](../../../sandbox/networking/egress/tls/)).
  - **Host tokens** are short-lived and rotated over the fleet channel. A host that was disconnected past expiry can still open the fleet channel for 24 h, and gets a fresh token right after hello.
  - **Tunnels:** a sandbox host's enrollment also creates its Cloudflare Tunnel (`<label>-<host>`), the tunnel's ingress to the gateway on loopback, and the proxied DNS record `<host>-gw-<label>.<zone>` through the Cloudflare API (`control-plane/src/lib/cloudflare.ts`; the label and zone come from `NEST_DOMAIN`, the zone id is looked up once by name and cached in `kv`), before the hosts row is written. The proof is checked before the first Cloudflare call (an unauthenticated caller costs none) and consumed atomically with the row after them; a failed call fails the enrollment, a proof refused at consumption deletes the tunnel just created, and the host retries with the same proof. The response carries the tunnel token and the `wss://` URL; the row keeps `tunnel_id`, `tunnel_hostname`, `dns_record_id` and `tunnel_state` (from the hello and every `tunnel_state` event; each transition is logged), and `hostGatewayUrl` answers that hostname only while the state is `connected`, `connecting` while it is, and `down` (`resolve`: not ready, logged as an error) while a tunnel host reports `none`: its hello URL is its own loopback, which no runner can reach, so it is never handed out. Only a host enrolled without a tunnel is reached at its hello `gateway_url`. A 401 or 403 from Cloudflare (a revoked token, a missing permission) enrolls the host without a tunnel and logs an error rather than failing every enrollment in the cell; any other failure fails the enrollment. A proof already used by a host that never said hello (nestd gave up or died before saving the response) is accepted again: that host is marked dead, its tunnel released, and the new row takes the proof. A brain host gets none (nor a proxy intermediate: it sends no CSR, and one of the previous release that still does is answered with one for that release; a sandbox host without a CSR is refused), and so does a cell missing any of `NEST_DOMAIN`, `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_TUNNEL_API_TOKEN` (the harness). FleetDO deletes the tunnel (connections cleaned up first) and the record when a host becomes `dead` (scale-down, a confirmed loss, STONITH), after the fence, never blocking it; a daily sweep (`tunnel_sweep`, also `POST /v1/admin/tunnels/sweep`) retries the deletions a dead host's row still owes, then lists the account's tunnels with the name prefix and the zone's records with the hostname suffix and deletes those this cell recorded creating (`tunnels_created`, written before the first call) whose host is dead or never got a row within an hour, and forgets such a record once both listings succeed, are complete and show nothing left for it. A nest-shaped name it cannot account for (another cell or deployment on the account, a hand-made tunnel) is counted and logged, never deleted; nothing with another name is ever touched ([gateway](../../../sandbox/gateway/), [provisioning](../../../compute/provisioning/)).
- **Previous-release hosts:** a host whose hello lacks `brain_epochs` (or that hasn't said hello since the column was added) runs nestd of the previous release (no epoch keying, kills in order, no lease-lapse refusal). It is drained of brains on sight, at its hello and before its agents are reconciled, and again whenever it is active again after STONITH by fence: no new placements, its brains condemned (AgentDO never starts one there, `issueCommands` refuses an `agent_start` for it, and a brain there is released only on the host's loss). Its sandboxes stay where they are: nothing moves them, and a host holding a lease is never retired, so such a host ends by its loss (lease expiry, STONITH) or an operator (the rollout rule in `dev/deploy.md` keeps brains off such hosts). A brain there that outlives its kill by 15 minutes wedges the host like any other: that is safe because no start reaches it and its nestd kills every brain when its lease lapses (origin/main `crates/nestd/src/host.rs:1085-1090`, `self_fence`). A hello's expired-to-active write applies only if the host is still expired.
- **Host kinds:** sandbox hosts and brain hosts. Their `role` is stored, in host tokens and launch records too, under the previous release's names (`burst`, `controller`) this release and read under either name, so a Worker rolled back to the previous release reads everything this one wrote; the next release writes `sandbox` and `brain` and rewrites the rows ([deploy](../../../../dev/deploy.md#host-role-names-expandcontract)). A sandbox host reports hugepages, vCPUs and restore ABIs and holds sandbox leases; a brain host's capacity is counted in brains. Sandbox placement considers sandbox hosts only, and `issueCommands` refuses an `agent_start` for any host that isn't a brain host, so a sandbox host never gets a brain.
- **Brain placement** (`placeBrain`, for AgentDO): among the active, connected, unwedged brain hosts of this release with fewer indexed brains than they may hold (the cell's `brain.max_brains_per_host`, else 2 per reported vCPU, unverified), the agent's previous brain host if it is one (a warm session), else the fullest (then the smallest id); never the host a move avoids; where the agent's sandbox runs plays no part. The decision is `pickBrainHost` (`control-plane/src/lib/placement.ts`), a pure function; `placeBrain` gathers its inputs, clears the picked host's idle clock, and launches a brain host only when `brainHostNeeded` says capacity is really short (not for a host with room that is merely reconnecting; a previous-release brain host doesn't count toward `max_hosts`). An agent `placeBrain` turns away is recorded as waiting (`brain_waiters`, dropped when it gets a host, is poked, or hasn't retried for 12 min): while any wait, the tick launches a brain host itself when one is needed, and a brain host's hello, or a brain's index row going, runs each waiting agent's kept start at once (AgentDO's `pokeIntent`) instead of at its backoff. The cap itself is enforced by `issueCommands`, which refuses an `agent_start` (retryably, `capacity_exhausted`, before anything is stored or sent) for a host whose index already holds its cap of other agents' brains ([brain hosts](../../../compute/brain-hosts/)).
- **Keys and gateways for the seam:** the cell's binding signing key lives in BrokerDO; FleetDO fetches the public keys from it and sends `binding_key{keys}` to every host right after `hello_ack` (and after a token rotation), the way it pushes a host token, and nestd forwards them to its gateway. It records each host's `gateway_url` from its hello, which `resolve` answers carry only for a host enrolled without a tunnel, and routes each `agent_attach` command's result to the sandbox's DO. Revocation needs no relay: a detach changes the attached set nestd sends its gateway, and an epoch bump voids the old bindings. The Access service token in front of the tunnel hostnames lives in BrokerDO, and `resolve` hands it out only for a host with a tunnel ([gateway](../../../sandbox/gateway/)).
- **Desired versions:** three per cell: the brain-host version, the sandbox-host version and the guest image. Setting one starts that kind's [rollout](../../../compute/provisioning/#upgrades): one canary host, its probe, then gentle drains of the old hosts.
- **Fleet channel:** nestd connects here and heartbeats every 5 s, which renews the leases of every sandbox on the host. See [../../../sandbox/fencing/](../../../sandbox/fencing/).
- **Hello reconciliation:**
  - **Sandboxes:** reported sandboxes we don't honor, including any below SandboxDO's current epoch, are fenced; the reported state of honored ones is adopted as evidence. `head` is informational.
  - **Stale incarnations:** an incarnation a host has at an epoch its lease no longer covers (no lease, or the lease is on another host) is destroyed there with one `sandbox_destroy{sandbox, epoch: <old>}`, never repeated, once it is clean (a hello reports it `dirty: false`, or the host sends `incarnation_retired`: its salvage landed, there was nothing to salvage, or SandboxDO refused it for good, and its disk is gone) or 11 min after FleetDO first saw it. The window (`SALVAGE_WINDOW_MS`) bounds how long a dirty incarnation's disk stays on a host that never reports it retired: nestd retries a transiently failing salvage with backoff until it lands, so a host that is partitioned, or whose salvage keeps failing, gives the work up when the destroy arrives. Incarnations come from hello reports, a non-holder's `fenced`, a STONITH fence's success and `incarnation_retired`. One still leased to its host (STONITH pending) waits; one superseded by a newer epoch on the same host is dropped, since nestd retires it itself (salvage, then delete) at that create; a dead host's are dropped.
  - **Agents:** a reported brain AgentDO's record doesn't place on that host is killed there (an orphan). A brain whose `agent_start` completed but that the host no longer reports is marked gone and reported exited at its row's epoch, until AgentDO takes it (the tick retries); only then does the row go. Reported ones keep the reported state.
  - **Cgroup delegation:** a hello with `cgroup_delegation_error` (nestd was configured to keep its VMMs in its unit's cgroup and could not) is logged as an error on every connection.
- **Brain index (`host_agents`):** one row per (agent, host) an `agent_start` went to, with that start's agent epoch (at most one start of an agent is outstanding on a host: AgentDO never re-issues one), until that brain's exit is reported there (`agent_exited` for an epoch at or above the row's, applied only after AgentDO took it, so a redelivered exit carries the same epoch) or its host's loss is acknowledged; an `agent_stop`'s `ok` and a failed `agent_start` drop nothing (the start's own exit does). Only those write it; AgentDO decides where brains run. A brain being stopped on its old host stays listed while it starts on a new one, and an older start's exit never drops a newer start's row. The transitions that prove a host's brains gone hand them back to AgentDO (`brainsLost`, one function): a silent host expired, STONITH confirmed, a host re-enrolled before it ever connected. A row is deleted only once its agent took `onHostLost`; a failed call is retried from the tick, which stays armed while a lost host still has rows. A drained or idle host is never declared dead while a brain is indexed there (it is alive until its exit, or until the host goes silent and is expired). A spot drain asks AgentDO, in the background, to move each brain off (condemned there, started elsewhere once released). `issueKill` stores one kill per (agent, host, epoch), so AgentDO can issue it until it has the id; `killProgress` answers AgentDO's escalation: whether a kill has a result, whether a start at or below the brain's epoch is still indexed there, and whether the host is dead or expired. An exit without an epoch (nestd of the previous release) is passed on with the row's epoch (none for a row stored by the previous release: AgentDO then condemns and proves; such a row never counts as indexed for escalation, and the host's next hello resolves it), and a reconnecting host's missing brains with their row's. An acknowledgement deletes only the row its notice was for (by command id): a newer start's row recorded meanwhile stays. **Proven gone (`lost`):** a host whose lease expired, or whose death was confirmed (EC2 or STONITH, an operator, or it never connected); a host retired as `dead` by scale-down is not, until EC2 confirms its instance gone. Only a lost host's brains are released, and `brainsLost` re-checks it before each notice; a notice AgentDO declines (the host isn't lost any more) keeps its row. A host's hello after its expiry clears `lost`: its brains were proven gone, and a host that once connected can't re-enroll under a new identity. The backfill marked lost only where the previous release had proof (expired, or dead other than by a scale-down retirement EC2 hasn't confirmed). An exit without an epoch for which the host has no row is ignored. A brain follows its own host, never its sandbox.
- **Retiring a drained host** (any role): only with no lease, no brain recorded and no stale incarnation still unsalvaged; one with an instance is terminated (and is lost once EC2 confirms it gone), one enrolled with a token has none to terminate and is reported for an operator's confirm-dead. Without EC2 in the cell, nothing sets `lost` for a retired host but an operator. A drain's notice to each agent is retried by the tick until the agent took it.
- **Wedged hosts:** before any wedge, nestd itself drops its runner connection when a killed brain hasn't exited in 60 s (the runner kills that host's brains, not its sandboxes, and their exits are reported). `hostWedged(host)` (AgentDO's escalation: a host processing no commands for 60 s after a kill, or a brain still indexed 15 minutes after its kill) closes the host's socket and refuses its hellos and heartbeats, so no lease renewal reaches it, and excludes it from every placement (sandboxes, brains, an operator's host) at once; 30 s after its last renewal the tick sends it to STONITH whether or not it holds leases, and its brains are released only once its death is confirmed (EC2, or an operator without it), never on the strength of its own watchdog. Exits that arrived earlier on its still-open socket released their records safely (an exit at an epoch means nothing at or below it runs there). In a cell without EC2 an operator's confirm-dead is required, and the agents on that host wait for it (liveness depends on it there). A lost brain host is replaced on demand: its brains' next starts find no room and launch one. `fleetView` shows each host's `wedged_ms`, `lost` and `brain_epochs`. `killProgress` counts a host as processing commands if any result came from it since the kill was stored, or an older command is still pending there. The blast radius is the whole host: every brain on it restarts, and every sandbox on it is placed again from its head (losing what it hadn't committed).
  - **New nestd process:** a new `instance_id` resets both seq lineages. Unfinished commands then fail retryably, except a `sandbox_create` the host reports running, which completes.
- **Commands:** persisted, delivered in order, exactly one result each.
- **A host's death** (a confirmed loss, STONITH, an idle or drained retirement, a proof re-used before the host connected) answers every command it never did with an error, without the failure handling a live host's error triggers (its sandboxes are reassigned or evicted instead), and resets its reliable channel; an `agent_start` answered so keeps its index row. These answers, and those to a command issued for a dead or unknown host, are FleetDO's own (`answered_by = fleet`): `killProgress` never counts them as the host having run a kill, so a brain on a host whose death isn't proof (an idle or drained retirement) waits for `lost` as before. Its sandboxes are reassigned or evicted; its brains are released only by the brain-index rules (`brainsLost` when the death is proof, an exit, or an AgentDO ack). A command for a dead or unknown host is answered with an error at once, never queued. Confirming a host dead also marks its instance to terminate, so one that still runs is not orphaned. Its row is pruned later ([retention](../../../data/#retention)).
- **Host reports:** the lease is the one authority for who holds a sandbox. A `sandbox_state` reaches SandboxDO only from the live lease's holder at its epoch; anything else is dropped (a stale `fenced` is kept as a stale incarnation). A holder reporting `fenced` (nestd self-fenced when its host lease lapsed) gets the sandbox reassigned at once, this host allowed.
- **Leases:**
  - **One lease, one host:** placement refuses a sandbox that already holds a lease at another epoch, and a lease is never overwritten. A retry at the lease's own epoch (its answer was lost) gets the same host back and sends nothing.
  - **A start never outlives an expiry:** expiring a host fails every `agent_start` it hasn't answered (its index row stays, so the loss reaches AgentDO for that epoch), an answered `agent_start` is never resent when the host comes back, and `issueCommands` refuses an `agent_start` for an expired, dead or unknown host. nestd refuses any start it held across its own lease lapse.
  - **Expiry:** every per-host step of the tick re-reads that host's row (a host that said hello while the previous one's expiry awaited is not expired from the snapshot). Any host silent for 30 s is expired, whatever its role: one holding live leases has them expired and waits for STONITH; one holding none (a brain host, or a sandbox host whose sandboxes all left) is marked `expired` at once, and AgentDO releases the brain record of every brain on it and starts each elsewhere, without STONITH: nothing on it can run twice, its runner killed the brains when its lease lapsed at 20 s, and only a brain record's host may attach its session. Its next `hello` makes it active again; an expired launched host that doesn't come back is retired after its kind's idle grace.
- **STONITH:**
  - **EC2:** terminates the old instance (signed with `aws4fetch`) and waits until it's `shutting-down`/`terminated`.
  - **Without EC2:** waits for the host to reconnect and fence. The fence is re-issued on every hello, every tick and after a failure, until one succeeds.
  - **`stonith_pending` holds** until a fence succeeds (the host is then active again, before its sandboxes are re-placed, so it may take them) or EC2 confirms the instance gone. A hello does not clear it: a host that reconnects while being terminated and dies before its fence result is still polled. Liveness is `last_rx` (heartbeats count in this state too) and the socket.
  - **Operator:** can confirm a host dead.
  - **Reassignment:** an idempotent per-sandbox queue that the alarm retries, so one failure can't strand the others.
- **Restore ABIs:** each host advertises the [restore ABIs](../../../sandbox/state/memory/#restore-abi) it can create and load (in `hello` and `capacity`), and each host release records the ones its hosts will have, so FleetDO knows whether launching a host would help. A memory generation is placed only on a host that loads its ABI; if none with room does and the desired host version wouldn't either, the sandbox boots disk-only.
- **Placement** grants a lease at the epoch of a SandboxDO [claim](../sandbox/#placement), only once every older epoch's lease is gone. It packs: among hosts whose free hugepages and vCPUs fit the sandbox, prefer one with its snapshot warm and a loading restore ABI, then the one with the fewest free hugepages that still fit, then fewest free vCPUs. Packing lets idle hosts empty out and scale to zero; spreading keeps every host partly full. An undersized hugepage pool makes Firecracker fail with SIGBUS, so hugepages are reserved, never overcommitted; paused sandboxes keep theirs. Disk I/O isn't packed; each sandbox's drive is rate-limited instead ([I/O limits](../../../sandbox/state/disk/#io-limits)).
- **Drains** ([modes](../../../compute/autoscaling/)): a draining host gets no new placements, and its resident sandboxes become `evacuating`. **FleetDO terminates a drained host only when, for every resident sandbox:**
  - SandboxDO's head is the host's last committed generation for it (exact ids, through [`isRestoreSource`](../../../sandbox/state/#restore-sources));
  - that head is `ready`, verified when it was committed;
  - the host's pending-upload list is empty. The list is all-or-nothing: an answer the host can't complete is an error, never a short list, because a short list looks the same as a complete one.

  A spot notice doesn't wait for the gate: the instance goes anyway, and whatever didn't commit is recorded as a loss.
- **Base generations:** an index of `(image digest, restore ABI) → generation` for the cell, with a per-digest backoff for failed preparation ([base generations](../../../sandbox/state/memory/#base-generations)). Each is a GC root until its image is retired.
- **Object-store GC:** the cell's sandbox registry, the GC schedule and the roots snapshot. A sandbox host runs the pass ([GC](../../../sandbox/state/object-store/#garbage-collection)). The registry is the authority for which sandboxes exist, and so for the roots: SandboxDO registers in `create`, before anything can be written for the sandbox; `place` registers (and logs an error for) one that somehow wasn't, since a sandbox missing from it would lose its data to GC. A destroyed sandbox's row is marked, and pruned after 30 days.
- **Autoscaling, per kind** ([autoscaling](../../../compute/autoscaling/)): the launch and retirement decisions are pure functions (`scaleUpPlan`, `idleStep`); sandbox hosts launch from the cell's entry, brain hosts from its `brain` section, each kind with its own pending launch, cap and idle grace. A cell without a `brain` section launches no brain host and retires none.
- **Not built:**
  - **The desired versions** per cell, which drive [host upgrades](../../../compute/provisioning/#upgrades).
  - **Command batching:** one frame per `issueCommands` call.
  - **Packing:** built. A host on regular pages (the default: `hugepages_mib_total` 0) takes a sandbox while its reported `memory_mib_free`, less the cell's `sandbox_reserve_mib` (768) for every lease the report doesn't count yet (no state yet, or a first state the host's last capacity report predates: nestd reports state at once but capacity at most every 30 s, so a burst would otherwise see none of its own placements; FleetDO orders the two with a counter in `kv`), still covers one more reserve, and while it is under `max_sandboxes_per_host` when that is set; declared vCPUs and memory are a shape, not a reservation. A host with a hugepage pool keeps the pool rule: the declared size counts against `hugepages_mib_free`, declared vCPUs against `vcpus_free`. Warm snapshot first, then the host with the least room left after this sandbox; an empty host always takes one. The restore-ABI match isn't built.
  - **Drains, the drain gate and base generations.**
