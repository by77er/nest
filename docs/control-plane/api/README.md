# API and surfaces

- **Worker HTTP API,** authenticated by [operator tokens](#operator-tokens), or by an [API client](clients/)'s token: an external system's scoped principal, which sees and acts only on what it created, within the operator's grant. The read-only [dashboard](../dashboard/) is a Worker of its own behind Cloudflare Access.
- **External events** (webhooks, email) are external integrations, not platform routes ([principle 9](../../README.md#principles)): one delivers to an agent through its inbox. Agents schedule their own wakes with `wake_at`.
- **Approvals:** a call the sink gate or a tool rule in `ask` mode holds is listed by `GET /v1/agents/<id>/asks` (`{ask, question, created_ms, approval?: {name, tool}}`, oldest first) and answered by `POST /v1/agents/<id>/asks/<ask>/answer {answer}`; the decision reaches the agent as an `ask_answer` turn. An API client answers its own subtree's. Agent events reach an API client's webhook ([events to the owner](clients/#events-to-the-owner)); the operator has no webhook yet.
- **`nest` CLI on my machine:** `login` (the Access service token, and a binding per sandbox from SandboxDO's `resolve`), `attach` (a terminal: a WebSocket to the sandbox host's [gateway](../../sandbox/gateway/), then vsock), `logs -f`, `port-forward` (TCP over the same path), `diff <a> <b>`. The CLI reaches a sandbox the way a brain does, by hostname and binding. Not built: these commands (the CLI has only `hook`, `mcp` and the in-sandbox commands).
- **Host authentication:**
  - A signed instance identity document (or a one-time enrollment token) is exchanged for a rotating host token. See [../../compute/provisioning/](../../compute/provisioning/).
  - The fleet channel accepts a token up to 24 h past expiry, so a reconnecting host can get a fresh one. The session channel accepts no grace period.
- **Two public routes for MCP OAuth** ([mcp OAuth](../../agents/capabilities/mcp/#oauth)): `GET /v1/oauth/callback`, where an authorization server sends the operator's browser (its single-use state is the proof), and `GET /v1/oauth/client.json`, nest's client ID metadata document. Every other route needs the operator's token but the host routes and a few more public ones (health, host enrollment, blobs, the [caller identity's keys](clients/#caller-identity-for-mcp-servers)), and the owner routes (agents, sandboxes, the client catalog, a client's `self`) take an API client's too ([the list](clients/#routes); `test/routes.test.ts` holds both lists and checks that one against the code).
- **Operator API:** endpoints are listed in `control-plane/README.md`.
  - **Includes:** egress policy layers (`PUT /v1/sandboxes/<id>/policy`), ports and public share links (operator-only), paged transcripts, a sandbox's hands target for a person or a harness (`POST /v1/sandboxes/<id>/resolve`), starting a brain on a named host (`POST /v1/agents/<id>/start {host}`; restarting one on another model is the owner's, [below](#restarting-on-another-model)), and the Access service token for the gateways (`PUT /v1/admin/secrets/access:gateway`).
  - **Taking a credential away:** `DELETE /v1/admin/secrets/<name>` removes an operator's secret ([BrokerDO](../durable-objects/broker/)), and `DELETE /v1/admin/capabilities/<name>/oauth` revokes an mcp capability's OAuth authorization ([mcp OAuth](../../agents/capabilities/mcp/#oauth)). Both take the admin token.
  - **Cells:** must be well-formed names, and must be in `CELLS` when that's set. See [which routes take a cell](#which-routes-take-a-cell).
  - **Agents:** `POST /v1/agents` takes an agent's cell from its sandbox when it has one; a cell that differs from the sandbox's is refused (409).
  - **Creates take an [`Idempotency-Key`](#idempotency-keys).**
  - **Compat (one release):** `POST /v1/sandboxes` and `POST /v1/agents` accept a `workstream` field and ignore it (old clients and scripts send it); the operator's `POST /v1/agents` refuses `overrides.params` with a 400 rather than drop it silently.

## Restarting on another model

**Decided (2026-11-10):** an agent's owner (the operator, or the [API client](clients/) whose subtree it's in) restarts its brain on another model or effort, keeping its conversation: `POST /v1/agents/<id>/start {restart: true, launch: {model?, effort?}}`.
- **What changes:** a `model` or `effort` given replaces the agent's; `null` clears one (the brain then runs on Claude Code's default); one left out stays. Nothing else of the launch changes (tools, system prompt). The answer is the start's (`started`, `waiting` or `none`) with the launch now stored: `launch: {model, effort}`.
- **Checked as a spawn's launch is** (`launchProblem`: plain tokens, never an option), on the whole launch it would store. A refused one stores nothing and leaves the brain as it was. Unknown fields are refused (400), in the body and in `launch`.
- **Only with `restart: true`:** `launch` alone is refused (400), so a stored change never waits silently for some later start.
- **Why an owner may:** no grant rule limits models, and a client can already pick any model by writing a template in its namespace and spawning from it. This is the same choice, for an agent it already owns.
- **The restart is the existing one** ([AgentDO](../durable-objects/agent/)): the launch is stored in the step that records the restart's intent, a live brain is condemned (killed: a turn it is running is cut, and the next brain redoes it as a `recovery` turn from its text), and the next brain starts with the stored launch, resuming the same session (`--resume` with the new `--model` and `--effort`, both [documented Claude Code flags](https://code.claude.com/docs/en/cli-reference)). A caller that wants the turn to finish first sends `when: "idle"` (below).
- **Only between turns, `when: "idle"`** (2026-11-10; only with `restart: true`, else 400): a caller that read the agent as idle can't be sure no turn starts before its restart (a timer, another agent's message). With `when: "idle"`, AgentDO checks in the step that records the restart that no turn runs and none is queued to start. Otherwise it refuses with `409 busy` (retryable; the message names the running or next turn) and stores nothing, the launch change included. The caller asks again later. Without `when`, a restart is as above: it cuts a running turn.
- **Several at once:** each is stored in its own step; the brain that starts has the last stored. A change while a restart waits for the condemned brain's exit joins that restart. An ended agent is refused (409), as any start is.

## Live trace

**Decided (2026-11-02):** `GET /v1/agents/<id>/trace?after=<seq>` is a WebSocket upgrade that streams an agent's turns as they happen. It's an owner route: the operator, or an [API client](clients/) for an agent in its subtree (anything else answers 404, as an unknown agent does). The Worker checks the caller before it forwards the upgrade. A browser can't set `Authorization` on a WebSocket, so an app's own Worker connects with its token and proxies the socket. Code: `control-plane/src/lib/trace.ts`, and the trace sockets in [AgentDO](../durable-objects/agent/#live-trace).
- **Why a WebSocket, not SSE:** AgentDO accepts the socket with the [hibernation API](https://developers.cloudflare.com/durable-objects/best-practices/websockets/), so an idle watched agent costs no duration between events ("Billable Duration (GB-s) charges do not accrue during hibernation"). An SSE stream would keep the request, and the object, alive and billed.
- **Messages** are JSON text frames. An event has `seq` (per agent, from 1, monotonic, durable), `ts_ms`, `turn` (within a turn), `type` and its fields:

  | `type` | Fields | From |
  |---|---|---|
  | `turn_started` | `input_kind` (`user`, `inbox`, `ask_answer`, `recovery`) | the runner |
  | `assistant_text` | `text` | the runner (Claude Code's text blocks) |
  | `tool_call` | `call_id`, `name`, `input` (the input as compact JSON, redacted, bounded) | the runner (each `tool_use` block) |
  | `tool_result` | `call_id`, `is_error`, `summary?` (the result's first 200 characters, redacted) | the runner |
  | `turn_completed` | `stop_reason`, `usage?` (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`) | the runner |
  | `rate_limited` | `retry_after_ms?`, `detail` | the runner |
  | `error` | `code`, `message` | the runner (a failed Claude Code result) |
  | `task_exited` | `task_id`, `status`, `exit_code?` | the runner (a background hands task) |
  | `timer_set`, `timer_fired`, `timer_cancelled` | `name`, and `at_ms` and `note`, `note`, or `by` | AgentDO ([timers](../../agents/capabilities/timers/)) |
  | `state` | `state` (as `GET /v1/agents/<id>` shows it) | AgentDO, at each change |
  | `ask` | `ask`, `question` | AgentDO (an approval or a tool rule in `ask` mode) |
  | `ask_answered` | `ask` | AgentDO |
  | `ended` | `reason` | AgentDO, once the agent's end is done; the socket then closes (1000) |

  Four messages have no `seq`: `{type: "gap", from, to, before?}` (below); `{type: "history", before}`, where the [trace history](#trace-history) takes over; `{type: "live"}`, once the backlog is sent (what follows happens as the client watches, so a viewer can animate only that); and `ended` sent again to a client that connects after the end having already read it. A client ignores a `type` it doesn't know.
- **Order:** the order AgentDO recorded them, one seq each. A runner event comes before the state change it causes (`turn_completed`, then `state: idle`). A `state: working` comes when the turn is sent to the brain, before its `turn_started`.
- **Not streamed:** the runner's `state_changed` (it streams as `state`), `escalation` (it streams as its `ask`), `usage`, `capabilities` and `inbox_delivered`, and everything that isn't an event (session bytes, hands calls' output). The full transcript is `GET /v1/agents/<id>/transcript`.
- **Resume:** AgentDO keeps the newest 1,000 events of the last 24 h. A client connects with `after` (the last `seq` it has; omitted means 0) and gets the events after it, then `live`, then live events. If events after `after` are gone from the ring, it first gets `{type: "gap", from, to, before}` (inclusive seqs; `before`, the [trace history](#trace-history) cursor that covers them). A client whose backlog starts at the ring's beginning (or before it) also gets `{type: "history", before}` when the agent has a transcript, before the backlog. An `after` beyond the newest gets nothing until new events.
- **Bounds and redaction:** the live path has no list of secrets (the runner redacts its own secret, the setup token, from session bytes only, and the model never sees it). Every string field is redacted, then cut: tool inputs, results, questions and messages to 4 KiB, assistant text to 16 KiB (UTF-8, marked `…` when cut). Redaction replaces the values of credential-named keys in a tool's input (`token`, `secret`, `password`, `authorization`, `api_key`, `credential`, `cookie`, `private_key`, …) and credential shapes in any string (nest client tokens and webhook secrets, `sk-ant-…`, GitHub and Slack tokens, AWS access key ids, PEM private keys, `Bearer`/`Basic` values) with `[redacted]`. A secret of another shape in a tool's input passes, bounded, as it does in the stored transcript.
- **Keepalive:** send the text `ping` (not JSON) at least every 30 s; the runtime answers `pong` without waking AgentDO ([`setWebSocketAutoResponse`](https://developers.cloudflare.com/durable-objects/api/state/)). AgentDO never pings.
- **Closes:** `1000` when the agent ended; `4008` when a newer trace socket took its place (8 per agent at most, the oldest goes); `1011` when a send to it failed. A client reconnects with `after=<last seq>` and a backoff, except after `ended`.
- **Answers to the upgrade:** `101`; `426` without `Upgrade: websocket`; `400` for an `after` that isn't a non-negative integer; `401`/`404` as for any owner route; `503` (`internal`, `retryable: true`) while AgentDO still runs a release without the trace, in the minutes after a deploy ([rollout](../../../dev/deploy.md)).

## Trace history

**Decided (2026-11-02):** `GET /v1/agents/<id>/trace/history?before=<cursor>&limit=<n>` gives the trace's older events, which the ring no longer holds or never held (an agent that ran before the live trace, or more than 1,000 events or 24 h ago). Same owner auth as the trace (the operator, or a client on its subtree; anything else 404). Code: `control-plane/src/lib/trace-history.ts`, `AgentDO.traceHistory`.
- **What it reads:** the committed transcript (Claude Code's session JSONL, the base in R2 that `--resume` and `GET …/transcript` read), normalized into the live trace's shape: a prompt gives `turn_started` (`input_kind: "unknown"`: the transcript doesn't say which of nest's inputs it was), an assistant message its `assistant_text` and `tool_call`s, a user message of tool results its `tool_result`s (the first 200 characters, as the runner sends live), and each turn ends with a `turn_completed` (`stop_reason` the last that ended a message there, `end_turn` or `max_tokens`; a `tool_use` stop ends no turn, so a turn cut off after one reads `unknown`; no `usage`). Only `user` and `assistant` lines are read: every other type Claude Code writes (`attachment`, `api-request`, `api-request-blob`, `api-request-shape`, `atis-latch`, `last-prompt`, `queue-operation`, `system`, `cost-state`, seen in a worker's transcript, 2026-11-02) gives nothing, which matters because request lines can hold whole request bodies. Subagent messages (`isSidechain: true`) give nothing: the parent's `Agent` call and its result stand for the subagent's work. Meta and compaction entries and thinking give nothing either. (Unverified: whether the live trace shows a subagent's own calls. The runner doesn't read stream-json's `parent_tool_use_id`, so if Claude Code streams subagent messages they reach the ring unmarked, and history and the ring would differ there.) The same redaction and bounds as the live path (each body goes through the live path's own normalizer). There was no transcript normalizer before this: [sessions](../../agents/sessions/) says "normalized on read", and this is the first reader built.
- **The shape:** `{events: [...], next_before: <cursor> | null}`, events oldest first. An event is the live shape without `seq` and `turn` (nest's turn ids aren't in the transcript), plus `entry`, its transcript line's byte offset in the base. `next_before` pages further back; `null` means the transcript's start. A cursor is opaque; one from a base the transcript has since left (it was rewritten) answers `{events: [], next_before, reset: true}`: start over from that cursor.
- **Pages:** at most `limit` events (default 200, at most 500), of whole entries, and extended back to the prompt of the oldest turn so a page holds whole turns, within about 2 MiB of transcript read from R2; a page that reaches that budget ends early with a cursor. Without `before`, the first page starts at the seam.
- **The seam, where history and the ring meet** (decided so a viewer stitches them with no event twice and none missing):
  - The seam is the ring's oldest event of a kind the transcript has too (`turn_started`, `assistant_text`, `tool_call`, `tool_result`, `turn_completed`), or now when the ring holds none. History holds the transcript's entries written before the seam's `ts_ms`; the ring holds the seam and everything after.
  - **At a turn's start** (the usual seam: an agent's first ring event of a turn, or a ring that begins at one), it's exact: the runner stamps `turn_started` before it writes the prompt to Claude Code, which stamps the prompt's entry after, and every entry of the turn before it was written before its `turn_completed`, so before the next turn was sent. Both stamps are the brain host's clock.
  - **Within a turn** (the ring pruned mid-turn, or a turn running when the live trace began): an entry is stamped when Claude Code makes it, at or a little before the runner reads it, so history may hold the seam's own events too. History leaves out any tool call or result whose id the ring has, and any assistant text equal to one in the ring within 5 s of the seam. The last turn before such a seam has no `turn_completed` in history (the ring goes on with it).
  - The viewer shows history, then the ring's backlog, then live events. A client that already holds ring events and got a `gap` drops what it holds and backfills from the gap's cursor (history covers everything before the seam), rather than merging by time.
- **Reads only:** an RPC to AgentDO and R2 reads. It never starts a brain, never reaches the sandbox, and never changes the ring. Bytes not yet flushed to R2 (at most 30 s idle, or until the turn's end) aren't in it; by then they are after the seam.
- **Answers:** `400` for a `before` that isn't a cursor or a `limit` that isn't an integer; `401`/`404` as for any owner route; `503` (`internal`, `retryable: true`) while AgentDO still runs a release without it.

## Which routes take a cell

**Decided (2026-11-02):** only a route about one cell's FleetDO reads `?cell=`. It is checked when that route reads it (default `local`), never by the router for every route (`Ctx.cell` in `control-plane/src/index.ts`), so in a deployment whose `CELLS` doesn't name `local` an external app needs no cell on the others.
- **About a cell** (`?cell=`): the fleet, hosts, images, lifetimes, tunnels, GC and the root certificate (`/v1/admin/…`), and the operator's `GET /v1/agents` and `GET /v1/sandboxes` without `?client=` (FleetDO's registry). A client's listing, and the operator's with `?client=`, take `?cell=` only as a filter.
- **In the body:** `POST /v1/agents` and `POST /v1/sandboxes` take `cell` (an agent with a sandbox takes the sandbox's).
- **No cell:** everything reached by an agent's or sandbox's id (its DO's record knows its cell), the catalog (one CatalogDO for every cell), clients and `/v1/clients/self/…`, and secrets (one BrokerDO). These accept a `?cell=` and ignore it, so callers that send one keep working.

## Idempotency keys

**Decided (2026-11-02):** `POST /v1/agents` and `POST /v1/sandboxes` take an `Idempotency-Key` header, so a create whose answer was lost can be sent again without making a second agent or sandbox. Any caller: the operator or an API client (an agent's `agent_spawn` doesn't come here: its ids already derive from its call key). Code: `control-plane/src/lib/idempotency.ts`, `createOnce` in `src/index.ts`.
- **The key:** 1-128 characters of letters, digits and `_ . : ~ + / = -` (a UUID, a ULID, base64url); another is 400. Without one, each create is its own, as before.
- **Scope:** per principal. A client's keys are in its own [ClientDO](../durable-objects/client/), the operator's in ClientDO's `operator` instance, so one principal's key never meets another's. One key binds one request: the route and its parsed body (defaults applied, keys sorted, SHA-256).
- **Retention:** 24 h from its first use (`IDEMPOTENCY_TTL_MS`), then the key is free again. Stripe keeps keys the same 24 h ([idempotent requests](https://docs.stripe.com/api/idempotent_requests)). Expired keys are deleted at the next claim, and in a client's hourly prune.
- **Answers:**
  - The same key and body again: the same object, with the first answer's status (an unplaced sandbox's 202 stays 202), its current view, and `Idempotent-Replayed: true`. An agent isn't started again: `started` is `null`.
  - The same key with another body or route: 409 `conflict`, not retryable; nothing is made.
  - The same key while its first request is still being handled (for up to 60 s, `IDEMPOTENCY_LEASE_MS`): 409 `conflict`, retryable.
- **How a second object is never made:** the id is fixed when the key is first claimed, in one synchronous step of the principal's ClientDO, and every step of a create is idempotent by id (`ClientDO.admit`, `SandboxDO.create`, `AgentDO.create`). A request that died mid-create leaves its claim, which the next request with the key takes over once the lease has passed, under the same id: it finds what was made and finishes it. A request that failed before it made anything (a 400, a 403 outside the grant) frees a fresh key; one that failed later leaves the key bound, and the next request with it takes over at once.
- **One pure step** (2026-11-09): a key reads as `none`, `held` (a request holds it, within its lease), `open` (bound, nobody holds it) or `done` (`keyView`), and every change of its row goes through `keyStep`. A held key is never claimed; an open one is taken over under its id; the first `finish` decides, also from a request that outlived its lease, but only for the object the key is bound to now (`finish` names the id it made: one from a request that held the key before its 24 h passed can't answer for a fresh claim's row); only the holder's abandon counts and it can't undo an answer.
  - **A key past its 24 h is free even before it is pruned:** a claim that finds its row expired deletes it and starts anew (a claim prunes at most 100 expired keys, so one could outlive its TTL as a row and answer a replay or a 409).
- **The validation runs inside the claim:** a replay answers even if the template or grant changed since.

## Operator tokens

The operator API takes scoped bearer tokens. Built: one `ADMIN_TOKEN` with every scope; the scopes, hashing and the revocation counter below aren't built.

| Scope | Allows |
|---|---|
| `observe` | Reading state, logs, transcripts and effective policy |
| `approve` | `observe`, plus answering questions and approvals, and temporary egress grants |
| `admin` | Everything else: policy layers, secrets, enrollment tokens, share links, terminals and port-forwards, confirm-dead, launch records |

- **Format:** a recognisable prefix per scope (`nest_obs_`, `nest_apr_`, `nest_adm_`) plus 256 random bits, so a leaked token is easy to spot in logs and for secret scanners.
- **Stored only as SHA-256 hashes** (a Worker secret) and compared in constant time. A fast hash is enough because the tokens are random, not passwords. Revoking one removes its hash.
- **Header only:** `Authorization: Bearer`, never a URL or query string, because Cloudflare logs request URLs ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)). The CLI sends the header on WebSocket upgrades too.

## Revocation counter

**One counter, `REVOCATION_COUNTER` (a Worker secret), is signed into every share link, terminal session and host token.** Anything minted under an older value is refused. Bumping it is the panic button:
- `wrangler secret put` deploys a new version at once ([secrets](https://developers.cloudflare.com/workers/configuration/secrets/)), which restarts every DO and drops every socket ([upgrades](../#upgrades)), so open terminals and host channels close and can't come back.
- An instance enrolls only once, so its host can't get a new token: leases expire and sandboxes restore on fresh hosts ([FleetDO](../durable-objects/fleet/)).
- It takes my Cloudflare credentials, not an operator token, so it works even when an `admin` token has leaked.
