# Data placement

**Each piece of data lives next to its main reader.**

| Store | Contents | Main reader | Credentials |
|---|---|---|---|
| DO SQLite | Heads, epochs, agent epochs, leases and placement markers, segment and generation indexes (with pins), current state, grants, tunnel ids per sandbox host (FleetDO); designed: loss records, the base-generation index and the three desired versions per cell (FleetDO) | Control plane | — |
| R2 | Session segments (native Claude Code session files, `sessions/`), bodies under `channels/` that no code reads (an operator delete, [deploy](../../dev/deploy.md#rollout-rules)), audit logs (egress under `audit/<host>/`, credential issuance under `audit/broker/`); designed: UI artifacts (diffs, screenshots), exported journals | DOs, UI, agents, me | The Worker's and DOs' bindings only |
| S3, per cell (one versioned Standard bucket; Express One Zone for hot data is designed) | Disk chunks, memory pages, generation manifests (base generations designed) | Hosts | Instance role |

- **Cross-cloud traffic is small text:** transcripts from brain hosts to Cloudflare, session files back from R2 when a brain starts on a new host, and hands frames between a brain and its sandbox's gateway over the tunnel. No bulk data crosses.
- **Bindings are verified, not stored.** SandboxDO has them signed with the cell's binding key, which BrokerDO holds; FleetDO pushes the public keys to each sandbox host's gateway; nothing records an issued binding. See [../sandbox/gateway/](../sandbox/gateway/).
- **R2 is the one global store for the control plane.** Each cell has its own S3-compatible store. See [../sandbox/state/object-store/](../sandbox/state/object-store/).

## Retention

Every DO table that would otherwise only grow has one retention rule, a named constant next to the code that applies it. A row something still depends on is never dropped.

| DO | Table | Kept | Why |
|---|---|---|---|
| FleetDO | `commands` | 24 h after its result (`COMMAND_RETENTION_MS`); one whose result's follow-ups are still owed stays until they run. A host's death answers what it never did, with an error and no failure handling; a command for a dead or unknown host is answered so at once and never queued. | Results are read back right after they arrive; a dead host never answers. |
| FleetDO | `hosts` (with its `commands`, reliable channel and `tunnels_created` rows) | 7 days after it died (`DEAD_HOST_RETENTION_MS`), and only once its death is proof (`lost`: lease expired or death confirmed), its tunnel and record are deleted (the row's ids are null), and no lease, stale incarnation, reassignment, eviction or brain-index row (`host_agents`) names it. | The tunnel sweep retries deletes from the row; AgentDO asks for a brain's host's status and kill progress until it released the brain; operators look at recent deaths. |
| FleetDO | `host_agents` (the brain index) | Never pruned: a row goes only when AgentDO took the brain's exit or its host's loss for it ([fleet](../control-plane/durable-objects/fleet/)). | The one-brain rule depends on it. |
| FleetDO | `leases`, `reassignments` (one row per lost lease), `evictions` | Bounded by live entities: one lease per placed sandbox, deleted on release, eviction or reassignment; queue rows deleted once SandboxDO took them (retried from the tick). | Each is work in flight. |
| FleetDO, AgentDO | `rel_out`, `rel_state` (reliable channels) | `rel_out` until acked (reset when the peer restarts or dies); `rel_state` one row per channel, dropped with a pruned host. | Resend after a reconnect. |
| AgentDO, ClientDO, FleetDO, McpConnectorDO, SandboxDO | `deadlines` | One row per armed deadline, deleted when it runs. | Multiplexes the one alarm. |
| FleetDO, SandboxDO, AgentDO | `kv` | A fixed set of keys per object (AgentDO: `info` (the record), `read_tainted`, `tools_listed`, `mcp_changed_ms`, `trace_sockets`, `registry`, `turn_text`; FleetDO: the zone id per zone, the mark counter, the root CA and a development root, the last prune, a GC request, when retention was switched on, a host's lineage-reset capture (`orphaned_commands:<host>`) until it is dealt with, per host kind an in-flight launch, a no-room backoff and the enrollment breakers, and one key for the breakers' basis; SandboxDO: `info` (the record), `ws_layer` (the operator layer), placement state (`placement_refused`, `placement_wait`, `failed_since`, `create_failure`), `client_reported`, `retention_report`, the turn-end checkpoint's (`turn_checkpoint_inflight`, `turn_checkpoint_ms`), `agent_repos`, an attached agent's push allowlist, and `agent_read_repos`, its read-only repos, each removed at detach; `read_token`, set once a read-only token was asked for; `client_inject` and `github_push`, an API client's sandbox's own bindings and push-token opt-ins from its create; `agent_inject` and `agent_github_push`, each attached agent's, removed at detach; `client_egress`, `client_env` and `client_egress_hosts`, its client layer's egress rules and env and its client's grant's `egress_hosts` as last read, with the grant revision they were read at; `agent_egress` and `agent_env`, each attached agent's, removed at detach). | Bounded by construction. |
| AgentDO | the whole object (`kv.info`, every table below, and its R2 session segments `sessions/<agent>/`) | An agent that [ended](../agents/#lifetimes): 30 days after its end (`AGENT_RECORD_RETENTION_MS`), once the end's steps are done and no brain record is left; segments first, then `deleteAll`. An agent that never ends (the operator's, stopped or not) is kept. | Its owner and the operator read its transcript and events for a while; nothing else needs it once it can't run. |
| AgentDO | `grants` ([transcript grants](../agents/tools/#built-transcript-grants-2026-11-06)) | One row per grant conferred at its creation, at most 16, fixed; kept with the agent. | What it may read beyond itself and what it owns; the agents it conferred grants on check them through it. |

| AgentDO | `children` (the agents it spawned) | One row per spawn, kept with the agent (an index of each child's `owner`; `ended` set once the child's end is done). Bounded by the live-children cap and the agent's life. | Its end ends them; the cap counts the live ones. |
| CatalogDO | `capabilities`, `templates`, `kv` | Keyed by name: bounded by the entries an operator writes (`kv` holds only the seeded flag and the seed version). | They are the catalog. |

A checkpoint's memory no longer a restore source is marked `mem_unrooted_ms`. With `SANDBOX_RETENTION` at `off` (an emergency stop) nothing more is marked. | A ready generation is a GC root (its memory until unrooted); a `deleting` one never is. |

FleetDO prunes at most once an hour, from any alarm: the tick while a host is live, the daily tunnel sweep, and its own daily `prune` deadline (armed on every start, so a quiet cell without tunnels still prunes). A dead host left at `lost` = 0 (an idle or drained retirement whose termination EC2 never confirmed, e.g. a cell without EC2 access) is never pruned, nor are the kill commands FleetDO answered for a host at `lost` = 0 (dead or alive): its death isn't proof (A6), and AgentDO reads a missing kill command as processed. FleetDO's other answers go after their retention. Generations (and so GC roots) are thinned by SandboxDO's own `retention` deadline ([state](../sandbox/state/#retention)) unless `SANDBOX_RETENTION` is `off`.

## Enums

The rule covers columns; closed sets inside a stored JSON body are parsed with their zod schema on read instead (CatalogDO skips and logs a row that fails). Every status, state, kind and type column (FleetDO's `hosts.status`, `role` and `tunnel_state`, `leases.state`, `commands.type`, `purpose` and `answered_by`, `launched.role` and `reason`, `enroll_tokens.role`; SandboxDO's record `state` (a field of its `kv` `info`); AgentDO's `turns`, `tool_calls`, `asks`, `approvals`, `brokered_journal` and `mcp_forwards` status, and `approvals.kind` (null read as `sink`); ClientDO's `members.state` and `idempotency_keys.state`; BrokerDO's `oauth_grants.status`; written through its union but never read back as a value: AgentDO's `inbox.status`) has a closed TypeScript union, shared with the wire types where one exists (`SandboxState`, `TunnelState`, `HostRole`, `CommandBody["type"]`); writes go through it, and every read is checked (`control-plane/src/lib/stored.ts`): a value outside the union is logged as an error and returned as read, so one bad row cannot stop a DO. There are no SQLite `CHECK` constraints on enum columns: SQLite can add one only by rebuilding the table, which on live DO data is a risky migration for a guard the types already give. A column whose null meant a value (`hosts.tunnel_state`, null for `none`) is written explicitly (`none` at enrollment). A renamed member goes expand/contract over two releases: the three `role` columns are read under both names and still written as `burst` and `controller`, and the next release rewrites them to `sandbox` and `brain` ([deploy](../../dev/deploy.md#host-role-names-expandcontract)). The admin views (`GET /v1/admin/fleet`, `/v1/admin/images`, `/v1/admin/lifetimes`) are typed by the contract `protocol/admin/view.ts`, which imports nothing, so the dashboard checks its client against it with type-only imports and never imports the control plane; the control plane asserts at compile time that its enums equal the protocol's. Flags (`hosts.lost`, `brain_epochs`, `host_agents.gone`, `drain_told`) are 0/1 integers; AgentDO's brain record phases live in its JSON state, not in columns.
