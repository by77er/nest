# Data placement

**Each piece of data lives next to its main reader.**

| Store | Contents | Main reader | Credentials |
|---|---|---|---|
| DO SQLite | Heads, epochs, agent epochs, leases and placement claims, segment and generation indexes (with pins and loss records), the base-generation index, current state, grants, tunnel ids per sandbox host and the three desired versions per cell (FleetDO) | Control plane | — |
| R2 | Session segments (native Claude Code session files), bodies under `channels/` that no code reads (an operator delete, [deploy](../../dev/deploy.md#rollout-rules)), audit logs (egress, credential issuance), UI artifacts (diffs, screenshots), exported journals | DOs, UI, agents, me | DO bindings only |
| S3, per cell (Express One Zone for hot data) | Disk chunks, memory pages, generation manifests, including base generations | Hosts | Instance role |

- **Cross-cloud traffic is small text:** transcripts from brain hosts to Cloudflare, session files back from R2 when a brain starts on a new host, and hands frames between a brain and its sandbox's gateway over the tunnel. No bulk data crosses.
- **Bindings are verified, not stored.** SandboxDO has them signed with the cell's binding key, which BrokerDO holds; FleetDO pushes the public keys to each sandbox host's gateway; nothing records an issued binding. See [../sandbox/gateway/](../sandbox/gateway/).
- **R2 is the one global store for the control plane.** Each cell has its own S3-compatible store. See [../sandbox/state/object-store/](../sandbox/state/object-store/).

## Retention

Every DO table that would otherwise only grow has one retention rule, a named constant next to the code that applies it. A row something still depends on is never dropped.

| DO | Table | Kept | Why |
|---|---|---|---|
| FleetDO | `commands` | 24 h after its result (`COMMAND_RETENTION_MS`). A host's death answers what it never did, with an error and no failure handling; a command for a dead or unknown host is answered so at once and never queued. | Results are read back right after they arrive; a dead host never answers. |
| FleetDO | `hosts` (with its `commands`, reliable channel and `tunnels_created` rows) | 7 days after it died (`DEAD_HOST_RETENTION_MS`), and only once its death is proof (`lost`: lease expired or death confirmed), its tunnel and record are deleted (the row's ids are null), and no lease, stale incarnation, reassignment, eviction or brain-index row (`host_agents`) names it. | The tunnel sweep retries deletes from the row; AgentDO asks for a brain's host's status and kill progress until it released the brain; operators look at recent deaths. |
| FleetDO | `host_agents` (the brain index) | Never pruned: a row goes only when AgentDO took the brain's exit or its host's loss for it ([fleet](../control-plane/durable-objects/fleet/)). | The one-brain rule depends on it. |
| FleetDO | `leases`, `reassignments` (one row per lost lease), `evictions` | Bounded by live entities: one lease per placed sandbox, deleted on release, eviction or reassignment; queue rows deleted once SandboxDO took them (retried from the tick). | Each is work in flight. |
| FleetDO, AgentDO | `rel_out`, `rel_state` (reliable channels) | `rel_out` until acked (reset when the peer restarts or dies); `rel_state` one row per channel, dropped with a pruned host. | Resend after a reconnect. |
| Every DO | `deadlines` | One row per armed deadline, deleted when it runs. | Multiplexes the one alarm. |
| FleetDO, SandboxDO, AgentDO | `kv` | A fixed set of keys per object (FleetDO: the zone id per zone, the cell, the mark counter, the root CA, the last prune, a GC request; SandboxDO: `agent_repos`, an attached agent's push allowlist, and `agent_read_repos`, its read-only repos, each removed at detach; `read_token`, set once a read-only token was asked for; `client_inject` and `github_push`, an API client's sandbox's own bindings and push-token opt-ins from its create; `agent_inject` and `agent_github_push`, each attached agent's, removed at detach; `client_egress`, `client_env` and `client_egress_hosts`, its client layer's egress rules and env and its client's grant's `egress_hosts` as last read, with the grant revision they were read at; `agent_egress` and `agent_env`, each attached agent's, removed at detach). | Bounded by construction. |
| AgentDO | the whole object (`kv.info`, every table below, and its R2 session segments `sessions/<agent>/`) | An agent that [ended](../agents/#lifetimes): 30 days after its end (`AGENT_RECORD_RETENTION_MS`), once the end's steps are done and no brain record is left; segments first, then `deleteAll`. An agent that never ends (the operator's, stopped or not) is kept. | Its owner and the operator read its transcript and events for a while; nothing else needs it once it can't run. |
| AgentDO | `grants` ([transcript grants](../agents/tools/#built-transcript-grants-2026-11-06)) | One row per grant conferred at its creation, at most 16, fixed; kept with the agent. | What it may read beyond itself and what it owns; the agents it conferred grants on check them through it. |
| AgentDO | `timers` ([timers](../agents/capabilities/timers/)) | One row per live timer, at most 32; deleted when it fires, is cancelled, or the agent ends. | The agent's wake-ups. |
| AgentDO | `children` (the agents it spawned) | One row per spawn, kept with the agent (an index of each child's `owner`; `ended` set once the child's end is done). Bounded by the live-children cap and the agent's life. | Its end ends them; the cap counts the live ones. |
| CatalogDO | `capabilities`, `templates`, `kv` | Keyed by name: bounded by the entries an operator writes (`kv` holds only the seeded flag and the seed version). | They are the catalog. |
| AgentDO, SandboxDO | `channel_subs`, `chan_wakes`, `chan_out` | Unread; dropped in a later release under the expand-only rule. | Nothing reads them. |
| BrokerDO | `secrets` | Keyed by name: bounded by the names an operator writes; an expired value stays (refused when resolved) until overwritten or deleted. | An operator sees what to renew. |
| BrokerDO | `oauth_grants`, `oauth_flows`, `oauth_clients` ([mcp OAuth](../agents/capabilities/mcp/#oauth)) | `oauth_grants` one row per token record (an authorization replaces it); `oauth_flows` until used, or expired (10 min) and swept at the next start; `oauth_clients` one per authorization server and redirect URI. | The tokens nest uses; a started authorization's verifier; a registration reused across capabilities. |
| BrokerDO | `injections`, and the secrets `inject:<binding>:<sandbox>` they name ([injection minting](../control-plane/durable-objects/broker/#injection-minting)) | One row per (sandbox, binding) with a minted token, overwritten by the next mint; deleted when nothing is mintable for it, when the sandbox is destroyed, and (the secret) once expired, at the next mint. | The token a push's reference resolves to, and what it was minted for, so a push with the same allowlist reuses it. |
| BrokerDO | `client_secrets`, and the secrets `client-secret:<cli>:<name>` they describe ([secrets](../control-plane/api/clients/#secrets)) | One row per secret an API client stores, at most its grant's `secrets.max_count`, until it deletes it or the client is deleted. | The client's credentials, injected into its sandboxes' requests; their metadata for its listing. |
| BrokerDO | `github_app_identity` ([BrokerDO](../control-plane/durable-objects/broker/)) | One row per configured GitHub App (`app_id` as its credentials name it): its numeric id and slug, until `expires_ms` (a day; 10 minutes when GitHub didn't answer), overwritten at the next lookup. | The App's identity API clients are shown. |
| BrokerDO | `identity_keys` ([caller identity keys](../control-plane/durable-objects/broker/#caller-identity-keys)) | One row per key: the signer, the next one (from a day before it signs) and keys retired less than a day ago; an older one is deleted at the next sign or JWKS read. About two rows. | The private JWK that signs `Nest-Identity`, and the public one the JWKS lists. |
| BrokerDO | `github_tokens`, `github_app_installations`, `github_installations` | Tokens: one row per (App, repo, permissions) a brokered action minted for, and per (App, client, repo, permissions) an API client did, overwritten by the next mint; every expired row is deleted at each mint, and the rows of an installation found stale at once. Installations: one row per (App, repo) looked up, refreshed after a day or dropped when a mint with it is refused as stale. `github_installations` (by repo alone) is the previous release's, still written for a rollback, never read; dropped next release. | The token is reused for 50 minutes; the installation saves a lookup per mint. |
| FleetDO | `tunnels_created` | With its host's row; without one, until a sweep whose two listings both succeeded and were complete shows neither the tunnel nor the record, past the hour's grace. A listing stops at 10 pages of 100 (`lib/cloudflare.ts`) and then says it is incomplete, so a large account only delays forgetting. | It is what the sweep may delete: forgotten only once nothing is left to delete. |
| FleetDO | `launched` | 7 days after EC2 confirmed it gone (`LAUNCH_RETENTION_MS`); never before. Confirming a host dead marks its instance to terminate, so every launched instance ends. | The record is what terminates the instance and confirms it gone. |
| FleetDO | `stale_incarnations` | 24 h after its `sandbox_destroy` was issued (`STALE_INCARNATION_RETENTION_MS`). | The destroy is sent once. |
| FleetDO | `enroll_tokens` | 7 days after use (`ENROLL_TOKEN_RETENTION_MS`). An unused token stays until used. | A used token can't be used again. |
| FleetDO | `gc_runs` | 30 days after it finished (`GC_RUN_RETENTION_MS`); the latest run, the latest proven run (so the next run isn't dry again) and an unfinished run always. | GC history for the operator. |
| FleetDO | `sandboxes` | Live rows always; a destroyed one 30 days (`DESTROYED_SANDBOX_RETENTION_MS`). `lifetime_ms`: when its SandboxDO confirmed its lifetime check is armed (the backfill's mark). | Its generations stopped being GC roots when it was destroyed. |
| FleetDO | `agent_registry` | One row per agent of the cell until its reap removes it (30 days after its end, `AGENT_RECORD_RETENTION_MS`); `ended_ms` once its end is done. A row the lifetimes view finds gone is dropped then. `client` and `labels` (with `sandboxes`' columns of the same names) are copied from the record at registration; null before. | The lifetimes view's agent pages; the operator's `GET /v1/agents` and `GET /v1/sandboxes`. |
| SandboxDO | the sandbox itself | Destroyed once [dormant](../control-plane/durable-objects/sandbox/#lifetime) (no agent attached, no VM up) for its idle TTL: its own, else the cell default (1 day). Its DO rows stay (a destroyed record is small and answers late reports); its S3 data goes with GC. | A sandbox nobody uses would otherwise hold its generations as GC roots for ever. |
| SandboxDO | `commits` (idempotency records) | A rejected request's record 7 days (`COMMIT_RECORD_RETENTION_MS`); a committed one while its generation's row exists (a `deleting` row's too, until it is pruned). Pruned from an hourly deadline, never on the commit path, through the indexed `generation_id`. | nestd asks again with an unanswered request's id before its next commit, possibly days later: a committed request finds its record while its generation is kept; any other meets the compare-and-set again, as a new request would. |
| SandboxDO | `epochs` (which host held which epoch) | The sandbox's life. `info().history` is read from it, never stored. | Salvage from any older epoch is authorized against it; one small row per placement. |
| AgentDO | `tool_calls`, `asks`, `approvals`, `turns`, `inbox`, `mcp_forwards`, `brokered_journal` | Finished rows (a turn `done`, `interrupted` or `dropped`) 7 days after they settled (a journal row still `sending` 7 days after its first attempt is given up on as `unknown`, then kept 7 more); a turn left `active` that isn't the agent's current one, and a message mirrored to a turn no longer active, are settled at 7 days and then go; a queued turn stays until run or dropped; a call still unfinished at 7 days is deleted like a finished one, while an open ask and its pending approval stay until answered; `events` the latest 500; `seg_buffer` until its bytes are acked. | Bounded history. The journal is the operator's record of brokered actions ([brokered](../agents/capabilities/brokered/#journal)). |
| AgentDO | `mcp_servers`, `mcp_forwards` ([mcp capabilities](../agents/capabilities/mcp/#data)) | `mcp_servers` one row per mcp capability of its spec; `mcp_forwards` 7 days (one still unsettled then is settled as unknown and goes). | A server's session and its copy of the shared tool list; each forwarded call's state and outcome, so a call key is forwarded once and a new epoch waits for an older one's forwards. |
| ClientDO | `kv` (the record), `members` ([ClientDO](../control-plane/durable-objects/client/)) | The record until the client is deleted; `members` one row per agent and sandbox of its subtree while it lives, an ended one 7 days. The `directory` instance's `names`: one row per client, with its phase (`reserved`, `live`, `deleted`) and since when; a deleted client's row stays 15 minutes as a tombstone, a reservation never confirmed 2 minutes. | The grant's maximums count the live rows; the client lists them. |
| ClientDO | `outbox`, `kv` (`webhook`, `delivery`) ([events](../control-plane/api/clients/#events-to-the-owner)) | `outbox` until delivered, at most 10,000 rows (the oldest dropped and counted). | The client's webhook. |
| ClientDO | `idempotency_keys` ([idempotency keys](../control-plane/api/#idempotency-keys)) | One row per key a principal sent with a create (a client's in its instance, the operator's in `operator`), 24 h from its first use, deleted at a later claim or a client's hourly prune. | A create sent again answers the object it made. |
| AgentDO, SandboxDO | `client_events` | Until ClientDO takes them (seconds, unless ClientDO is unavailable). | The hand-off to ClientDO. |
| McpConnectorDO | `kv`, `subscribers`, `leases`, `admits` ([McpConnectorDO](../control-plane/durable-objects/mcp-connector/)) | `kv` a fixed set of keys; `subscribers` until the agent says it no longer wants notices or hasn't answered for 24 h; `leases` until released or expired (4 call timeouts); `admits` one minute. | One list per server and credential; admission across agents. |
| AgentDO | `segments` (the transcript's R2 segment index) | The agent's life; rows of a superseded base aren't dropped yet (a gap). | The transcript is rebuilt from them. |
| SandboxDO | `grants` | Until each expires (the `grants` deadline deletes it). | Bounded by live grants. |
| SandboxDO | `generations` | Ready rows as [generation retention](../sandbox/state/#retention) keeps them; a row it drops is marked `deleting` (`state`, `deleting_ms`) and a main-chain one pruned a week later; an orphan's row never is (its commit record must answer a late salvage). A checkpoint's memory no longer a restore source is marked `mem_unrooted_ms`. With `SANDBOX_RETENTION` at `off` (an emergency stop) nothing more is marked. | A ready generation is a GC root (its memory until unrooted); a `deleting` one never is. |

FleetDO prunes at most once an hour, from any alarm: the tick while a host is live, the daily tunnel sweep, and its own daily `prune` deadline (armed on every start, so a quiet cell without tunnels still prunes). A dead host left at `lost` = 0 (an idle or drained retirement whose termination EC2 never confirmed, e.g. a cell without EC2 access) is never pruned, nor are the kill commands FleetDO answered for a host at `lost` = 0 (dead or alive): its death isn't proof (A6), and AgentDO reads a missing kill command as processed. FleetDO's other answers go after their retention. Generations (and so GC roots) are thinned by SandboxDO's own `retention` deadline ([state](../sandbox/state/#retention)) unless `SANDBOX_RETENTION` is `off`.

## Enums

The rule covers columns; closed sets inside a stored JSON body are parsed with their zod schema on read instead (CatalogDO skips and logs a row that fails). Every status, state, kind and type column (FleetDO's `hosts.status`, `role` and `tunnel_state`, `leases.state`, `commands.type` and `purpose`, `launched.role` and `reason`, `enroll_tokens.role`; SandboxDO's `state`; AgentDO's `turns`, `inbox`, `tool_calls`, `asks`, `approvals` and `brokered_journal` status) has a closed TypeScript union, shared with the wire types where one exists (`SandboxState`, `TunnelState`, `HostRole`, `CommandBody["type"]`); writes go through it, and every read is checked (`control-plane/src/lib/stored.ts`): a value outside the union is logged as an error and returned as read, so one bad row cannot stop a DO. There are no SQLite `CHECK` constraints: SQLite can add one only by rebuilding the table, which on live DO data is a risky migration for a guard the types already give. A column whose null meant a value (`hosts.tunnel_state`, null for `none`) is written explicitly and migrated once. A renamed member goes expand/contract over two releases: the three `role` columns are read under both names and still written as `burst` and `controller`, and the next release rewrites them to `sandbox` and `brain` ([deploy](../../dev/deploy.md#host-role-names-expandcontract)). The admin views (`GET /v1/admin/fleet`, `/v1/admin/images`, `/v1/admin/lifetimes`) are typed by the contract `protocol/admin/view.ts`, which imports nothing, so the dashboard checks its client against it with type-only imports and never imports the control plane; the control plane asserts at compile time that its enums equal the protocol's. Flags (`hosts.lost`, `brain_epochs`, `host_agents.gone`, `drain_told`) are 0/1 integers; AgentDO's brain record phases live in its JSON state, not in columns.
