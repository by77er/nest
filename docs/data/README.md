# Data placement

**Each piece of data lives next to its main reader.**

| Store | Contents | Main reader | Credentials |
|---|---|---|---|
| DO SQLite | Heads, epochs, agent epochs, leases and placement claims, segment and generation indexes (with pins and loss records), the base-generation index, current state, grants, channel messages (up to about 32 KB) and cursors, task ledgers, tunnel ids per sandbox host and the three desired versions per cell (FleetDO) | Control plane | — |
| R2 | Session segments (native Claude Code session files), large and older (7+ days) channel message bodies (`channels/<channel>/b/<id>`), audit logs (egress, credential issuance), UI artifacts (diffs, screenshots), exported journals | DOs, UI, agents, me | DO bindings only |
| S3, per cell (Express One Zone for hot data) | Disk chunks, memory pages, generation manifests, including base generations | Hosts | Instance role |

- **Cross-cloud traffic is small text:** transcripts from brain hosts to Cloudflare, session files back from R2 when a brain starts on a new host, and hands frames between a brain and its sandbox's gateway over the tunnel. No bulk data crosses.
- **Bindings are verified, not stored.** SandboxDO has them signed with the cell's binding key, which BrokerDO holds; FleetDO pushes the public keys to each sandbox host's gateway; nothing records an issued binding. See [../sandbox/gateway/](../sandbox/gateway/).
- **R2 is the one global store for the control plane.** Each cell has its own S3-compatible store. See [../sandbox/state/object-store/](../sandbox/state/object-store/).

## Retention

Every DO table that would otherwise only grow has one retention rule, a named constant next to the code that applies it. A row something still depends on is never dropped.

| DO | Table | Kept | Why |
|---|---|---|---|
| FleetDO | `commands` | 24 h after its result (`COMMAND_RETENTION_MS`). A host's death answers what it never did, with an error and no failure handling; a command for a dead or unknown host is answered so at once and never queued. | Results are read back right after they arrive; a dead host never answers. |
| FleetDO | `hosts` (with its `commands`, reliable channel and `tunnels_created` rows) | 7 days after it died (`DEAD_HOST_RETENTION_MS`), and only once its death is proof (`lost`: lease expired or death confirmed), its tunnel and record are deleted (the row's ids are null), and no lease, stale incarnation, reassignment, eviction or brain-index row (`host_agents`) names it. | The tunnel sweep retries deletes from the row; AgentDO asks for a brain's host's status and kill progress until it released the brain; operators look at recent deaths. |
| FleetDO | `host_agents` (the brain index) | Never pruned: a row goes only when AgentDO took the brain's exit or its host's loss for it ([fleet](../control-plane/durable-objects/fleet/)). | The one-brain rule depends on it. |
| FleetDO | `leases`, `reassignments` (one row per lost lease), `evictions` | Bounded by live entities: one lease per placed sandbox, deleted on release, eviction or reassignment; queue rows deleted once SandboxDO took them (retried from the tick). | Each is work in flight. |
| FleetDO, AgentDO | `rel_out`, `rel_state` (reliable channels) | `rel_out` until acked (reset when the peer restarts or dies); `rel_state` one row per channel, dropped with a pruned host. | Resend after a reconnect. |
| Every DO | `deadlines` | One row per armed deadline, deleted when it runs. | Multiplexes the one alarm. |
| FleetDO, SandboxDO, WorkstreamDO, AgentDO | `kv` | A fixed set of keys per object (FleetDO: the zone id per zone, the cell, the mark counter, the root CA, the last prune, a GC request; SandboxDO: `agent_repos`, an attached agent's push allowlist, removed at detach). | Bounded by construction. |
| AgentDO | the whole object (`kv.info`, every table below, and its R2 session segments `sessions/<agent>/`) | An agent that [ended](../agents/#lifetimes): 30 days after its end (`AGENT_RECORD_RETENTION_MS`), once the end's steps are done and no brain record is left; segments first, then `deleteAll`. An agent that never ends (the operator's, stopped or not) is kept. | Its owner and the operator read its transcript and events for a while; nothing else needs it once it can't run. |
| AgentDO | `children` (the agents it spawned) | One row per spawn, kept with the agent (an index of each child's `owner`; `ended` set once the child's end is done). Bounded by the live-children cap and the agent's life. | Its end ends them; the cap counts the live ones. |
| CatalogDO | `capabilities`, `templates`, `kv` | Keyed by name: bounded by the entries an operator writes (`kv` holds only the seeded flag and the seed version). | They are the catalog. |
| ChannelDO | `messages` | Per channel, `retention_days` (default 30, `DEFAULT_RETENTION_DAYS`), from the daily `maintenance` deadline; the newest message per key is kept while it is the newest (its row is what the keyed view points at). Bodies older than 7 days (`TIER_AFTER_MS`) and over 32 KiB live in R2 (`channels/<channel>/b/<id>`), deleted before their row (pages of 1000, R2's per-call limit). Channels themselves are never deleted ([open question](../control-plane/durable-objects/channel/)). Built-in channels (`<agt>/inbox`, `<agt>/events`, `<sbx>/events`, `user`) use the default. | Readers page with `since`; the keyed view is shared state. |
| ChannelDO | `keys` | One row per live key; a keyed post with no text removes it. | It is the keyed view. |
| ChannelDO | `idem`, `rate` | Idempotency keys (per poster) 7 days (`IDEM_RETENTION_MS`); a rate window once it ended. | A retried post lands once within a call's outcome lifetime. |
| ChannelDO | `subs`, `acl`, `kv`, `directory` | Bounded by live subscriptions (removed by `unsubscribe`, a `once` delivery, or a subscriber that isn't an agent), the grant list the operator sets, a fixed set of keys (`meta`, `head`), and (`~directory` only) one row per channel. | They are the channel's state. |
| AgentDO | `channel_subs` | One row per subscription it has; an ended (`once`) one 7 days. | The high-water `seq` deduplicates deliveries; `skipped`/`skipped_to` record notices taken without delivery (no `read`) for stage 2. |
| AgentDO | `chan_wakes` | An hour: older rows are dropped whenever the wake cap is counted. | Merged notices' wakes count toward the hourly cap. |
| AgentDO, SandboxDO | `chan_out` | Until ChannelDO acknowledged the post, or (refused for good 3 times) dead-lettered: logged and removed. | Its `<agt>/events` or `<sbx>/events` post is owed. |
| TaskLedgerDO | `tasks` | Open tasks (not done or canceled): at most 10,000 per ledger (`LIMITS.openTasks`), a create or reopen beyond it refused. **Closed tasks: no rule yet**, the one exception to the rule above ([open question](../control-plane/durable-objects/tasks/#retention)): they are kept, so a long-lived ledger grows by its closed tasks. | The ledger is the record; a long-lived ledger keeps accepting work. |
| TaskLedgerDO | `comments`, `history` | Both deleted for a task `done` or `canceled` more than 30 days ago (`CLOSED_TASK_DETAIL_MS`); `history` keeps the latest 500 rows per task; at most 1,000 comments per task (one beyond is refused, none dropped). Pruned daily from the alarm. | A closed task's detail stops mattering; an open task's is bounded. |
| TaskLedgerDO | `outbox`, `applied`, `kv`, `deadlines` | `outbox` rows until their agent took the notice (or doesn't exist); `applied` keys 7 days (`APPLIED_RETENTION_MS`); `kv` a fixed set of keys (name, next number, watcher); `deadlines` two keys (notices, prune). | Notices are delivered at least once; a re-run tool call is answered from `applied`. |
| BrokerDO | `secrets` | Keyed by name: bounded by the names an operator writes; an expired value stays (refused when resolved) until overwritten or deleted. | An operator sees what to renew. |
| BrokerDO | `oauth_grants`, `oauth_flows`, `oauth_clients` ([mcp OAuth](../agents/capabilities/mcp/#oauth)) | `oauth_grants` one row per token record (an authorization replaces it); `oauth_flows` until used, or expired (10 min) and swept at the next start; `oauth_clients` one per authorization server and redirect URI. | The tokens nest uses; a started authorization's verifier; a registration reused across capabilities. |
| BrokerDO | `injections`, and the secrets `inject:<binding>:<sandbox>` they name ([injection minting](../control-plane/durable-objects/broker/#injection-minting)) | One row per (sandbox, binding) with a minted token, overwritten by the next mint; deleted when nothing is mintable for it, when the sandbox is destroyed, and (the secret) once expired, at the next mint. | The token a push's reference resolves to, and what it was minted for, so a push with the same allowlist reuses it. |
| BrokerDO | `github_tokens`, `github_installations` | One row per (repo, permissions) a brokered action minted for, overwritten by the next mint; one per repo looked up (refreshed after a day). No pruning yet: bounded by the repos agents act on. | The token is reused for 50 minutes; the installation saves a lookup per mint. |
| FleetDO | `tunnels_created` | With its host's row; without one, until a sweep whose two listings both succeeded and were complete shows neither the tunnel nor the record, past the hour's grace. A listing stops at 10 pages of 100 (`lib/cloudflare.ts`) and then says it is incomplete, so a large account only delays forgetting. | It is what the sweep may delete: forgotten only once nothing is left to delete. |
| FleetDO | `launched` | 7 days after EC2 confirmed it gone (`LAUNCH_RETENTION_MS`); never before. Confirming a host dead marks its instance to terminate, so every launched instance ends. | The record is what terminates the instance and confirms it gone. |
| FleetDO | `stale_incarnations` | 24 h after its `sandbox_destroy` was issued (`STALE_INCARNATION_RETENTION_MS`). | The destroy is sent once. |
| FleetDO | `enroll_tokens` | 7 days after use (`ENROLL_TOKEN_RETENTION_MS`). An unused token stays until used. | A used token can't be used again. |
| FleetDO | `gc_runs` | 30 days after it finished (`GC_RUN_RETENTION_MS`); the latest run, the latest proven run (so the next run isn't dry again) and an unfinished run always. | GC history for the operator. |
| FleetDO | `sandboxes` | Live rows always; a destroyed one 30 days (`DESTROYED_SANDBOX_RETENTION_MS`). `lifetime_ms`: when its SandboxDO confirmed its lifetime check is armed (the backfill's mark). | Its generations stopped being GC roots when it was destroyed. |
| SandboxDO | the sandbox itself | Destroyed once [dormant](../control-plane/durable-objects/sandbox/#lifetime) (no agent attached, no VM up) for its idle TTL: its own, else the cell default (1 day). Its DO rows stay (a destroyed record is small and answers late reports); its S3 data goes with GC. | A sandbox nobody uses would otherwise hold its generations as GC roots for ever. |
| SandboxDO | `commits` (idempotency records) | A rejected request's record 7 days (`COMMIT_RECORD_RETENTION_MS`); a committed one while its generation's row exists (a `deleting` row's too, until it is pruned). Pruned from an hourly deadline, never on the commit path, through the indexed `generation_id`. | nestd asks again with an unanswered request's id before its next commit, possibly days later: a committed request finds its record while its generation is kept; any other meets the compare-and-set again, as a new request would. |
| SandboxDO | `epochs` (which host held which epoch) | The sandbox's life. `info().history` is read from it, never stored. | Salvage from any older epoch is authorized against it; one small row per placement. |
| WorkstreamDO | `events`, `user_notifications`, `applied` | The latest 5,000 and 1,000 rows; idempotency keys 7 days. | Bounded history. |
| AgentDO | `tool_calls`, `asks`, `approvals`, `turns`, `inbox`, `mcp_forwards`, `brokered_journal` | Finished rows (a turn `done`, `interrupted` or `dropped`) 7 days (a journal row still `sending` stays: a redelivery reads it); `events` the latest 500; `seg_buffer` until its bytes are acked. | Bounded history. The journal is the operator's record of brokered actions ([brokered](../agents/capabilities/brokered/#journal)). |
| AgentDO | `mcp_servers`, `mcp_forwards` ([mcp capabilities](../agents/capabilities/mcp/#data)) | `mcp_servers` one row per mcp capability of its spec; `mcp_forwards` settled rows 7 days. | A server's session and its copy of the shared tool list; each forwarded call's state and outcome, so a call key is forwarded once and a new epoch waits for an older one's forwards. |
| McpConnectorDO | `kv`, `subscribers`, `leases`, `admits` ([McpConnectorDO](../control-plane/durable-objects/mcp-connector/)) | `kv` a fixed set of keys; `subscribers` until the agent says it no longer wants notices or hasn't answered for 24 h; `leases` until released or expired (4 call timeouts); `admits` one minute. | One list per server and credential; admission across agents. |
| AgentDO | `segments` (the transcript's R2 segment index) | The agent's life; rows of a superseded base aren't dropped yet (a gap). | The transcript is rebuilt from them. |
| SandboxDO | `grants` | Until each expires (the `grants` deadline deletes it). | Bounded by live grants. |
| SandboxDO | `generations` | Ready rows as [generation retention](../sandbox/state/#retention) keeps them; a row it drops is marked `deleting` (`state`, `deleting_ms`) and a main-chain one pruned a week later; an orphan's row never is (its commit record must answer a late salvage). A checkpoint's memory no longer a restore source is marked `mem_unrooted_ms`. With `SANDBOX_RETENTION` at `report` (the default) or `off` nothing is marked. | A ready generation is a GC root (its memory until unrooted); a `deleting` one never is. |

FleetDO prunes at most once an hour, from any alarm: the tick while a host is live, the daily tunnel sweep, and its own daily `prune` deadline (armed on every start, so a quiet cell without tunnels still prunes). A dead host left at `lost` = 0 (an idle or drained retirement whose termination EC2 never confirmed, e.g. a cell without EC2 access) is never pruned, nor are the kill commands FleetDO answered for a host at `lost` = 0 (dead or alive): its death isn't proof (A6), and AgentDO reads a missing kill command as processed. FleetDO's other answers go after their retention. Generations (and so GC roots) are thinned by SandboxDO's own `retention` deadline ([state](../sandbox/state/#retention)), once `SANDBOX_RETENTION` is `on`.

## Enums

The rule covers columns; closed sets inside a stored JSON body are parsed with their zod schema on read instead (CatalogDO skips and logs a row that fails; AgentDO reads its spec's `escalate_to` through `storedEnum`). Every status, state, kind and type column (FleetDO's `hosts.status`, `role` and `tunnel_state`, `leases.state`, `commands.type` and `purpose`, `launched.role` and `reason`, `enroll_tokens.role`; SandboxDO's `state`; WorkstreamDO's `events.type` and `user_notifications.urgency`; AgentDO's `turns`, `inbox`, `tool_calls`, `asks`, `approvals` and `brokered_journal` status; ChannelDO's `acl.action` and `directory.kind`, and a subscription's `delivery` inside its JSON body; TaskLedgerDO's `tasks.status`, with the task's `status` and `priority` read back from its JSON body) has a closed TypeScript union, shared with the wire types where one exists (`SandboxState`, `TunnelState`, `HostRole`, `CommandBody["type"]`, `WorkstreamEvent["type"]`); writes go through it, and every read is checked (`control-plane/src/lib/stored.ts`): a value outside the union is logged as an error and returned as read, so one bad row cannot stop a DO. There are no SQLite `CHECK` constraints: SQLite can add one only by rebuilding the table, which on live DO data is a risky migration for a guard the types already give. A column whose null meant a value (`hosts.tunnel_state`, null for `none`) is written explicitly and migrated once. A renamed member goes expand/contract over two releases: the three `role` columns are read under both names and still written as `burst` and `controller`, and the next release rewrites them to `sandbox` and `brain` ([deploy](../../dev/deploy.md#host-role-names-expandcontract)). The admin views (`GET /v1/admin/fleet`, `/v1/admin/images`, `/v1/admin/lifetimes`) are typed by the contract `protocol/admin/view.ts`, which imports nothing, so the dashboard checks its client against it with type-only imports and never imports the control plane; the control plane asserts at compile time that its enums equal the protocol's. Flags (`hosts.lost`, `brain_epochs`, `host_agents.gone`, `drain_told`) are 0/1 integers; AgentDO's brain record phases live in its JSON state, not in columns.
