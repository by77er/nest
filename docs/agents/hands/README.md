# Hands

MCP tools that act on the agent's bound sandbox. `nest mcp` (a stdio shim Claude Code spawns on the host) forwards them to the agent runner, which calls the [guest agent](../../sandbox/guest-agent/) over vsock RPC. The exact schemas are in `protocol/schemas/guest/hands-tools.json`; the wire semantics are in [../../interfaces/host-guest/](../../interfaces/host-guest/).

| Tool | Modeled on | Semantics |
|---|---|---|
| `Bash` | Bash | Per-agent **cwd persists** across calls (exported variables don't: each call is a fresh `bash -c`). Timeouts (default 2 min, max 10), `run_in_background` (a running background task holds the sandbox awake; [idle rule](../../control-plane/durable-objects/sandbox/#activity-and-idle)), output truncation like the built-in. If the cwd disappeared, the command runs in the slot's cwd (or `/`) and the output starts with a `nest:` warning. |
| `TaskOutput` / `TaskStop` | Background shell tools | Poll (optionally blocking) or kill background jobs |
| `Read` | Read | Line-numbered output, `offset`/`limit`, images as MCP image content, PDFs (`pages`), notebooks. **Regular files only** (FIFOs, sockets and devices are refused; use Bash). Whole-file reads are capped at 256 KB; `offset`/`limit` reads stream and stop counting lines after 1 GiB. |
| `Write` | Write | **Must read before overwriting**, and **rejected if the file changed since the read** (size or content; an mtime-only change such as `touch` is fine). |
| `Edit` | Edit | Exact-string replace, `replace_all`, must read first. If the file changed since the read, a **unique** match still applies and the result is flagged `changed_since_read` with a note. Files over 16 MB go through Bash. |
| `Glob` / `Grep` | Glob / Grep | Glob: newest 100 matches, at most 500k entries walked. Grep: ripgrep in the guest with the same output modes and limits, output capped at 16 MB, 2 min timeout. |

- **Writes replace the file atomically when that's safe:** a new file, or a regular file the sandbox user owns with one link and no ACL, is written to a temporary file beside it (given the target's mode, group and xattrs) and renamed over it, so readers never see a partial file. The file gets a new inode, as with an editor's atomic save. Anything else (another owner, hard links, an ACL, a directory or mount that refuses the temporary file or the rename) is written in place, like Claude Code's own Write. Either way, writes go through symlinks, keep hard links, owner and mode, and create missing parent directories.
- **Durability comes from commits, not writes:** neither path syncs. A write is durable once a [generation commit](../../sandbox/state/) covers it, and every commit first needs a successful guest `syncfs` ([flush before commit](../../sandbox/state/disk/#flush-before-commit)).
- **Everything runs as the sandbox user.** Bash, Grep and helpers (pdftotext, vips, convert) are spawned as that uid with the agent's environment (`HOME`, `USER`, `LOGNAME`, `SHELL` from passwd, plus `NEST_AGENT_ID` and `HTTP(S)_PROXY`). Read/Write/Edit/Glob run inside the guest agent with the user's **filesystem identity** (per-thread `setfsuid`/`setfsgid`), so permission checks and new files' ownership are the user's, not root's.
- **Per-agent exec context:** every call carries the agent ID. The guest runs each call's processes in their own leaf of that agent's cgroup (accounting, and `cgroup.kill` on interrupt), placed before exec; a call that can't be placed is refused.
- **A call ends with its command:** once the main process exits, output drains for up to 1 s, then whatever it left running (`cmd &`) is killed with the call's cgroup. Long-lived processes use `run_in_background`. The exit is typed in `detail` (`exited`, `signaled`, `timed_out`, `unknown`), and the model's text gives a shell's code: 128+n for signal n, 124 for a timeout.
- **Cancellation:** an MCP cancel or a hard interrupt kills the call's process tree; in-process file tools return `[Interrupted]` and are abandoned after 2 minutes at most.
- **A hangup is a cancel,** including one caused by a runner restart: hands calls get no detach grace. The brain that made the call is gone, and the [journal](#journal) gives recovery its outcome. Terminals do get one ([guest agent](../../sandbox/guest-agent/#terminals)).
- **A wedged guest is detected:** the guest sends a heartbeat on a call silent for 10 s. The runner fails a call after 30 s without a frame, or at the tool's own deadline plus 15 s, and tells the model the outcome is unknown.
- **Agents without hands** (never bound, or detached) get a clear error.
- **Schemas and descriptions are copied closely** from Claude Code's built-ins to keep them familiar to the model. Tools appear as `mcp__nest__<Name>`.
- **Input drift:** the guest ignores input fields it doesn't know, since models trained on newer built-ins add some. A field that would change a call's meaning and that nest doesn't implement is listed for its tool in `hands-tools.json`, and the runner rejects it with an error naming it: ignoring it would mislead the model. Each new [Claude Code baseline](../runner/) sorts the built-ins' new fields into implemented, ignored or rejected.
- **Fidelity risk:** the built-ins are heavily tuned. **Spike:** run the same tasks with native tools (Claude Code inside a VM) and with hands over RPC, and compare success rate, number of turns and token use. The same eval gates each new Claude Code baseline.
- **Rejected alternative:** native tools redirected with `CLAUDE_CODE_SHELL_PREFIX` plus a filesystem mount. The prefix also wraps hooks and MCP server startup, the command it receives includes setup that refers to local files, Firecracker has no virtiofs, and pointing the working directory at the repo would let the repo's config load on the host.

## Journal

A hands call that was in flight when its brain died may have an unknown outcome. Durable-execution systems record that as a first-class state instead of guessing ([an example, 2026-03](https://urandom.io/blog/2026-03-29-exactly-once-is-a-fantasy-agent-systems-need-idempotent-tools)), and so does nest, while keeping unknowns rare:
- **Records:** the guest keeps a record per call on tmpfs, keyed by `(agent, epoch, tool_use_id)`: **intent** at the point of no return, **outcome** after. Both stream to AgentDO as events.
- **Two stages:** every fallible step (validation, admission, cgroup placement, the output file, read-record checks) runs before the intent, under a reservation. A refusal drops the reservation, which proves nothing ran, so its error says `executed: false`. After the intent, losing the call makes its outcome unknown.
- **Proven non-executions are retried:** the runner retries a retryable refusal with `executed: false` (e.g. `busy` while a snapshot freezes the filesystem, or a full admission queue) for up to 30 s, honoring `retry_after_ms`, instead of showing it to the model.
- **Duplicates are refused** before any other check, so a repeated `call_id` never runs twice.
- **Lookup after a crash:** at brain start, the runner asks the guest for each call AgentDO has in flight (`call_status`, read-only, any epoch). Whenever the guest outlived the brain or the runner, the [recovery context](../sessions/#after-a-crash) then reads "exited 0, output at …" or "killed by the hangup after 40 s, output so far at …". **Unknown** remains only when the guest lost its records (a reboot, or a restore from disk) or restarted mid-call.
- **Calls that may have run aren't retried by the platform:** the model checks first (e.g. `git status`, the remote branch). Irreversible external actions (publishing, deploying, opening PRs) should go through [brokered actions](../tools/), which read the current state and use natural idempotency keys.
