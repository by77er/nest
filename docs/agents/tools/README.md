# Tools

`nest mcp` runs on the brain host next to each brain. An agent's tools come from its [capabilities](../capabilities/), and every call is checked against its grants; there are no role-specific tools.

| Group | Tools | Executes |
|---|---|---|
| **[Hands](../hands/)** | `Bash`, `Read`, `Edit`, `Write`, `Glob`, `Grep`, `TaskOutput`, `TaskStop` | In the bound sandbox, through its [gateway](../../sandbox/gateway/) |
| **Agents** | `agent_spawn`, `agent_stop`, `exit` (end itself; every agent's, never gated), `attach`, `adopt` (take ownership of a parked resource), `wake_at` and `wake_cancel` (scheduled wakes on itself), `timer_set`, `timer_cancel` and `timer_list` (named timers that wake it: [timers](../capabilities/timers/)), `read_transcript`, `list` (any resource kind, filtered by labels) | Control plane |
| **Sandboxes** | `sandbox_create`, `sandbox_fork`, `sandbox_destroy`, `checkpoint`, `expose_port`, `egress_policy` | Control plane |
| **Authority** | `grant`, `revoke` | Control plane |
| **Brokered actions** | `github.create_pr`, `github.review_check`, `github.review_comment`, `github.comment`, `github.create_issue`, `github.dispatch_workflow`, `github.create_webhook`, `email.send`, `http.request(profile)`; each is its own tool (`github_create_pr`, …, `http_request`), and `brokered{action, args}` reaches them all ([brokered](../capabilities/brokered/#tools)) | Control plane, with secrets that never reach a sandbox |
| **Metrics** | `metrics_query` (see [metrics](../../control-plane/metrics/)) | Control plane → Analytics Engine |

**Built:** the table is the design. The registry (`protocol/schemas/control/platform-tools.json`) holds interim tools that predate grants, and the first that use them: `read_transcript` (on itself, an agent it owns, transitively, or one a [grant](#grants) covers) and `list` (agents only: those its grants cover) work, as do `expose_port` and `egress_policy`; `fork_sandbox`, `attach`, `checkpoint` and the seeded `management` and `memory` capabilities' tools answer `not_implemented`. `agent_spawn`, `agent_stop` and `exit` are built ([lifetimes](../#lifetimes)), and so are `timer_set`, `timer_cancel` and `timer_list` ([timers](../capabilities/timers/)); `wake_at` and `wake_cancel` aren't. Brokered actions are built except `github.review_check`, `github.dispatch_workflow`, `github.create_webhook` and `email.send` ([brokered](../capabilities/brokered/)). Hands are built ([hands](../hands/)).

**Coordination tools are not platform tools.** Messaging, shared state, memory and external events are external integrations an agent reaches over MCP ([principle 9](../../README.md#principles)); the platform's part is the agent's inbox, which an integration posts to over the public API. A stored spec naming a tool the registry lacks still starts: the tool isn't offered, and a call answers `unknown_tool`.

## Grants

A grant is `(principal, action, resource, limits?, expires?, parent)`. A resource is an id, a label selector (`sandbox{project=auth}`), or `own` (whatever the principal owns, now or later).

- **Attenuation:** an agent can grant, or put in a spawn spec, only grants it holds, with equal or tighter limits. I hold the root, so authority flows down from me and only shrinks.
- **The chain is the revocation list:** each grant records its `parent` and is valid only while every ancestor is. Limits intersect down the chain. Revoking a grant revokes everything derived from it, and the grants an agent issued end when it's removed. Every call is checked online against one store, so no signed tokens are needed; attenuable tokens ([Biscuit](https://doc.biscuitsec.org/reference/specifications), the [IETF attenuating agent tokens draft](https://www.ietf.org/archive/id/draft-niyikiza-oauth-attenuating-agent-tokens-01.html)) solve offline and cross-domain checks, which nest doesn't have.
- **Ownership:** creating a resource gives its creator every grant on it. Built for agents only: the child's `owner`, checked transitively by `agent_stop` and `read_transcript` ([spawning](../#spawning)). A sandbox `agent_spawn` makes is owned by the child it is made for.
- **Budgets shrink like grants:** see [spawning](../#spawning). An agent over budget is parked and escalates.
- **Checked twice:** AgentDO filters `tools_list` by grants, then checks every `tool_call` again.
- **Approval:** a sink call from a tainted session under `when_tainted: approve` first asks the operator (see [taint and sinks](#taint-and-sinks)).

### Built: transcript grants (2026-11-06)

The smallest slice that lets an agent read agents it doesn't own (a memory-consolidating agent reading its siblings' transcripts), in the shape above, so later actions extend it (`control-plane/src/lib/grants.ts`):
- **Shape:** a spawn spec's `grants: [{action, resource, limits?, expires_ms?}]`. The principal is the agent spawned; the parent is whoever spawned it. The one action is `read_transcript`.
- **Resources:** an agent id (`agt_…`), or a label selector `agent{key=value,…}` (each label must match; `agent{}` is every agent). A selector's value has no `,`, `{`, `}` or control character. Stored in canonical form (keys sorted). `own` and other kinds aren't built.
- **Limits:** `max_age_ms` (only transcript entries whose `timestamp` is at most this old; an entry without one is withheld) and `max_entries` (per call). Absent means none. Each is a ceiling on what the call asks for: `limit`, `since_ms`. An unknown limit is refused, never dropped. `expires_ms` is absolute.
- **Who confers:**
  - The operator (`POST /v1/agents` with the admin token): any grant in the new agent's subtree. Its parent is the root.
  - An [API client](../../control-plane/api/clients/) (the same route under its token): over its own subtree, which its owner auth already reads.
  - An agent (`agent_spawn{grants}`): only a grant that attenuates one it holds whose chain holds now. That means the same action, a resource within every link's (more labels, or an id the selector covers), each limit present and no looser, and an expiry no later.
- **Confinement (the explicit check, `inScope`):** every grant records the subtree it was conferred in (`scope`: the client, or null for the operator's own agents). It reaches only agents whose `client` equals it, at confer time and again at every call, whatever the labels. So a client's agent never reads another client's agents or the operator's, and the operator's agents never read a client's. An id outside the subtree is refused at confer time (404 from the API, as for any id outside a client's subtree; `forbidden` from `agent_spawn`).
- **The store:** each grant is a row in its principal's AgentDO (`grants`), written with the agent's record and fixed after. Its `parent` is the operator, a client, or `(agent, grant id)`. "One store" is read as one online check, not one object. Every call walks the chain (`resolveChain`): each link must be unexpired, of the same action and subtree; an agent parent must not have ended (from the moment its end is asked, before the cascade reaches its children) and must still hold the parent grant; a client parent must not be deleted. Limits intersect down the chain, and the expiry is the earliest. A stored grant this release can't read fully (an unknown action or limit) authorizes nothing.
- **Checked twice:** `tools_list` offers `read_transcript` with an unexpired `read_transcript` grant and `list` with any unexpired grant, whatever the spec's tools say. Every `tool_call` is checked against that list again, then against the whole chain. The brain's list isn't refreshed when a grant lapses: the call refuses it.
- **`read_transcript`:** on itself or an agent it owns, as before (no limits). On any other agent, it takes the first grant, in the order conferred, whose chain holds and reaches the target, and applies its limits. Otherwise `forbidden`, also for an id naming no agent, so a holder can't probe which ids exist. It keeps paging (`since_seq`, `base`), the 500-entry and 256 KiB caps, and adds `since_ms`, a time window the model asks for. The window is applied by the target and again by the reader (a target of the previous release ignores it).
- **`list {kind: agent, labels?, state?, limit?, cursor?}`:** the agents its grants cover, one grant per page in conferred order (an agent two grants cover appears under each), filtered by labels. The source is the client's registry, or for the operator's own agents the reader's cell's registry. Each row is checked against the grant again on its own client and labels. Each row gives `{agent, labels, created_ms, ended_ms, actions}`.
- **Taint:** reading another agent's transcript taints the reader, as before. A `list` row whose labels an agent wrote (`agent_spawn`'s labels) taints too: it is another agent's text. Rows a client or the operator labelled don't (for the operator's own agents, the owner comes from each row's record, since the cell's registry has none).
- **No revocation of a single grant yet:** nothing revokes one grant by id (no `revoke` tool or route). A grant ends only when it expires, when its holder ends, or when its chain breaks (an ancestor expires, a conferring agent ends, a conferring client is deleted).
- **Not built:** the `grant` and `revoke` tools. Also not built: grants in templates, `own`, other actions and resource kinds, `when_tainted` on grants, ownership expressed as grants (it stays the owner-chain walk), and `list` beyond agents or across cells for the operator's own agents.

## Taint and sinks

An agent that reads untrusted content, holds private data and can send data out can be made to leak it: the [lethal trifecta](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/) (2025-06), also framed as the [Agents Rule of Two](https://ai.meta.com/blog/practical-ai-agent-security/) (2025-10). Model robustness helps but isn't a boundary: adaptive attacks broke 12 published defenses at over 90% ([2025-10](https://arxiv.org/abs/2510.09023)). So nest tracks what each session has read, the way [CaMeL](https://arxiv.org/abs/2503.18813) and [FIDES](https://arxiv.org/abs/2505.23643) label data, but per session, which is cheap:

- **Taint is one bit per session, kept by AgentDO and set only by the platform.** It's set by hands output, `WebFetch`/`WebSearch` results, `mcp` and `api` capability results, `read_transcript` (and `list` rows whose labels an agent wrote), a tainted inbox message, and tainted results from an integration. It lasts for the session (a `--resume` keeps it).
- **It propagates:** a spawned agent starts with its spawner's taint, and an inbox message carries its sender's taint.
- **Sinks** are the actions that can send data out or widen authority: widening an egress policy, external brokered actions, `mcp` tools not marked read-only, `api` capabilities with `mode: rw`, and granting a sink action. Each sink grant carries `when_tainted: approve | allow` (default `approve`), and attenuation can only tighten it.
- **A sink call from a tainted session** with `approve` asks for approval. Only I or an untainted holder of that grant can approve it (built: the operator, or the [API client](../../control-plane/api/clients/) whose subtree the agent is in; no agent can answer an ask, and the seeded `approve`/`deny` tools answer `not_implemented`).
- **One gate for every sink (built):** a remote MCP tool, a brokered action and `egress_policy` widening all go through the same gate (`control-plane/src/lib/sinks.ts`, AgentDO's `sinkGate`). A gated call isn't sent: it answers `pending` with an ask id, and the operator is asked once per exact call (the same sink with the same arguments asked again before a decision gets the same ask). **Approvals are a kernel gate:** the held call is recorded in AgentDO, listed by `GET /v1/agents/<id>/asks` (`{ask, question, created_ms, approval?: {name, tool}, input?, input_bytes?}`, oldest first: the question shows the deciding argument first and whole, and `input` is the whole call: [API](../../control-plane/api/)) with every other open ask (a call a tool rule in `ask` mode held, which has an approval too: [runner](../runner/#lifecycle)), and answered by `POST /v1/agents/<id>/asks/<ask>/answer`; the decision arrives as the agent's next turn (`ask_answer`). An API client owner is also sent each one as an `agent.ask` event by webhook ([events to the owner](../../control-plane/api/clients/#events-to-the-owner)); an owner agent is told nothing. An approval lets through **one** call of that sink with exactly those arguments (SHA-256 of their canonical JSON) within an hour (a tool rule's approval has no expiry: the owner's decision for rule asks, 2026-11-11; whether sink approvals should match is open), whichever tool reaches it (`github_create_issue` or `brokered{action: github.create_issue}`); the model calls again. A redelivery of the call it was spent on uses it again. The details and the reason it's asynchronous are in [mcp sinks](../capabilities/mcp/#sinks).
- **Built so far:** a conservative stand-in kept by AgentDO: a session is tainted if the agent has hands or a web built-in, or once another agent's text reached it that may be tainted (sticky): an inbox post relayed under another name than the caller's own (`user` for the operator, its id for a client), a spawn's task from a tainted spawner, or another agent's transcript. An untrusted [mcp capability](../capabilities/mcp/#taint)'s tool list or results set it too (a `trusted` one's don't), and so does an untrusted `http.request` profile's answer. It guarantees that no such text, and nothing from a sandbox, the web or an untrusted MCP server, reaches a session that then posts untainted; the operator's own text never taints. It over-taints freely (a captain that reads a hands worker's result once is tainted for good). The sinks checked: remote MCP tools ([mcp sinks](../capabilities/mcp/#sinks)), brokered actions ([brokered](../capabilities/brokered/#the-pipeline)) and widening egress (`egress_policy`, always `approve`: a per-grant `when_tainted` for it waits for grants). `api` capabilities and granting sinks aren't built.
- **Ways back to clean:**
  - A fresh session starts untainted unless the wake that starts it carries taint, or it then reads tainted content.
  - **Quarantined reports:** a spawn spec can declare a `report_schema` of enums, numbers and ids. A child's final report that validates against it reaches the spawner untainted, even from a tainted child. This is the dual-LLM / map-reduce pattern from [Design Patterns for Securing LLM Agents](https://arxiv.org/abs/2506.08837) (2025-06), and how a captain stays clean while its workers read code.
- **Template defaults ("balanced", tuned from experience):** widening egress and granting sinks are `approve`. Brokered actions already scoped by their binding (e.g. `github.create_pr` to the binding's repos) are `allow`. Management grants stay off agents with hands.

**Brokered actions** run one pipeline in AgentDO (grant, cap, secret scan, sink gate, current external state, a natural idempotency key, journal): see [brokered](../capabilities/brokered/#the-pipeline).

- **Identity:** the runner knows which agent each MCP process belongs to and authenticates to the control plane with its host token. Stale agent epochs are rejected.
- **Never block on a human:** an approval answers `pending` at once, the turn ends, and the decision arrives as a later turn.
- **Inbound messages** are inbox posts: mid-turn they join the running turn, otherwise they queue a turn. One flagged `interrupt` interrupts the current turn (built for the public API only: the operator and API clients).

## The `nest` CLI inside sandboxes

Scripts and programs running in a sandbox can call `nest expose`, `nest unexpose` and `nest whoami` through the guest agent over vsock. What they send is **always tainted**. `NEST_AGENT_ID`, set on every hands exec, attributes a call. It isn't a secret, because identity inside a sandbox is attribution only. Everything else needs a brain. The CLI socket is to take at most 256 connections ([admission](../../sandbox/guest-agent/#admission), designed; today it has no cap).

**Designed, not built:** `nest hold <duration>` asks to keep the sandbox awake (no pause or suspend) for a background build or a dev server. It's granted up to the sandbox's maximum hold (1 h by default) and prints the granted duration; a later call replaces the hold, and `nest hold 0` ends it ([idle rule](../../control-plane/durable-objects/sandbox/#activity-and-idle)). Nothing inside a sandbox can ask for it to be paused, suspended or shut down.
