# Setup: everything needed to bring nest up

What I provide, where it goes, and what each piece unlocks, in the order testing needs it. Everything not listed here is generated by the agent doing the setup (see [generated, not provided](#generated-not-provided)).

## Rules for every credential

- **Never paste a credential into a chat.** Add it in the cloud environment's settings: the environment menu in the session's title bar → **Edit** → **Network secrets** (older apps: **API credentials**), or as an environment variable, under the exact name given below.
- **A new session picks it up;** a running session doesn't. Start a new session on the same branch after adding one.
- **Least privilege, then rotate:** each credential below is scoped as narrowly as testing allows. Revoke them all after testing (see [cleanup](#cleanup)).
- **Network:** the environment already reaches every endpoint below. If its network access is ever narrowed, it needs `api.anthropic.com`, `api.cloudflare.com`, `*.workers.dev`, `*.amazonaws.com`, `registry.npmjs.org`, `github.com`, `crates.io` and `static.crates.io`.

## Decisions to make first

| Decision | Default | Why it matters |
|---|---|---|
| AWS region | `us-east-1` | It hosts the first cell: the burst hosts and the cell's S3 bucket. It must offer C8i instances. |
| Monthly spend cap | $25 | Becomes an AWS Budgets alarm. Testing costs a few dollars. |
| Dedicated AWS account | Yes | Keeps the blast radius of broad testing credentials to nest. |
| Separate Claude token for captains | Optional | Needed only to verify that two setup tokens can be revoked independently. |
| Domain on Cloudflare | Not yet | Needed only for previews (`*.preview.<domain>`), share links (`*.share.<domain>`) and email hooks, not for testing. |

## Stage 1: real Claude Code (no cloud, no KVM)

**Unlocks:** the checks against the real Claude Code binary (spike item 9) and the hands fidelity eval (item 10), run in the cloud dev environment.

| What | How | Environment variable |
|---|---|---|
| A Claude Pro or Max subscription | The one these agents will run on | — |
| A setup token | On a computer with a browser: install Claude Code, run `claude setup-token`, sign in. It prints a one-year token that can only make model requests ([docs](https://code.claude.com/docs/en/authentication)). | `NEST_CLAUDE_OAUTH_TOKEN` |
| (Optional) a second token | Run `claude setup-token` again, for captains | `NEST_CLAUDE_OAUTH_TOKEN_CAPTAIN` |
| Consent to spend quota | About 20 short turns on the cheapest model, plus one e2e turn | — |

Not `CLAUDE_CODE_OAUTH_TOKEN`: that name could change how the session's own Claude Code signs in.

**Then, in a new session on this branch:** "Run `e2e/claude-verify/run.py` and `NEST_E2E_CLAUDE=real e2e/run.sh`, and record the results in the verify list in `docs/README.md` and in the docs that own each item." See [e2e/README.md](../../e2e/README.md).

## Stage 2: the control plane on Cloudflare

**Unlocks:** a deployed control plane. Hosts can enroll once stage 3 has created the proxy root CA key.

| What | How | Environment variable |
|---|---|---|
| A Cloudflare account on **Workers Paid** ($5/month) | Dashboard → Workers & Pages → Plans | — |
| Account ID | Dashboard → Workers & Pages → the right-hand sidebar | `CLOUDFLARE_ACCOUNT_ID` |
| API token | Dashboard → My Profile → API Tokens → Create Token → the **Edit Cloudflare Workers** template, limited to this account. It covers Workers scripts (including Durable Objects), R2 and logs. | `CLOUDFLARE_API_TOKEN` |

`wrangler` reads both variables directly. The control plane deploys to `nest-control-plane.<subdomain>.workers.dev` until there's a domain.

## Stage 3: burst hosts on AWS

**Unlocks:** real Firecracker sandboxes, and spike items 1–8, 11 and 12.

| What | How | Environment variable |
|---|---|---|
| An AWS account, ideally dedicated to nest | AWS Organizations → add an account, or a fresh account | — |
| A provisioning key | IAM → Users → create `nest-provisioner` with `AdministratorAccess` **in that account only** → Security credentials → create an access key | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |
| Region | From the decisions above | `AWS_REGION` |
| vCPU quotas | Service Quotas → EC2: raise **All Standard (A, C, D, H, I, M, R, T, Z) Spot Instance Requests** and **Running On-Demand Standard (…) instances** to at least 16 vCPUs. New accounts often start lower. | — |
| A budget alarm | Billing → Budgets → a monthly cost budget at the spend cap, emailing me | — |

The provisioning key creates the narrow credentials nest actually runs with:
- the control plane's IAM user (`RunInstances` with the launch template only; terminate and stop only instances tagged `nest=true`; `kms:Sign` on the proxy root CA key only);
- the hosts' instance role (S3 access to the cell's bucket only);
- **the proxy root CA key:** a KMS key (`ECC_NIST_P256`, sign and verify), which never leaves KMS. The setup agent self-signs the root certificate through KMS `Sign` and stores it as `ROOT_CA_CERT_PEM`; the image bakes it in ([tls](../sandbox/networking/egress/tls/)).

**Prefer not to hand over an admin key?** The setup agent can write a CloudFormation template instead. Deploying it from the console creates the same resources, plus a narrower deploy key to provide in its place.

## Generated, not provided

The setup agent creates these itself, so none are needed from me:
- **Control-plane secrets:** the operator tokens (`observe`, `approve`, `admin`; the Worker keeps only their SHA-256 hashes, and I get the tokens), `HOST_TOKEN_SECRET`, `REVOCATION_COUNTER`, and the root certificate from stage 3, all random or freshly generated (see [API](../control-plane/api/)). Built: one `ADMIN_TOKEN`, and the root key as `ROOT_CA_KEY_PEM` until KMS signing lands.
- **`AWS_IDENTITY_CERT_PEM`:** AWS's public certificate for verifying instance identity documents, from AWS's docs.
- **Cloud resources:** the R2 bucket `nest-control`, the cell's S3 bucket with its gateway endpoint, the security group, the launch template, and the IAM pieces and KMS key above.
- **Images:** the guest kernel and root filesystem, and the burst-host bootstrap (Amazon Linux 2023, kernel 6.18, Firecracker from the 1.17 line pinned by digest; see [provisioning](../compute/provisioning/)).
- **Enrollment tokens** for hosts outside AWS.

## Cost while testing

- **Claude:** subscription quota only.
- **Cloudflare:** $5/month for Workers Paid; usage stays inside what's included.
- **AWS:**
  - a c8i.large spot host is about $0.03/hour, plus about $0.005/hour for its public IPv4;
  - S3 is cents;
  - the KMS root key is $1/month, plus $0.15 per 10,000 `Sign` calls (one per host enrollment or renewal; not in the free tier, [pricing](https://aws.amazon.com/kms/pricing/));
  - an idle cell costs nothing once its hosts terminate.

## Cleanup

- **Claude:** revoke the setup token(s). Where tokens are revoked isn't in the public docs (unverified); stage 1 checks it.
- **Cloudflare:** delete the API tokens; `wrangler delete` removes the Worker.
- **GitHub:** delete the App; its key goes with it.
- **AWS:** terminate every instance tagged `nest=true`, delete the stacks or resources, schedule the root CA key's deletion in KMS, and deactivate the `nest-provisioner` key. Closing a dedicated account removes everything.
- **Environment settings:** remove the variables.
