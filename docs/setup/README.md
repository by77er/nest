# Setup: everything needed to bring nest up

What I provide, where it goes, and what each piece unlocks, in the order testing needs it. Everything not listed here is generated by the agent doing the setup (see [generated, not provided](#generated-not-provided)).

## Rules for every credential

- **Never paste a credential into a chat.** Add it in the cloud environment's settings: the environment menu in the session's title bar → **Edit** → **Network secrets** (older apps: **API credentials**), or as an environment variable, under the exact name given below.
- **A new session picks it up;** a running session doesn't. Start a new session on the same branch after adding one.
- **Least privilege, then rotate:** each credential below is scoped as narrowly as testing allows. Revoke them all after testing (see [cleanup](#cleanup)).
- **Network:** the environment already reaches every endpoint below. If its network access is ever narrowed, it needs `api.anthropic.com`, `api.cloudflare.com`, `*.workers.dev`, `*.amazonaws.com`, `registry.npmjs.org`, `github.com`, `crates.io` and `static.crates.io`.

Not for the local harness. |
| Brain-host instance class | `t3a.medium`, then `t3.medium` (x86, because both kinds boot the one x86 host AMI) | Brains need no KVM; the class sets the cost of keeping a warm host for 30 min after its last brain ([brain hosts](../compute/brain-hosts/)). |

## Hostnames

Every nest hostname is a first-level label of the `bitcru.sh` zone, ending in `-nest`, so Universal SSL covers all of them and nothing is bought. Universal SSL covers the zone apex and first-level subdomains only ([Universal SSL](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/)); anything deeper (`x.nest.bitcru.sh`) would need the paid Advanced Certificate Manager, so no nest name goes deeper. A new host's hostname works the moment its record exists.

| Hostname | What | Routing | Access |
|---|---|---|---|
| `nest.bitcru.sh` | The control plane Worker: API, Discord interactions | The Worker's custom domain (`control-plane/wrangler.jsonc`) | Operator tokens |
| `dash-nest.bitcru.sh` | The [dashboard](../control-plane/dashboard/), its own Worker | The `nest-dashboard` Worker's custom domain (`dashboard/wrangler.jsonc`) | An Access application whose policy is me; the Worker also verifies Access's token on every request and answers 403 without one |
| `<host>-gw-nest.bitcru.sh` | One per sandbox host: the tunnel to its [gateway](../sandbox/gateway/) (hands, terminals, ingress). `<host>` is the host id without its `hst_` prefix; the tunnel is named `nest-<host>` | A proxied CNAME to `<tunnel-id>.cfargotunnel.com`, created by the Worker at enrollment (with the tunnel and its ingress to `http://127.0.0.1:18790`) and deleted when the host dies. **No Worker route**, so a fetch from a Durable Object never re-enters the Worker | An Access application on `*-gw-nest.bitcru.sh` whose policy accepts the service token |
| `<port>-<sandbox>-preview-nest.bitcru.sh` | Previews ([ingress](../sandbox/networking/ingress/)) | Worker route `*-preview-nest.bitcru.sh/*` (**not built**: the name is minted, nothing serves it) | An Access application on `*-preview-nest.bitcru.sh` whose policy is me |
| `<port>-<sandbox>-share-nest.bitcru.sh` | Share links | Worker route `*-share-nest.bitcru.sh/*` (**not built**: the link is minted and signed, nothing serves or verifies it) | None; the Worker is to check the signed expiry |

The account holds tunnels that are not nest's. nest names its tunnels `nest-<host>` and its records `<host>-gw-nest.bitcru.sh`, and the Worker's cleanup and daily sweep delete only tunnels and records with those names, never anything else in the account or zone.

The shapes follow two rules: a Worker route's wildcard may only lead the hostname, never sit inside it ([routes](https://developers.cloudflare.com/workers/configuration/routing/routes/)), and an Access application's wildcard may stand for part of a label, one wildcard per label, spanning one level ([application paths](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/app-paths/)). So the kind of a name is its suffix, and the wildcard is its prefix.

## Stage 1: real Claude Code (no cloud, no KVM)

**Unlocks:** the checks against the real Claude Code binary (spike item 9) and the hands fidelity eval (item 10), run in the cloud dev environment.

| What | How | Environment variable |
|---|---|---|
| A Claude Pro or Max subscription | The one these agents will run on | — |
| A setup token | On a computer with a browser: install Claude Code, run `claude setup-token`, sign in. It prints a one-year token that can only make model requests ([docs](https://code.claude.com/docs/en/authentication)). | `NEST_CLAUDE_OAUTH_TOKEN` |
| (Optional) a second token | Run `claude setup-token` again, for captains | `NEST_CLAUDE_OAUTH_TOKEN_CAPTAIN` |
| Consent to spend quota | About 20 short turns on the cheapest model, plus one e2e turn | — |

Not `CLAUDE_CODE_OAUTH_TOKEN`: that name could change how the session's own Claude Code signs in.

**Then, in a new session on this branch:** "Run `e2e/claude-verify/run.py` and `NEST_E2E_CLAUDE=real e2e/run.sh`, and record the results in the verify list in `docs/README.md` and in the docs that own each item." See [e2e/README.md](../../e2e/README.md).

## Stage 3: sandbox hosts on AWS

**Unlocks:** real Firecracker sandboxes, and spike items 1–8, 11 and 12.

| What | How | Environment variable |
|---|---|---|
| An AWS account, ideally dedicated to nest | AWS Organizations → add an account, or a fresh account | — |
| A provisioning key | IAM → Users → create `nest-provisioner` with `AdministratorAccess` **in that account only** → Security credentials → create an access key | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |
| Region | From the decisions above | `AWS_REGION` |
| vCPU quotas | Service Quotas → EC2: raise **All Standard (A, C, D, H, I, M, R, T, Z) Spot Instance Requests** and **Running On-Demand Standard (…) instances** to at least 16 vCPUs. New accounts often start lower. | — |
| A budget alarm | Billing → Budgets → a monthly cost budget at the spend cap, emailing me | — |

The provisioning key creates the narrow credentials nest actually runs with:
- the cell's control-plane IAM user (`RunInstances` with the cell's two launch templates only; terminate and stop only instances tagged `nest=true`; `kms:Sign` and `kms:GetPublicKey` on the cell's proxy root CA key only), whose access key goes in the Worker secret `AWS_CELL_CREDENTIALS` under the cell's name ([cells](../compute/cells/));
- the hosts' instance roles, one per kind (a sandbox host's: the cell's bucket only; a brain host's: reading `releases/` only);
- **the proxy root CA key:** a KMS key (`ECC_NIST_P256`, sign and verify), which never leaves KMS. The cell stack creates it; FleetDO self-signs the cell's root certificate through KMS `Sign` the first time it is needed, and the guest image bakes it in, fetched from `GET /v1/admin/root-ca?cell=<cell>` ([tls](../sandbox/networking/egress/tls/)).

**The cell's resources** (VPC with public subnets and an S3 gateway endpoint, bucket, a security group, instance role and launch template per host kind, the control plane's IAM user) are one [inframe](https://github.com/by77er/inframe) stack per cell in [deploy/](../../deploy/), with OpenTofu state in a versioned S3 bucket. It creates no instances: FleetDO launches them.

**Prefer not to hand over an admin key?** The setup agent can write a CloudFormation template instead. Deploying it from the console creates the same resources, plus a narrower deploy key to provide in its place.

## Stage 4: brain hosts

**Unlocks:** brains on their own hosts, apart from sandboxes, and the two host kinds scaling apart. Done in `use1` (2026-10-29, [brain hosts](../compute/brain-hosts/)).

Nothing new to provide. Brain hosts live in the same account and cell, launched by FleetDO from a second launch template (no KVM; in S3 it may read the release, `releases/*`, only; the class from the decisions above). Claude Code comes with the host image and release; each brain's setup token comes from BrokerDO in its `agent_start`. The tunnel below is what lets them reach sandboxes, so stage 4 needs the domain and the tunnel credentials from the table below first.

## Generated, not provided

The setup agent creates these itself, so none are needed from me:
- **Control-plane secrets:** the operator tokens (`observe`, `approve`, `admin`; the Worker keeps only their SHA-256 hashes, and I get the tokens), `HOST_TOKEN_SECRET`, `REVOCATION_COUNTER`, and the root certificate from stage 3, all random or freshly generated (see [API](../control-plane/api/)). Built: one `ADMIN_TOKEN`; each cell's root key is in KMS and FleetDO self-signs the cell's root certificate through it.
- **`AWS_IDENTITY_CERT_PEM`:** AWS's public certificate for verifying instance identity documents, from AWS's docs.
- **Cloud resources:** the R2 bucket `nest-control`, the cell's S3 bucket with its gateway endpoint, the security group, the launch templates (sandbox hosts and brain hosts), the IAM pieces and KMS key above, and, per sandbox host, its tunnel and DNS record.
- **The binding key:** the per-cell key SandboxDO signs bindings with, generated by FleetDO and pushed to each sandbox host's gateway ([gateway](../sandbox/gateway/)).
- **Images:** the guest kernel and root filesystem, and the one host AMI for both kinds from the cell's Image Builder pipeline, with its per-kind bootstrap (Amazon Linux 2023, kernel 6.18, Firecracker from the 1.17 line pinned by digest, the pinned Claude Code baseline); see [provisioning](../compute/provisioning/).
- **Enrollment tokens** for hosts outside AWS.

## Cost while testing

- **Claude:** subscription quota only.
- **Cloudflare:** $5/month for Workers Paid; usage stays inside what's included.
- **AWS:**
  - a c8i.large spot sandbox host is about $0.03/hour, plus about $0.005/hour for its public IPv4;
  - a `t3a.medium` brain host is about $27/month on demand (unverified), less on spot, and it terminates 30 min after its last brain ([brain hosts](../compute/brain-hosts/));
  - S3 is cents;
  - the KMS root key is $1/month, plus $0.15 per 10,000 `Sign` calls (one per host enrollment or renewal; not in the free tier, [pricing](https://aws.amazon.com/kms/pricing/));
  - an idle cell costs nothing once its hosts terminate.

## Cleanup

- **Claude:** revoke the setup token(s). Where tokens are revoked isn't in the public docs (unverified); stage 1 checks it.
- **Cloudflare:** delete the API tokens; `wrangler delete` removes the Worker.
- **GitHub:** delete the App; its key goes with it. Revoke the `github_user` token if one was made.
- **AWS:** terminate every instance tagged `nest=true`, delete the stacks or resources, schedule the root CA key's deletion in KMS, and deactivate the `nest-provisioner` key. Closing a dedicated account removes everything.
- **Environment settings:** remove the variables.
