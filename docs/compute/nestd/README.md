# nestd

The per-host daemon. It's trusted, but it's fenced.

- **Both host kinds,** one binary; the config's `role` (written at bootstrap: [host kind](../provisioning/#host-kind); `burst`/`controller` this release, `sandbox`/`brain` read too) says which. On sandbox hosts it runs sandboxes and everything beside them; on [brain hosts](../brain-hosts/) it enrolls, holds the lease, delivers lifecycle commands to the [agent runner](../../agents/runner/) and self-fences, and nothing else: a brain host's config may name no driver, netns, S3 store, cloudflared or gateway URL (`Config::validate` refuses them at start), and nestd binds no proxy or gateway socket, sweeps no VM leftovers, asks for no proxy CA at enrollment, and refuses every sandbox command (`forbidden`, not retryable; `host_kind_refusal`). Brain commands are the same on both kinds this release: that a sandbox host never gets one is FleetDO's rule (`issueCommands`). Not built: a sandbox host refusing `agent_start` and binding no runner socket; it waits for the next release, because a Worker rolled back to the previous release still starts workers' brains on their sandbox's host ([deploy](../../../dev/deploy.md#host-role-names-expandcontract)). A sandbox host's enrollment answer must carry the proxy CA, or nestd fails the enrollment. nestd knows nothing about hands: a brain reaches a sandbox through the sandbox's [gateway](../../sandbox/gateway/), and the nestd ↔ runner link carries lifecycle only ([nestd-runner](../../interfaces/host-internal/nestd-runner/)).
- **Sandboxes:** runs them through [drivers](../../sandbox/drivers/), and sets up each one's netns (tap0, nft, **listening sockets handed to nest-proxy**), and (planned) its ublk daemon and UFFD handler. It boots a VM right after pushing the sandbox's policy and listeners to nest-proxy (waiting for an acknowledgement is designed, not built: [nestd-proxy](../../interfaces/host-internal/nestd-proxy/#policy-acknowledgement)), and it installs the root-namespace rule that rejects nest-proxy's non-public egress ([kernel backstop](../../sandbox/networking/egress/steering/#kernel-backstop)). See [../../sandbox/networking/egress/steering/](../../sandbox/networking/egress/steering/).
- **The gateway** (sandbox hosts): nestd is the source of truth for what the [gateway](../../sandbox/gateway/) may admit, over `/run/nest/gateway.sock` ([nestd-gateway](../../interfaces/host-internal/nestd-gateway/)). It mirrors the cell's binding verification keys (from FleetDO's `binding_key`) and, per sandbox, the epoch, the vsock socket, the attached clients and the guest's version; replays the mirror in full on every gateway connection. A sandbox is in the mirror only while it runs: boot and resume add it, the guest's hello and slot changes refresh it only while it is `running` (never a suspended one, so a paused VM is never reachable), suspend forgets it without a tombstone, and a fence tombstones its epoch so a late update can never re-add it (one tombstone map per host, which the gateway and nest-proxy links both consult; a create at a tombstoned epoch answers `stale_epoch`; a sandbox's tombstone goes when a newer epoch runs here or the sandbox is destroyed at or above it, the same lifetime as its `fenced` row). It drops a gateway that stays silent, or stops reading, for 15 s. The gateway connects in like nest-proxy does, as its own user: `sockets.gateway_uids` names that user, and `sockets.gateway_gid` its group, which owns `gateway.sock` and, once a VM has started, the VM's vsock socket (`0660`) and jail root (search only), so the gateway can dial the guest and nothing else of the VM ([gateway](../../sandbox/gateway/)). **Agent slots** are configured by the control plane's `agent_attach` and `agent_detach` commands (the proxy port, the guest slot, idempotent, a stale epoch refused; the guest round trip runs without the sandbox lock, and a fence that lands meanwhile answers `stale_epoch` and undoes the slot). An attach with no guest connection (suspended to disk) fails before it binds the proxy listener; a slot that never took is removed everywhere, including the slot set the guest connection re-sends in `configure`. The guest's hello is cached per sandbox and reported with every `running` and in the fleet hello.
- **cloudflared** (sandbox hosts): when the enrollment response carries a tunnel token and `cloudflared_bin` is configured, nestd keeps the token in its credentials file and runs `cloudflared --no-autoupdate tunnel --metrics 127.0.0.1:18791 run` as a child, as the `cloudflared_user` system user, with the token in the `TUNNEL_TOKEN` environment variable (never on a command line), logs its output, restarts it with a 1 s to 30 s backoff whenever it exits, and kills it at shutdown. Whether the tunnel serves is reported, not assumed: nestd polls cloudflared's `/ready` on the metrics address (`cloudflared_metrics`; 200 while cloudflared holds a connection to the edge, 503 before) every 2 s until ready and every 10 s after, and tells the control plane the tunnel's state (`none`, `connecting`, `connected`) in the fleet hello and as a `tunnel_state` event on every change, so the tunnel hostname is advertised only while it is served. The fleet hello's `gateway_url` still comes from configuration. Without a token (the harness, a brain host) nothing is started and the state is `none`.
- **Brains:** one table in the runner link (`runner_link.rs`), keyed by (agent, agent epoch): each start's state and the runner connection it went out on. It is what the fleet hello reports (each agent once); a fenced start leaves the report at once. `agent_started` marks its own epoch's entry; an exit removes the agent's entries at or below its epoch, never a newer start's (an event without an epoch, which only a runner of an older release sends, is dropped). A forwarded kill whose brain hasn't exited after 60 s drops the runner connection: the runner kills every brain on the host (sandboxes untouched), and their exits are reported. A graceful `agent_stop` names its epoch too, and stops only a start at or below it. An exit nestd reports at an epoch means no brain of the agent at or below it runs here. A sandbox fence never touches brains (a brain survives its sandbox moving): brains are fenced by the host lease and their agent epoch. `agent_stop{mode: kill}` is applied on arrival and its result reported at once; nestd remembers the highest killed agent epoch per agent, forwards the kill with its epoch (the runner keeps the same tombstone), and refuses a later `agent_start` at or below it (its `agent_exited{fenced}` follows once no older start of the agent is out here). A kill is answered with the brain's `agent_exited` at once only when no start at or below its epoch went out to the runner; otherwise the exit comes from the runner. nestd never replays a start: when the runner connection drops (the runner kills every brain), each start sent on it is reported `agent_exited{crashed}` at its epoch (or `fenced`, if already fenced), which AgentDO restarts with a current start. A start received while no runner is connected is sent once when one connects. A start never outlives a lease lapse: one that arrived before a lapse, or while lapsed, is refused (`agent_exited{fenced}` at its epoch) when the executor reaches it, even after a renewal, and the runner's fence of every brain also drops any start still waiting to register.
- **Pure cores:** the fleet link's decisions (and command dedup and the lease watchdog's) are a pure core in `crates/nestd-core`, model checked, proved and mutation-tested as shipped; `fleet.rs` is only its I/O shell ([verification](../../verification/nestd/)).
- **Privilege split:** nestd is the only privileged component. nest-proxy, the gateway and the agent runner run unprivileged.
- **Control plane connections:**
  - one control WebSocket to FleetDO, with a 5 s heartbeat that acts as the lease
  - on brain hosts, one WebSocket per active agent from the runner to its AgentDO, carrying the session stream
  - events batched every 1–2 s
- **Fleet channel resilience:**
  - **Liveness:** no inbound message for about 2.5 heartbeat intervals means the connection is presumed dead, and nestd reconnects.
  - **Commands strictly in order:** nestd forwards only the next command batch: from `hello_ack.next_command_seq` (FleetDO's baseline for the connection), then one past each forwarded batch. A batch that overtakes a lower one is a gap: nestd reconnects and the hello resends in order, so a later batch's ack never covers one that never ran. `last_command_seq` only rises, offline too ([fleet](../../interfaces/control-host/fleet/)).
  - **Retryable errors:** a retryable error from FleetDO also triggers a reconnect, which resends every unacknowledged batch.
  - **Bounded outbox:** audit batches are merged, and when the outbox overflows while offline, low-value events (audit, capacity, egress-denied, port-opened) are dropped first.
  - **Heartbeat timing:** heartbeat keys strictly increase, and the lease deadline is checked on both `CLOCK_MONOTONIC` and `CLOCK_BOOTTIME`, so a host waking from suspend notices that its lease has lapsed.
- **Stamps** sandbox and epoch on everything that comes from a guest.
- **Flushes before every cut:** today it asks the guest to `sync` (guest v1 `prepare_snapshot`, a failure ignored) and pauses the VM while it chunks the disk, telling the gateway first so binds get `busy` at once until the VM runs again ([nestd-gateway](../../interfaces/host-internal/nestd-gateway/)). Designed, not built: a guest `syncfs` with a 30 s budget, an `fsync` of the ublk device, then the disk epoch flip, with a failed flush failing the commit, pause or suspend ([disk](../../sandbox/state/disk/#flush-before-commit)).
- **Pending uploads** (designed, not built): frozen sets cut but not yet committed, per sandbox. A drain's list is all-or-nothing: if any entry can't be read, the whole answer is an error ([drain gate](../../control-plane/durable-objects/fleet/)).
- **Restore ABIs** (designed, with memory snapshots): compute the ABIs it can create and load from the bytes it runs (never from version strings) and advertise them in `hello` and `capacity` ([restore ABI](../../sandbox/state/memory/#restore-abi)).
- **Ingress guards** (with the gateway; designed, not built): counts each sandbox's in-flight responses and open WebSockets and terminals, and reports changes to SandboxDO as evidence. A stream whose client stops reading stops counting until it reads again, and stops for good after 2 h ([idle rule](../../control-plane/durable-objects/sandbox/#activity-and-idle)).
- **Idle re-check** (designed, not built): before a pause or suspend, re-checks running turns and ingress guards under the sandbox lock and answers `busy` rather than freezing work.
- **Disk rate limits** (designed, not built): set each drive's Firecracker rate limiter from the sandbox's limits ([I/O limits](../../sandbox/state/disk/#io-limits)).
- **Base generations** (designed, not built): prepare one in a scratch VM when FleetDO asks ([base generations](../../sandbox/state/memory/#base-generations)).
- **Self-fences** when its local lease expires. On a sandbox host: freezes and then stops the VMs (`Fenced` is terminal, so their memory goes back to the host; salvage reads only the disk), tells the proxy to drop their listeners, sends the gateway `sandbox_remove` for every sandbox (its open calls close with 4409) and removes their netns. On a brain host: stops the runner's brains. See [../../sandbox/fencing/](../../sandbox/fencing/).
- **Fencing doesn't wait on anything:**
  - `fence` commands take effect when they arrive, not behind slow commands.
  - `Fenced` is terminal for its epoch. A fenced incarnation keeps its disk until its salvage lands (then nestd deletes it, see retiring), and its `fenced` row until a `sandbox_destroy` at that (old) epoch or a newer epoch's create here.
  - VMs are paused through a pause handle that doesn't need the sandbox lock.
  - The link to nest-proxy never blocks: sends time out, and a ping watchdog catches a wedged proxy.
  - The sandbox lock is never held while waiting for a commit result.
- **Commits** are compare-and-set through SandboxDO, idempotent per request id. A commit whose answer timed out is kept, and the next commit on that sandbox first asks again under the same id and adopts the stored outcome (SandboxDO may have moved its head), so a lost answer never turns into a `parent_mismatch` that fences the sandbox.
- **Failed lifecycle steps leave nothing half-done:** a boot or cold resume that fails after creating its VM (the guest not up within `guest_ready_timeout_ms`, 60 s by default) stops that VM, so none runs unowned beside the next boot (a guest that refuses `resume`, its clock or RNG not reseeded, isn't ready: nestd reconnects and asks again until that timeout); a suspend that fails resumes the VM and reports `running` again, so SandboxDO can ask again, unless its commit was rejected (`stale_epoch`, `parent_mismatch`), which fences the incarnation instead (nothing resumes a sandbox stuck in `suspending`).
- **Per-sandbox rate limits** apply to everything a sandbox can make nestd emit: egress denials and alerts (deduplicated), audit records, port reports (merged), `nest` CLI relays (with a concurrency cap) and task exits. See `crates/nestd/src/limits.rs`.
- **Control sockets** (`proxy.sock`, `runner.sock`, `gateway.sock`, named by `nest_protocol::host::paths` under `run_dir`) carry secrets. They're mode `0660` with an optional group, the peer uid is checked with `SO_PEERCRED`, and only one peer is served at a time.
- **Restarts:** each incarnation (a sandbox at one epoch) has its own directories, `<state_dir>/sandboxes/<sandbox>/<epoch>/` (disk, snapshot, `meta.json`) and `<run_dir>/vm/<sandbox>/<epoch>/`, so incarnations never share a file: a newer epoch's create never waits on, or overwrites, an older one here. `meta.json` (versioned) names the incarnation and the head its disk matches, says whether no VM has written to the disk since it last matched that head, or since it was made from the base image (set when the disk is complete and when a commit lands with no VM running on it, as after a suspend; cleared, durably, before a VM runs on it again), and records a commit request until its answer arrives. It is written atomically, first once the disk is complete and synced, then after every commit. An incarnation is deleted by renaming it to `<epoch>.del` first, which a scan finishes off, so a crash never leaves a half-deleted one that `meta.json` still names. A disk a VM has run on can't cheaply be told apart from its base, so one with no head is salvaged (as a sibling, or as the head if this host still holds the epoch). A starting nestd, before its first fleet hello: kills every VM process the old one left (below), tears down every `ns-sbx_*` netns bind mount under `persist_dir` (deleting `tap0` and the `inet nest` table inside first), and removes the VM runtime directories and stale jails. Then it scans the incarnations: a clean one (no VM has written to it, nothing unanswered) is deleted unreported, so the control plane evicts a suspended sandbox and wakes it from its head as before; every other one becomes a `fenced` row (reported in the hello, no lease claimed, its epoch tombstoned) and is retired. An incarnation directory whose `meta.json` is missing or not valid JSON (a disk still being prepared) is removed, never guessed at, and so is the flat `sandboxes/<sandbox>/disk.img` of a nestd from before per-epoch directories (it had no `meta.json` either, so its uncommitted work is not salvaged: the control plane re-placed it from head anyway); one whose `meta.json` can't be read otherwise, or has another version, is kept and logged.
- **Retiring an incarnation** (fenced, superseded by a newer create here, or found at start): salvage it as a sibling branch if it may hold work (nothing to commit when the disk equals its head's disk, whatever the head's memory), asking first under any unanswered request id (persisted, so this holds across restarts too; a final refusal of an unanswered request that wasn't a salvage doesn't end it: the salvage follows). A transient failure (a timeout, a store error, `parent_mismatch`, anything retryable) keeps the disk and is retried with backoff (1 s doubling to 5 min) until it lands or a destroy removes the directory; a final refusal (`stale_epoch`, `invalid_message`: SandboxDO will never take that work) is logged with the error and ends it. Then its directories are deleted, its `fenced` row (while still that epoch's) marked clean, and `incarnation_retired` reported, so FleetDO need not wait out the salvage window. Once per incarnation; nothing it hears touches a newer incarnation: rows are only updated, and sandboxes only fenced, at their own epoch (`fence_sandbox` takes the epoch and checks it under the summary lock), and lock-free pause handles are kept per incarnation, so an older epoch's late fence task never takes a newer one's.
- **Housekeeping:** renews nest-proxy's intermediate CA (new key and CSR) when less than 48 h remain, and reports `capacity` when it changes (at least every 10 min).
- **Spot interruptions:** polls IMDS `spot/instance-action` every 5 s and reports `spot_notice`; FleetDO then suspends the host's sandboxes ([autoscaling](../autoscaling/)). Planned: cut every disk first, then a prioritized checkpoint and commit ([spot notice](../../sandbox/state/#spot-notice-2-minutes)).
- **Process supervision:** no VM outlives nestd. The process driver's guests, an unjailed Firecracker and the jailer are forked by one long-lived spawner thread with `PR_SET_PDEATHSIG=SIGKILL` (the child enters the sandbox netns itself, before exec; nestd aborts if that thread ever ends) and recorded in a pidfile (pid and start time). Each child resets `oom_score_adj` to 0 before exec, so it doesn't inherit nestd's -900 and the kernel kills a guest VMM, never nestd, under memory pressure. The jailer drops its uid, which clears the death signal, so jailed VMMs are covered by cgroups: with `delegated_cgroup` (the unit has `Delegate=yes`), nestd moves itself into `<unit>/supervisor` first thing in `main`, before its runtime starts a thread, and starts each VMM under `<unit>/vms` (`--parent-cgroup`), so the unit's stop, a crash restart included, kills them all; without it they sit under the jailer's default parent, outside the unit. A delegation that fails never stops nestd: it runs with the default parent and reports `cgroup_delegation_error` in every fleet hello. A stopped VMM's cgroup is removed once it has exited. Either way a starting nestd first kills every `sbx-*` VMM cgroup under both parents (`cgroup.kill`, waiting for each to empty) and every process its pidfiles still name (through a pidfd, after re-checking the start time, so a reused pid is never hit). **Unverified on a real host** (the delegated layout and `cgroup.kill` are tested only against a fake cgroup directory). **Planned:** `WatchdogSec` on nestd. The delegated cgroup and the start-up kill are unverified on an EC2 host (AL2023's systemd 252, the jailer's `--parent-cgroup`).
- **Credentials:** S3 access comes from the instance role. nestd has no R2 credentials; it reads R2 only through Worker-signed URLs from DOs.
- **Guest memory is regular pages** (`huge_pages` defaults to `false`): a VM costs what it touches. The jailer caps each VMM's cgroup (`--cgroup-version 2 --cgroup memory.max=`) at the declared memory plus `vm_memory_overhead_mib` (128), and the capacity report carries `MemAvailable` (`memory_mib_free`) and the hugepage pool's size (`hugepages_mib_total`, 0 here), which is how the control plane packs ([memory](../../sandbox/state/memory/)).
- **Runs alongside** [nest-proxy](../../sandbox/networking/egress/), cloudflared and the [gateway](../../sandbox/gateway/) on sandbox hosts, and the agent runner on brain hosts.
