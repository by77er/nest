# nestd

The per-host daemon. It's trusted, but it's fenced.

- **Both host kinds.** On sandbox hosts it runs sandboxes and everything beside them; on [brain hosts](../brain-hosts/) it enrolls, holds the lease, delivers lifecycle commands to the [agent runner](../../agents/runner/) and self-fences. nestd knows nothing about hands: a brain reaches a sandbox through the sandbox's [gateway](../../sandbox/gateway/), and the nestd ↔ runner link carries lifecycle only ([nestd-runner](../../interfaces/host-internal/nestd-runner/)).
- **Sandboxes:** runs them through [drivers](../../sandbox/drivers/), and sets up each one's netns (tap0, nft, **listening sockets handed to nest-proxy**), and (planned) its ublk daemon and UFFD handler. It boots a VM right after pushing the sandbox's policy and listeners to nest-proxy (waiting for an acknowledgement is designed, not built: [nestd-proxy](../../interfaces/host-internal/nestd-proxy/#policy-acknowledgement)), and it installs the root-namespace rule that rejects nest-proxy's non-public egress ([kernel backstop](../../sandbox/networking/egress/steering/#kernel-backstop)). See [../../sandbox/networking/egress/steering/](../../sandbox/networking/egress/steering/).
- **The gateway** (sandbox hosts): nestd is the source of truth for what the [gateway](../../sandbox/gateway/) may admit, over `/run/nest/gateway.sock` ([nestd-gateway](../../interfaces/host-internal/nestd-gateway/)). It mirrors the cell's binding verification keys (from FleetDO's `binding_key`) and, per sandbox, the epoch, the vsock socket, the attached clients and the guest's version; replays the mirror in full on every gateway connection. A sandbox is in the mirror only while it runs: boot and resume add it, the guest's hello and slot changes refresh it only while it is `running` (never a suspended one, so a paused VM is never reachable), suspend forgets it without a tombstone, and a fence tombstones its epoch so a late update can never re-add it. It drops a gateway that stays silent, or stops reading, for 15 s. The gateway connects in like nest-proxy does. **Agent slots** are configured by the control plane's `agent_attach` and `agent_detach` commands (the proxy port, the guest slot, idempotent, a stale epoch refused; the guest round trip runs without the sandbox lock, and a fence that lands meanwhile answers `stale_epoch` and undoes the slot). An attach with no guest connection (suspended to disk) fails before it binds the proxy listener; a slot that never took is removed everywhere, including the slot set the guest connection re-sends in `configure`. The guest's hello is cached per sandbox and reported with every `running` and in the fleet hello. **Not built:** `gateway_uids` and an unprivileged gateway user in the host install (the unit runs the gateway as root).
- **cloudflared** (sandbox hosts): when the enrollment response carries a tunnel token and `cloudflared_bin` is configured, nestd keeps the token in its credentials file and runs `cloudflared --no-autoupdate tunnel --metrics 127.0.0.1:18791 run` as a child, as the `cloudflared_user` system user, with the token in the `TUNNEL_TOKEN` environment variable (never on a command line), logs its output, restarts it with a 1 s to 30 s backoff whenever it exits, and kills it at shutdown. Whether the tunnel serves is reported, not assumed: nestd polls cloudflared's `/ready` on the metrics address (`cloudflared_metrics`; 200 while cloudflared holds a connection to the edge, 503 before) every 2 s until ready and every 10 s after, and tells the control plane the tunnel's state (`none`, `connecting`, `connected`) in the fleet hello and as a `tunnel_state` event on every change, so the tunnel hostname is advertised only while it is served. The fleet hello's `gateway_url` still comes from configuration. Without a token (the harness, a brain host) nothing is started and the state is `none`.
- **Brains:** one table in the runner link (`runner_link.rs`): each brain's hands binding, state, and the runner connection its `agent_start` went out on. It is what the fleet hello reports and what a sandbox fence looks up; a fenced brain leaves the report at once. nestd never replays a start: when the runner connection drops (the runner kills every brain), each brain started on it is reported `agent_exited{crashed}` (or `fenced`, if already fenced), which AgentDO restarts with a current start. A start received while no runner is connected is sent once when one connects.
- **Privilege split:** nestd is the only privileged component. nest-proxy, the gateway and the agent runner run unprivileged.
- **Control plane connections:**
  - one control WebSocket to FleetDO, with a 5 s heartbeat that acts as the lease
  - on brain hosts, one WebSocket per active agent from the runner to its AgentDO, carrying the session stream
  - events batched every 1–2 s
- **Fleet channel resilience:**
  - **Liveness:** no inbound message for about 2.5 heartbeat intervals means the connection is presumed dead, and nestd reconnects.
  - **Retryable errors:** a retryable error from FleetDO also triggers a reconnect, which resends every unacknowledged batch.
  - **Bounded outbox:** audit batches are merged, and when the outbox overflows while offline, low-value events (audit, capacity, egress-denied, port-opened) are dropped first.
  - **Heartbeat timing:** heartbeat keys strictly increase, and the lease deadline is checked on both `CLOCK_MONOTONIC` and `CLOCK_BOOTTIME`, so a host waking from suspend notices that its lease has lapsed.
- **Stamps** sandbox and epoch on everything that comes from a guest.
- **Flushes before every cut:** asks the guest agent to `syncfs` (30 s budget), `fsync`s the ublk device, then flips the disk epoch. A failed flush fails the commit, pause or suspend ([disk](../../sandbox/state/disk/#flush-before-commit)).
- **Pending uploads:** frozen sets cut but not yet committed, per sandbox. A drain's list is all-or-nothing: if any entry can't be read, the whole answer is an error ([drain gate](../../control-plane/durable-objects/fleet/)).
- **Restore ABIs:** computes the ABIs it can create and load from the bytes it runs (never from version strings) and advertises them in `hello` and `capacity` ([restore ABI](../../sandbox/state/memory/#restore-abi)).
- **Ingress guards** (with the gateway): counts each sandbox's in-flight responses and open WebSockets and terminals, and reports changes to SandboxDO as evidence. A stream whose client stops reading stops counting until it reads again, and stops for good after 2 h ([idle rule](../../control-plane/durable-objects/sandbox/#activity-and-idle)).
- **Idle re-check:** before a pause or suspend, re-checks running turns and ingress guards under the sandbox lock and answers `busy` rather than freezing work.
- **Disk rate limits:** sets each drive's Firecracker rate limiter from the sandbox's limits ([I/O limits](../../sandbox/state/disk/#io-limits)).
- **Base generations:** prepares one in a scratch VM when FleetDO asks ([base generations](../../sandbox/state/memory/#base-generations)).
- **Self-fences** when its local lease expires. On a sandbox host: freezes and then stops the VMs (`Fenced` is terminal, so their memory goes back to the host; salvage reads only the disk), tells the proxy to drop their listeners, sends the gateway `sandbox_remove` for every sandbox (its open calls close with 4409) and removes their netns. On a brain host: stops the runner's brains. See [../../sandbox/fencing/](../../sandbox/fencing/).
- **Fencing doesn't wait on anything:**
  - `fence` commands take effect when they arrive, not behind slow commands.
  - `Fenced` is terminal for its epoch. A fenced incarnation keeps only its disk and its `fenced` row, until a `sandbox_destroy` at that (old) epoch removes both, or a newer epoch's create reuses the sandbox here.
  - VMs are paused through a pause handle that doesn't need the sandbox lock.
  - The link to nest-proxy never blocks: sends time out, and a ping watchdog catches a wedged proxy.
  - **The sandbox owns its listeners;** the proxy mirror follows it. A listener nest-proxy reports failed is rebound under the sandbox lock, only if that incarnation still has it, at most 3 times in 10 minutes. A lost DNS or transparent HTTP(S) listener fences the incarnation (no egress at all otherwise); a lost TCP exception or explicit proxy listener raises a `blocked` workstream event ([nestd-proxy](../../interfaces/host-internal/nestd-proxy/)).
  - The sandbox lock is never held while waiting for a commit result.
- **Commits** are compare-and-set through SandboxDO, idempotent per request id. A commit whose answer timed out is kept, and the next commit on that sandbox first asks again under the same id and adopts the stored outcome (SandboxDO may have moved its head), so a lost answer never turns into a `parent_mismatch` that fences the sandbox.
- **Per-sandbox rate limits** apply to everything a sandbox can make nestd emit: egress policy denials and alerts (nest-proxy aggregates them; nestd only rate-limits), audit records, port reports (merged), `nest` CLI relays (with a concurrency cap) and task exits. See `crates/nestd/src/limits.rs`.
- **Control sockets** (`proxy.sock`, `runner.sock`, `gateway.sock`, named by `nest_protocol::host::paths` under `run_dir`) carry secrets. They're mode `0660` with an optional group, the peer uid is checked with `SO_PEERCRED`, and only one peer is served at a time.
- **Housekeeping:** renews nest-proxy's intermediate CA (new key and CSR) when less than 48 h remain, and reports `capacity` when it changes (at least every 10 min).
- **Spot interruptions** (planned): poll instance metadata for the 2-minute notice, then cut every disk and run a prioritized checkpoint and commit ([spot notice](../../sandbox/state/#spot-notice-2-minutes)).
- **Process supervision** (planned): VMs in systemd scopes with `BindsTo=nestd`, and `WatchdogSec` on nestd, so if nestd dies its VMs die with it.
- **Credentials:** S3 access comes from the instance role. nestd has no R2 credentials; it reads R2 only through Worker-signed URLs from DOs.
- **Guest memory is regular pages** (`huge_pages` defaults to `false`): a VM costs what it touches. The jailer caps each VMM's cgroup (`--cgroup-version 2 --cgroup memory.max=`) at the declared memory plus `vm_memory_overhead_mib` (128), and the capacity report carries `MemAvailable` (`memory_mib_free`) and the hugepage pool's size (`hugepages_mib_total`, 0 here), which is how the control plane packs ([memory](../../sandbox/state/memory/)).
- **Runs alongside** [nest-proxy](../../sandbox/networking/egress/), cloudflared and the [gateway](../../sandbox/gateway/) on sandbox hosts, and the agent runner on brain hosts.
