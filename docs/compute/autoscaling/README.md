# Autoscaling and spot

- **Scale to zero.** FleetDO launches hosts only when there's runnable work queued. **Built** for burst hosts (`AWS_CELLS`, [control plane](../../../control-plane/README.md)): a sandbox no connected host can take launches one spot host from the cell's launch template (each instance type on spot, then the first on demand), unless a launch is pending or the cell is at `max_hosts`; a launched host that holds no lease and no agent for `idle_grace_ms` (10 min) is marked dead, then terminated; a launch that hasn't enrolled within `enroll_timeout_ms` is terminated. Verified on EC2 (use1, 2026-10-17): a sandbox with no host launched a spot `c8i.large`/`c8i-flex.large` within 15 s of a placement retry; it enrolled about 30 s after boot and took the sandbox; after the sandbox was deleted the host was retired at the idle grace (3 min in the test) and terminated 20 s later, leaving the cell at zero. Suspended sandboxes don't keep a host up: a retired host's suspended sandboxes are evicted (lease dropped; their head is in S3) and wake lazily elsewhere. Not built: EC2 Fleet, and gentle drains for consolidation.
- **EC2 Fleet** spot requests across the 8i family (C8i, M8i, R8i, preferring `d` variants) with the **price-capacity-optimized** allocation strategy, as AWS recommends ([docs](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-fleet-allocation-strategy.html)), falling back to on-demand.
- **Idle grace:** keep a host N minutes after its last activity so conversations with several turns stay fast.
- **Pack, then consolidate:** placement fills hosts before opening new ones (see [FleetDO](../../control-plane/durable-objects/fleet/)), so idle hosts empty out. A host that's emptying is drained gently, then terminated.
- **Drain:** stop placing on the host, suspend its sandboxes to S3, then terminate it once FleetDO's [drain gate](../../control-plane/durable-objects/fleet/) passes (every resident's head is the host's last commit, and no upload is pending).
  - **Gentle** (consolidation, upgrades): residents keep running and suspend at their next idle point, under the usual [idle rule](../../control-plane/durable-objects/sandbox/#activity-and-idle). After 30 min the drain turns forced.
  - **Forced** (spot notices): suspend every resident now. One that was busy (an agent mid-turn, an ingress guard or a hold) is placed elsewhere at once; the rest wait until something needs them. **Built:** nestd polls IMDS `spot/instance-action` every 5 s and reports `spot_notice`; FleetDO stops placing on the host, suspends its running sandboxes and evicts each as it reports `suspended`; a sandbox with an agent mid-turn is placed again at once (ingress guards and holds aren't known to the control plane yet). A draining host doesn't count toward `max_hosts`, and one with no leases left is terminated. Verified on EC2 (use1, 2026-10-17, an AWS FIS spot interruption with 2 min notice on a host running a real Claude Code agent mid-turn in a 4-min Bash loop): the sandbox was suspended to S3 and evicted within 35 s of the notice, a replacement launched at once and enrolled about 35 s later, the sandbox was restored there from S3 under epoch 2 about 90 s after the notice, and the agent resumed with its interrupted turn re-queued as a recovery turn, re-ran the command and finished. Afterwards it suspended 4 min after the agent went idle (the test setting), the host was retired 3 min later, and a new turn woke it from zero hosts: running again in about 66 s. With the process driver only the S3 path is exercised (the guest doesn't write to the disk image), not file contents.
  - **Moves keep state:** a paused sandbox is snapshotted as it is, without running again, and a move keeps memory unless no host could load it (an [ABI-changing upgrade](../provisioning/#upgrades)).
  - **Size:** each host is capped so a forced drain finishes in about 90 s at its measured upload bandwidth, inside the 2-minute spot notice.
- **Moves are checkpoint and restore,** like every sandbox provider; no one offers live migration.
- **Optional stopped warm host:** a stopped instance with the image already on disk, costing about $2/mo for EBS. Starting it is faster than a fresh launch. (Auto Scaling warm pools can't use spot in mixed-instance groups; [docs](https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-warm-pools.html).)
- **Spot interruption** gives 2 minutes' notice. See [../../sandbox/state/](../../sandbox/state/).
- **The controller host is never scaled.** It's replaced if it fails.
