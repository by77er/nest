# Credentials inventory

| Credential | Stored | Seen by | Notes |
|---|---|---|---|
| Claude setup token (subscription OAuth, 1 year, model requests only) | BrokerDO | Claude Code process env on brain hosts only, **never a sandbox host, never a VM** | Separate named tokens per template, e.g. captains vs workers (to verify that they're independent and revocable). FleetDO never sends a sandbox host a brain; for one release sandbox hosts keep the runner installed, for a rollback ([deploy](../../../dev/deploy.md#host-role-names-expandcontract)) |
| GitHub App id and private key | BrokerDO (`github_app`, JSON `{app_id, private_key}`, `PUT /v1/admin/secrets/github_app`) | Control plane (BrokerDO signs the App's JWT) | Mints installation tokens per binding (1 hour, narrowed to the binding's repos and permissions); every mint is audited; see [BrokerDO](../../control-plane/durable-objects/broker/). Built for brokered actions |
| GitHub installation tokens | nest-proxy memory (sandbox injection, not built); BrokerDO (`github_tokens`, reused for 50 minutes) and AgentDO memory for one brokered call | Proxy only; the control plane for brokered actions | Injected by placeholder, on the binding's exact hosts, methods and path. A brokered action's token names one repo and that action's permissions ([brokered](../../agents/capabilities/brokered/#github-permissions)) |
| Other injected secrets | BrokerDO → nest-proxy memory | Proxy only | Per host and grant. Pushed with the policy hash; the proxy refuses one whose binding isn't in the installed policy. Every push and refusal is audited |
| Brokered-action secrets (`http:<name>` for an http profile; email, …) | BrokerDO | Control plane only (AgentDO attaches it to the profile's request), never a VM | Executed outside the VM; a reflected value is masked in the answer; never resolvable into a host command |
| Proxy root CA key (per cell) | AWS KMS (`ECC_NIST_P256`, non-exportable) | Nobody: the cell's FleetDO calls `kms:Sign` | Signs per-host intermediates at enrollment and renewal; CloudTrail logs each issuance; the root certificate, derived from the key by FleetDO, is in the cell's image. See [tls](../../sandbox/networking/egress/tls/) |
| Per-host intermediate CA (~7 days, pathLen 0) | nest-proxy memory; the key is generated on the host | Proxy | Signs leaf certificates (≤ 24 h) on the fly |
| OIDC signing key (deferred) | Worker secret | Control plane | JWKS published |
| Host token | FleetDO issues it; nestd and the runner hold it in memory | Host | Obtained with the signed identity document; rotated; void when the [revocation counter](../../control-plane/api/) moves |
| Binding key (per cell) | BrokerDO (`binding_key:<cell>`, the private key); FleetDO pushes the public keys to each sandbox host's gateway over the fleet channel | BrokerDO (signs bindings for SandboxDO), the gateway (verifies) | Bindings are verified, never stored; an epoch bump voids them. See [gateway](../../sandbox/gateway/) |
| Bindings (sandbox, epoch, client, scope, about an hour) | Nowhere: signed tokens | The runner or `nest` CLI that holds one, the gateway | Minted by SandboxDO's `resolve` for an attached client (resolved again before expiry), revoked by `detach` and by any epoch bump |
| Cloudflare Tunnel API token (Account: Cloudflare One Connector: cloudflared → Edit, Zone: DNS: Edit) | A secret on the GitHub `production` environment, written to the Worker as the secret `CLOUDFLARE_TUNNEL_API_TOKEN` at deploy | Control plane only | Creates and deletes one tunnel and one DNS record per sandbox host; sweeps leaks daily. See [gateway](../../sandbox/gateway/) |
| Per-host tunnel token | The Worker creates it at enrollment and returns it in the enrollment response; nestd keeps it in its credentials file (`0600`) and in cloudflared's process environment, never on a command line | Sandbox host | Names one tunnel; deleted with the host |
| Access service token (`access:gateway`) | BrokerDO, stored through `PUT /v1/admin/secrets/access:gateway` | SandboxDO puts it as `edge` in the hands target of every host whose tunnel is connected, never in a direct target, so a runner holds it in memory for the connection; **never a sandbox**; not built: the `nest` CLI through a login | The edge check in front of every gateway hostname |
| Operator tokens (`observe`, `approve`, `admin`) | SHA-256 hashes only, as a Worker secret | Me (`nest` CLI) | Scoped; header only, never in URLs. Not built: today one `ADMIN_TOKEN` Worker secret. See [API](../../control-plane/api/) |
| Admin token, the dashboard's copy | The GitHub `production` secret `NEST_ADMIN_TOKEN`, written to the `nest-dashboard` Worker as a secret at its deploy | The dashboard Worker only; never the page | Full admin, used for two GETs. The Worker answers nothing without a valid Cloudflare Access token for the dashboard's application (`Cf-Access-Jwt-Assertion`, RS256 against the team's keys). Rotating the admin token takes two writes. See [dashboard](../../control-plane/dashboard/) |
| Cloudflare Workers deploy token (Workers edit) | GitHub `production` secret `CLOUDFLARE_API_TOKEN` | `deploy.yml` (control plane) and `deploy-dashboard.yml` | A second token, apart from mine, so GitHub's copy can be revoked on its own ([dev/setup](../../../dev/setup.md)) |
| Cloudflare Access token (Account › Access: Apps and Policies › Edit) | GitHub `production` secret `CLOUDFLARE_ACCESS_API_TOKEN` | `deploy.yml`'s infra job, for the `edge` stack | Manages the Access applications in front of the gateways, the dashboard and previews |
| AWS: deploy role (`nest-<cell>-deploy`) | Nothing stored: assumed over GitHub OIDC | `deploy.yml` jobs in the `production` environment | Administrator-equivalent (applying the stack manages IAM); its trust policy admits only this repo's `production` environment ([dev/deploy](../../../dev/deploy.md)) |
| AWS: host roles | Instance profile, one per host kind | nestd (nest-proxy is kernel-blocked from IMDS) | Sandbox hosts: S3 for their whole cell (below). Brain hosts: read the release (`releases/*`) only ([brain hosts](../../compute/brain-hosts/)) |
| AWS: control plane (per cell, `nest-<cell>-control-plane`) | Worker secret `AWS_CELL_CREDENTIALS`, keyed by cell; a cell without an entry has no AWS access | That cell's FleetDO | The cell's launch template only; terminate/stop only instances tagged `nest=true`; `kms:Sign` and `kms:GetPublicKey` on the cell's proxy root CA key only. The operator view names each cell's source, never the key. See [cells](../../compute/cells/) |
| R2 | DO bindings | Control plane | Hosts use Worker-signed URLs only (no R2 S3 credentials exist) |
| Webhook secrets (`hook:<hk_…>`) | BrokerDO | Control plane only | BrokerDO verifies signatures itself; brokered actions send the secret straight to the provider |
| MCP server and API credentials (`cap:<name>`) | BrokerDO | Control plane only | One per `mcp` or `api` capability; attached per call |
| MCP OAuth tokens (access and refresh, per `auth.oauth` record) | BrokerDO's `oauth_grants`, never `secrets` | Refresh token: BrokerDO only. Access token: AgentDO's memory, for the requests to the one server it was issued for | Obtained by the operator's authorization; refreshed by BrokerDO, one refresh at a time; a refused refresh clears both and the capability needs authorizing again. See [mcp OAuth](../../agents/capabilities/mcp/#oauth) |
| MCP OAuth client: a pre-registered client's secret (`cap:<name>`), or a registration (RFC 7591) | BrokerDO (`secrets`, or `oauth_clients`) | BrokerDO only, sent to the token endpoint | nest's client ID metadata document (`/v1/oauth/client.json`) is public and holds no secret |
| api-loop API key (deferred) | BrokerDO | Control plane only | For the `api-loop` backend, once the API credits are picked up |
| Cloudflare Analytics read token | BrokerDO (`cap:metrics`) | Control plane only | Account Analytics Read only; see [metrics](../../control-plane/metrics/) |

**S3 access is a cell-wide host role, not per-sandbox STS credentials.** Hosts are trusted and fenced, and nest has a single owner, so there's no tenant to isolate from another. Per-sandbox credentials would gain nothing if the host minted them (it would still hold the cell role), and the control plane deliberately holds no S3 access to mint them with.
