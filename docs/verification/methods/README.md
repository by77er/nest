# Verification methods

Which formal method or tool fits which part of nest, what it costs, how a spec stays in sync with the code, and which past bugs each would have caught. Evaluated on 2026-10-25 against `main` at `edf6829`. Every tool marked "ran" was installed without root and run on a toy nest model in a scratch directory. Nothing was added to the repo or to CI.

## Decision

| Need | Tool | Why |
|---|---|---|
| Protocol models (placement, leases, epochs and fencing, STONITH, one brain per agent, reliable channels, commit chain and GC) | **Quint** was this survey's pick: random simulation in CI, bounded checks with Apalache (`quint verify`). **Superseded by the pilots: TLA+ with TLC** ([recommendation](../README.md#recommendation)) | Quint: typed, code-like syntax and `--mbt` ITF traces for conformance. The pilots then ran TLA+ exhaustively, with liveness, and found every reported bug; Quint's exhaustive and liveness path is the TLA+ export anyway |
| Spec-to-code conformance | **Model-based testing**: Quint ITF traces replayed against the real DOs in vitest (workerd), and against nestd's state machines through `quint-connect` | It checks the code itself, not a copy of it. Drift fails the build mechanically. MongoDB found test-case generation worked where trace checking didn't |
| Await interleavings in the TS Durable Objects | **fast-check** `fc.scheduler` and `fc.commands` (`scheduledModelRun`), in vitest | The bugs come from awaits inside one object (re-check after an await, re-entrant cross-DO calls). It runs in the existing vitest suite |
| Tokio concurrency inside nestd and the gateway | **shuttle** with its `shuttle-tokio` wrapper. **loom** only for small synchronisation primitives | Randomised scheduling scales to real task graphs. loom is exhaustive but suits small tests |
| Pure Rust decision functions (seq dedup, meta.json recovery, `isRestoreSource`-style predicates) | **Kani** | Proves a property for all inputs up to a bound, in seconds, without a model |
| Lean | Keep it for infra theorems. Add proofs only for pure, data-shaped kernels (GC mark covers every restore source, grants only shrink, binding claim checks) | The toolchain is already pinned. Lean has no model checker, and LLMs prove Lean far less reliably than they write Dafny (see costs) |

## What nest's runtime implies

- **Durable Objects interleave at awaits.** The input gate holds events only while a *storage* operation is pending ([glossary](https://developers.cloudflare.com/durable-objects/glossary), [Cloudflare 2021](https://blog.cloudflare.com/durable-objects-easy-fast-correct-choose-three/)). A cross-DO RPC or a `fetch` lets other requests in. Neither page says this outright, so treat it as inferred from the rule's scope. This is the class behind the cross-DO deadlock and the missing "re-check after await" in `65bf6ef`. A protocol model sees it only if every await is a separate step. fast-check sees it if the await is routed through `fc.scheduler`.
- **Objects can be reset mid-call, and hosts restart.** Every model needs a `crash` action that keeps the durable variables (SQLite, S3) and drops the volatile ones (memory, sockets, timers). Lesson 4 (restarts read only what is durable) is exactly that invariant.
- **Mixed versions are normal.** "Wire formats are compatible one version back" becomes a model with a version variable per component and both versions' handlers enabled.

## Conformance: keeping specs and code in sync

| Approach | Shape in nest | Catches drift? | Cost | Verdict |
|---|---|---|---|---|
| (a) Trace checking / validation | e2e and vitest runs log DO decisions as JSON lines; TLC or Apalache checks that each log is a behaviour of the spec | Yes, for the runs logged | Instrumenting every DO and host, mapping partial observations onto spec states, and TLC's trace-validation features (documented mostly in PRs). MongoDB's 2020 attempt failed because the spec was abstract and written after the code; CCF made it work after "months" of alignment | Phase 2, once the specs exist and match the code |
| (b) Model-based testing from the model | `quint run --mbt --out-itf` → a vitest replay harness drives the real DO step by step, then compares a projection of its SQLite with the ITF state. `quint-connect` does the same for Rust state machines | Yes: an action without a driver, or a diverging state, fails | One driver per DO (estimate: 100–200 lines), plus a projection function | **Recommended** |
| (c) Refinement proofs (Lean, Ivy, Veil) | Prove the DO code refines the model | Yes, completely | It would need TS semantics in Lean, or a rewrite. Person-months per protocol (estimate) | No |
| (d) Runtime assertions | Invariants (`epoch` monotone, head moves only by CAS at the current epoch) asserted in DO code: they throw in tests and count a metric in production | Partly: they check states, not transitions | Low | Yes, as a complement |

**Recommended shape: an ITF replay harness per protocol.**
1. Quint actions are named after the DO handler or wire event they model (`claim`, `commit`, `leaseLost`, `hello`, `fence`), and their parameters are the handler's arguments.
2. `test/mbt/<protocol>.mbt.test.ts` reads N traces generated in CI (seeded). For each step, it calls the real DO through its stub in workerd (`runInDurableObject` for reads), feeding host messages from `protocol/fixtures` shapes. After the step, it asserts `project(state) == itfState`.
3. The driver map is exhaustive in both directions: an unknown `actionTaken` fails, and a driver with no spec action fails. A PR that changes a DO's handler set therefore cannot pass without touching the spec. This makes drift a red build, not a review judgement.
4. Rust gets the same through `quint-connect` for nestd's pure cores (the fleet link's dedup and resend, incarnation recovery), with Kani for their decision functions.
5. Later: emit the same action names as structured logs from e2e, for CCF-style trace validation of real multi-process runs.

Lesson 8 still applies: the harness must drive the real DO with the platform's own bindings. A fake collaborator in the replay hides exactly the binding bugs that MBT can't model.

## Costs

| Tool | Learning curve | Spec size per protocol | Checker runtime | CI time (estimate) | Drift risk | Who maintains |
|---|---|---|---|---|---|---|
| Quint + MBT | Days (code-like) | 150–500 lines (estimate; AWS's TLA+ specs were 102–939 lines) | Simulation: seconds. Apalache bounded: tens of seconds to minutes | 1–3 min per protocol | Low with the exhaustive driver map | The PR author (an agent) updates the spec and driver; the reviewer checks the invariants |
| TLA+ / TLC | 2–3 weeks (AWS) | As above | Exhaustive: minutes to hours depending on bounds | Must be bounded to fit a job | High without (a) or (b) | Harder for agents: an NL-to-TLA+ study found best semantic correctness of 8.6% |
| P | Days for actor-minded engineers | Similar | Minutes | Adds a .NET job | Medium (PObserve exists) | A third language |
| Alloy 6 | Days | 20–100 lines per structural property | Seconds | Under 1 min | Medium (a separate model) | Narrow use |
| Ivy | Weeks (EPR modelling) | 50–300 lines | Seconds when the invariant is inductive | Under 1 min | High | Specialist |
| Lean proofs | Weeks; proof repair on every model change | 20 lines (toy) to thousands | Compile time | Already in `infra` | High for evolving protocols | LLMs are weakest here: 27% on Lean vs 82% on Dafny |
| Lean + Plausible | Hours | Properties only | Seconds | Seconds | Low (it tests the real Lean functions) | Easy |
| shuttle | Hours | Tests only | Seconds per 1,000 schedules | 1–2 min | Low (it tests the real code) | Agents, as ordinary tests |
| loom | Hours | Tests only | Grows exponentially with threads | Keep tests tiny | Low | As above |
| Kani | Hours | One harness per function | Under 1 s to minutes | Firecracker: 27 harnesses in about 15 min | Low (it checks the real code) | As above. A 0.5 GB toolchain to cache |
| fast-check | Hours | Tests and a small model | Seconds | Under 1 min | Low | As above |
| DO simulation | Weeks to build the harness | — | Seconds per seed | Minutes | Low | One-off build |

On LLM authorship: an NL-to-TLA+ study of 30 models found best rates of 26.6% syntactic and 8.6% semantic correctness ([arXiv 2606.05792](https://arxiv.org/abs/2606.05792)). The vericoding benchmark measured LLM success at about 82% in Dafny, 44% in Verus and 27% in Lean ([arXiv 2509.22908](https://arxiv.org/abs/2509.22908)). I found no comparable measurement for Quint (unverified that agents write it better; this session's single data point needed one fix). Whatever the language, the checker carries the trust: a wrong spec with a passing checker is the main risk, so reviewers read the invariants, not the actions.

## Past bug classes

Sources: [review lessons](../../../dev/review-lessons.md) and the fix commits named.

| Bug class (where it was found) | Caught by | Modelling detail needed | Would not catch |
|---|---|---|---|
| **Split brain across moves:** an old brain with an hour-long binding kept acting while the new one re-ran the turn (`ce5c472`, H1) | Quint/TLA+ model of AgentDO + SandboxDO + gateway, checking that no hands call is admitted below the current agent epoch | Bindings as credentials that outlive a stop; brain moves without a sandbox epoch change; a partitioned old host | Kani, loom and shuttle (in-process only); fast-check unless the move-with-stale-binding scenario is in its command set |
| **Stale epochs or holders accepted** (an older start's exit cleared the current brain, `ce5c472` M5; reports from an expired lease reached SandboxDO, `4f85ffd`) | Quint + MBT replay against `AgentDO` exits and `SandboxDO` reports and commits; Kani for the Rust-side checks; Lean or Alloy for the pure predicate | Per-host belief versus the DO's epoch; reordered `sandbox_state` and `fence ok` | Abstract models that make fencing atomic |
| **STONITH left a sandbox `fenced` with no lease** (`4f85ffd`) | Quint model with an unordered, lossy channel between host, FleetDO and SandboxDO, plus a "no stuck sandbox" invariant (or liveness through TLC) | Two copies of "who holds it", and message reordering | Single-object tests |
| **Cross-DO re-entrancy deadlock:** an agent's start placed a sandbox, which called back into the agent (`65bf6ef`, H1) | TLC deadlock detection, or a progress invariant, over a model where each DO is a process with its in-flight awaits. fast-check `scheduler` with a timeout in vitest | Await-level granularity and the serial queue held across RPC | Coarse protocol models (one atomic step per handler), Kani, Alloy |
| **Check-then-act across an await** (re-check the epoch after each await, L3 in `65bf6ef`) | fast-check `scheduler` (demonstrated) | Wrap the awaited RPC in `s.schedule` | Models with atomic handlers; e2e (rare timing) |
| **Retries that stop after one failure** (lesson 6, `1b83482`) | Liveness under fairness in TLA+/TLC ("a placeable sandbox is eventually placed"); fast-check commands with a `fail` command and an "eventually placed after N ticks" check | Failures as nondeterministic actions; the retry deadline in the model | Safety-only checking (AWS's lock-manager liveness bug was missed the same way) |
| **Deadline re-armed inside its handler, then swallowed** (lesson 2) | fast-check `fc.commands` on `Deadlines` against a map-of-earliest model, including "re-arm while running" | Unit level: the alarm multiplexer | Protocol models (below their abstraction) |
| **A restart read something not yet durable** (lesson 4) | Any model with a `crash` action that drops volatile state; fast-check command "restart = rebuild from storage"; DO simulation with crash injection | Durable and volatile variables kept apart | Models that treat every write as durable |
| **Pruning that could delete needed data** (GC grace and roots, `daf4f11`; host rows pruned before their brains moved, `dede063` M1) | Alloy or Lean for "the mark covers every restore source"; Quint for GC running concurrently with commits under the 12 h grace | Time and grace windows, orphaned siblings, reuse of uploaded chunks | Example-based tests that miss the concurrent interleaving |
| **Mixed-version windows** (`65bf6ef` "mixed-version hole"; rollback-safe epochs, `dede063` M2) | Quint/TLA+ with a version per component and both handler sets enabled, plus an `upgrade` or `rollback` action | Old-version semantics modelled explicitly, one version back | Every single-version model; the fixtures catch shape drift only |
| **A fake collaborator hid a binding error** (lesson 8, `2a6ee74` (#13), "Illegal invocation") | None of the formal methods. Only running the default binding on the platform (`fetchMock`, workerd, e2e) | — | Every model and every fake-based test |
| **Wrong encoding guessed** (lesson 5) | Tests from observed samples; Plausible or Kani only round-trip what they are given | — | Formal methods (the spec would encode the same guess) |

## Open questions

- TLA+ or Quint in the long run: the pilots chose TLA+ for now; revisit when the model-based-testing harness is built ([roadmap](../roadmap/)).
- Where do specs live (`verification/` beside `deploy/lean/`, or per crate and package), and who owns them under `CODEOWNERS`?
- Can `@cloudflare/vitest-pool-workers` route cross-DO stub calls through `fc.scheduler` without a production code seam? Unverified.
- Liveness checks (retries, eventual placement) need TLC through TLA+ export or fast-check bounds; Apalache's liveness support was not checked.
