# The live trace (2026-11-02)

A release's rollout rule ([Rollout rules](../deploy.md#rollout-rules)).

**Not a one-way deploy.** No Durable Object class is added and no host changes: the trace is what AgentDO already gets from the runner ([live trace](../../docs/control-plane/api/#live-trace)). AgentDO gains two tables (`trace`, `trace_head`), a `kv` key (`trace_sockets`), a WebSocket auto-response (`ping` → `pong`) and a socket tag (`trace`); the Worker a route, `GET /v1/agents/<id>/trace`.
- **The gap after the deploy:** an AgentDO still on the previous code for minutes answers the forwarded upgrade with its session route's 400 (no `x-nest-trace` header), and the Worker answers `503` (`internal`, `retryable: true`), never 500. A client retries with a backoff. Events an agent applied before its AgentDO restarted on this release were never recorded, so the first connect's ring starts at the restart.
- **Stored data (expand-only):** the new tables and key. Nothing is renamed or dropped.
- **What a rollback does:** the route answers 401 to a client (an unknown route to a non-operator) and 404 to the operator; open trace sockets close with the restart. The previous code never reads `trace`, `trace_head` or `trace_sockets`, and doesn't set the auto-response. After the roll forward the ring carries on from `trace_head` (no seq is reused). What happened during the rollback was never recorded, so no seq covers it and no gap reports it: the transcript has it.
- **Operator steps after the deploy:** none.
- **Cloud check:** with a client on `use1` and its token, `POST /v1/agents {template, cell: "use1", start: false}`, then connect to `wss://nest.bitcru.sh/v1/agents/<id>/trace` with `Authorization: Bearer <client token>` (e.g. `websocat -H`; retry a 503 for up to 10 minutes): the upgrade answers 101 and the first message is `{"type": "live"}` (an unstarted agent has nothing to replay), and `ping` gets `pong`. Another client's token gets 404. `POST /v1/agents/<id>/stop {"end": true}`: the socket gets `{"seq": m, "ts_ms": …, "type": "ended", "reason": "stopped"}`, and closes with 1000 within a minute (the end's alarm). Connecting again with `?after=<m - 1>` gets exactly the `ended` (seq `m`) and a close; with `?after=<m>`, `{"type": "ended", "reason": "stopped"}` without a seq and a close.
