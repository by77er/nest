# Workers carry their PRs to merge (2026-11-12)

A release's rollout rule ([Rollout rules](../deploy.md#rollout-rules)), for the projects app ([PR upkeep](../../projects/README.md#pr-upkeep)).

**Not a one-way deploy, and no ordering constraint.** No nest change. ProjectDO gains a migration step (a `pr_told` table; `pr_read_next_ms`, `pr_read_last_ms`, `pr_read_attempts` on `settings`) and a method, `nudgePrRead`; ReviewDO gains a method, `verdictsAt`. The Worker and both objects are one script, so they deploy together.
- **The worker's prompt** reaches nest's shared `projects/worker` template at the next catalog sync (Admin, **Sync catalog**). A project's own model templates are written again at each worker start, so new workers get it either way; running workers keep the prompt they started with, and are told of their PRs all the same.
- **The GitHub App** needs nothing new: the read asks `pull_requests: read` and `checks: read`, within the grant, and `check_run` is subscribed already.
- **What a rollback does:** the previous release has no read and tells workers nothing of their PRs. Its migrations end before this step, so the new table and columns stay unread, and redeploying this release picks them up as they were (a worker already told of a condition at a head isn't told again).
