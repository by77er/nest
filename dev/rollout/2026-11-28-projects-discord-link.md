# Projects: linked Discord servers (2026-11-28)

Not a one-way deploy, and no ordering constraint.

- **What it adds:** `/mcp/discord`, served to the agents of the clients the Worker var `LINKED_CLIENTS` lists (`wrangler.jsonc`: the Discord bot's production client), scoped to the projects the owner linked to the caller's `guild` label; the owner's `GET`/`PUT`/`DELETE /api/projects/:id/links[/:guild]` and Settings' "Discord servers" ([projects/README.md#linked-servers-discord](../../projects/README.md#linked-servers-discord)). Stored: DirectoryDO's table `links` with an index and a trigger deleting a project's links with its row, added by a migration the previous release skips. A linked server's proposal is a row of `proposals` in the routines' shape (`routine` `discord:<guild>`), no new column. Also: the app's own servers now refuse nest's connector when its token names another client or none (nest's connector has named the client since 2026-11-12, #270).
- **Before the Worker deploys:** nothing. No Access change: `/mcp` is bypassed already (`projects/deploy/`), and nest needs none (a client's capability may point at any https URL since 2026-11-28). Nothing is visible to the bot's agents until the owner links a project.
- **After:** the bot's operator makes its capability `discord/c<id>` at `https://projects-nest.bitcru.sh/mcp/discord`, with no `auth`, and labels its agents with `guild`.
- **What a rollback does:** the previous release has no `/mcp/discord` (404) and no links routes; its DirectoryDO keeps the `links` table and trigger unread (the trigger still runs on a project row's delete, harmlessly). Proposals a linked server made stay in triage and show as from "the routine Discord server <guild> (run <agent>)"; accepting one makes a draft as for a routine's, whose body then names the server and agent (`Proposed by the routine "Discord server <guild>" (run <agent>)`); rolled forward, every server linked to that project reads that body, so edit it if the server's id matters. Rolling forward again finds the links as they were.
