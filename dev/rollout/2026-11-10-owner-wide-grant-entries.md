# Owner-wide grant entries (2026-11-10)

A release's rollout rule ([Rollout rules](../deploy.md#rollout-rules)).

**Not a one-way deploy; write no `owner/*` entry until this release is live, and don't roll back past it while a grant holds one unless failing closed is acceptable.** No Durable Object class or host change. BrokerDO gains three tables, `github_repo_owners`, `github_installation_accounts` and `github_account_repos` (expand-only), and four methods (`githubAccountId`, `repoOwners`, `accountRepos`, `clientGithubTokenOwned`); the Worker two routes, `GET` and `POST /v1/clients/self/grant/repos`. A client grant (stored JSON in ClientDO, read as it is) may hold `owner/*` in `repos`, `read_repos` and `github.repos`, and a new field, `repo_owners`.

- **Mid-deploy:** a grant write with an owner-wide entry meets a BrokerDO of the previous release: `githubAccountId` is missing, so the write answers 503 (retryable) and saves nothing. The two membership routes answer 503 likewise. A token request the Worker leaves to the mint (a repo under an owner-wide `github.repos` entry) calls its own method, `clientGithubTokenOwned`, which a previous BrokerDO lacks: 503, nothing minted (an extra argument to the old `clientGithubToken` would have been ignored, minting for any repo).
- **A previous release reading a grant with `owner/*` fails closed.** It compares names exactly, and no repo it accepts can be named `owner/*` (`Repo` refuses `*`), so the entry matches nothing: a spec naming one of that account's repos is refused (403), and so is a token for one. It never reads the entry as everything. It ignores `repo_owners`. Its PATCH refuses `owner/*` (400), so it can't write one.
- **`wrangler rollback`:** the tables stay, unread; grants keep their entries, which then match nothing until this release returns.
