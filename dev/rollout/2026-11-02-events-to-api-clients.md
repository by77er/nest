# Events to API clients (2026-11-02)

A release's rollout rule ([Rollout rules](../deploy.md#rollout-rules)).

**Not a one-way deploy.** No Durable Object class is added (ClientDO, AgentDO and SandboxDO gain tables), and no host change: the events come from what AgentDO and SandboxDO already see ([events to the owner](../../docs/control-plane/api/clients/#events-to-the-owner)).
- **In the gap after the deploy:** a busy ClientDO can run the previous code for minutes ([upgrades](../../docs/control-plane/#upgrades)) and answer `enqueue` with "does not implement the method". The agent or sandbox keeps the event in its `client_events` outbox and retries every 5 s, so nothing is lost and no agent waits. `PUT /v1/clients/self/webhook` answers a retryable 503 from such a ClientDO (`newMethod`), and `GET /v1/clients/self` answers without `events`; retry them.
- **Stored data (expand-only):** new tables `client_events` (AgentDO, SandboxDO) and `outbox` (ClientDO); new `kv` keys `webhook` and `delivery` (ClientDO) and `turn_text` (AgentDO); the admin client view gains `events`. Nothing is renamed or dropped.
- **What a rollback does:** the previous code drops the `client_events` and `deliver` deadlines (no handler), never reads the new tables, and answers the `/v1/clients/self` routes 401 (an unknown route to a non-operator). After the roll forward, an agent's waiting events go at its next alarm (the hourly `prune` at the latest) and a client's backlog at its next hourly prune. Lost: events of anything that happened while rolled back (never written), and a `sandbox.destroyed` not yet handed over (the previous SandboxDO's `client` handler drops the deadline, and a destroyed sandbox has no later alarm).
- **Operator steps after the deploy:** none. Each client sets its own webhook with its token.
- **Cloud check:** with a client on `use1` and an https endpoint you control that records requests, `PUT /v1/clients/self/webhook {"url": …}` with the client's token answers a `whsec_` secret (retried for 10 minutes while it answers 503). Create a sandbox with that token and `DELETE` it: the endpoint gets one POST with body `{"id", "type": "sandbox.destroyed", "sandbox"}` and a `Nest-Signature` that verifies against the secret, and `GET /v1/clients/self` shows `events.backlog: 0, failures: 0`. Then make the endpoint answer 500 and destroy another sandbox: `failures` grows (attempts 1 s, 2 s, 4 s apart) with `last_error: "HTTP 500"`. An agent's `agent.turn_completed` with its final text needs a brain host and a turn (the lead's).
