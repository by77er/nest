# The guest image's GitHub credential helper and GITHUB_TOKEN go (2026-11-15)

A release's rollout rule ([Rollout rules](../deploy.md#rollout-rules)), for [GitHub in the image](../../docs/sandbox/networking/egress/injection/#github): phase C4 of the plan to take service integrations out of nest's kernel ([decisions](../../docs/README.md#settled-decisions)). It follows C3 (`2026-11-15-kernel-github-minting.md`), after which nothing in the control plane fills `nest-ph-github`.

**Not a one-way deploy, and no ordering constraint.** No Durable Object class, table, column, route, RPC method or wire change; no `nest-guest` change. The Worker and the host release this merge publishes behave exactly as C3's: the only control-plane source change is a comment.

- **What changes:** the image source only. `images/guest/build.sh` no longer installs `git-credential-nest`, sets git's system `credential.https://github.com.helper`, or writes `GITHUB_TOKEN=nest-ph-github` to `/etc/environment`; `build-on-ec2.sh` no longer stages the helper. `git` and `gh` stay, unconfigured. The fixtures `egress_policy.github.json` and `egress_policy.github_read.json` (what C3's deleted constructor built) go with nest-proxy's tests on them; `egress_policy.github_none.json` becomes `egress_policy.base_floor.json`, the operator's base-layer floor as data, which a vitest now carries through `PUT /v1/admin/egress/base` to a sandbox's policy.
- **When it reaches sandboxes:** not at the merge. The pipeline carries `nest-base.ext4.zst` over from the current release (`scripts/publish-release.sh`), so the live image keeps the helper until the operator rebuilds it by hand (`images/guest/build-on-ec2.sh`, which launches a builder instance) and promotes the build into `releases/current/` as before, keeping the image it replaces. Hosts install `releases/current/` at boot, so the new image reaches each sandbox host as it is replaced, and then only sandboxes created fresh there: a sandbox's disk is a copy of the image it was created from (or of its parent, for a fork), restored from its own generations wherever it moves. Old and new disks coexist for as long as older sandboxes live.
- **A sandbox created from the older image** (every live one today) keeps the helper and `GITHUB_TOKEN=nest-ph-github` on its disk. Nothing fills that placeholder unless an operator binding takes it (none does), so git and `gh` without an app's environment send it to GitHub as a credential and are refused; the base layer's floor already refuses their writes, since no credential nest injected is in `Authorization`. The projects app's sandboxes are unaffected: their `GH_TOKEN` comes before `GITHUB_TOKEN` for `gh`, and their `GIT_CONFIG_*` empties git's helper list before adding the app's (`projects/test-node/git-credential.test.ts` runs both against each image's configuration).
- **A sandbox created from the new image** has no helper and no GitHub environment. Without an app's environment, git asks for a credential only after GitHub's 401 and, finding no helper, prompts on a terminal or fails without one; `gh` runs unauthenticated. Public fetches work as before. An app's sandboxes get the same `GH_TOKEN` and helper from the app as on the older image.
- **The control plane against either image:** no difference since C3; it reads nothing from the image. `nest-ph-github` stays out of every placeholder nest assigns (`injectionPlaceholder`, and nest-proxy's substring search) while older disks may carry it.
- **What a `wrangler rollback` does:** the previous Worker (C3's) behaves the same. A Worker from before C3 is two versions back; there, a sandbox with kernel repos on a new-image disk would push with no credential (git finds no helper) and be refused: narrower, and no live sandbox has kernel repos.
- **Rolling the image back:** put the previous build back into `releases/current/`; hosts launched after that create sandboxes with the helper again, which nothing fills. Sandboxes created from the new image keep it.
- **Cloud check after the operator's rebuild:** on a sandbox created on a host with the new image, `command -v git-credential-nest` prints nothing, `git config --system --get-all credential.https://github.com.helper` prints nothing, and `GITHUB_TOKEN` is unset; a projects start still pushes its branch.
- **Contract:** nothing to drop. The `nest-ph-github` exclusion goes once no sandbox created from the older image remains (destroy or recreate them; phase C6 decides).
