# The projects app reads its repo's name and owner through (2026-11-12)

A release's rollout rule ([Rollout rules](../deploy.md#rollout-rules)), for the projects app ([the repo's binding](../../projects/README.md#the-repos-binding)).

**Not a one-way deploy, and no ordering constraint.** No nest change. All in one script, so the Worker and its Durable Objects deploy together.
- **DirectoryDO** gains a migration step (`installation_checked_ms` and `repo_owner_type` on `projects`) and a method, `claimInstallationCheck`; `projectForRepo` answers `anchored`, and `bindRepo` takes the owner recorded at attach. It loses `unrenameRepo`, which only this script called.
- **ProjectDO** gains a migration step (`comments_default_id`, filled for existing rows where the comments user is the owner recorded at attach, and `comments_cleared` on `settings`) and the methods `repoOwnerSeen`, `attachedOwner`, `writeOldOwnerCopy` and `dismissCommentsCleared`; `onIssue` takes an optional `repo_owner`; "Needs you" gains the item `comments_cleared`. The Worker gains `POST /api/projects/:id/comments-cleared/dismiss`.
- **Expand, for a rollback:** this release reads neither ProjectDO's `settings.repo` nor ReviewDO's `repo` setting, and trusts no copy of the owner, but keeps writing them: the name at create, at a rename applied and at every catalog sync (from the directory's); the owner at attach, at "Use the repo owner", and at every sync from GitHub's last answer for a binding read from GitHub. One it can't write is logged, not rolled back.
- **What a rollback does:** the previous release reads those copies again. Its review gate and triage trust ProjectDO's owner copy, which the last sync on this release made the owner then (a transfer since that sync leaves the old owner trusted there, as before this release), and trust an event routed by name as before. A default comments user this release cleared stays nobody (its `comments_decided` is set, so the previous release's attach doesn't default it again); its "Needs you" doesn't list the notice, and the columns are unread. A rename applied while an old copy couldn't be written leaves that DO on the old name until a sync on this release.
- **Contract, the release after:** stop writing `settings.repo_owner_id` and `repo_owner_login` (`writeOldOwnerCopy`, and the writes at attach and "Use the repo owner" in `src/do/project.ts`), ProjectDO's `settings.repo` and ReviewDO's `repo` setting (`writeOldCopies` in `src/binding.ts`). The owner recorded at attach (`attachedOwner`) still reads `repo_owner_*` for bindings not read from GitHub: move it to its own column first, or drop it once every binding is read from GitHub.
